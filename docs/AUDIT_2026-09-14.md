# Project audit — 2026-09-14

Four independent reviews in one day: three adversarial code audits covering
the whole package, and one hostile peer review of the manuscript. Every
finding below was reproduced by execution, not inferred from reading.

This document is the consolidated verdict and the plan that follows from
it. The full reports are `paper/hostile_review_2026-09.md` and the
per-audit detail recorded in the commits of 2026-09-14.

---

## The one-sentence finding

The problem was never capability or effort. It was that nobody had ever
checked.

Thirty thousand lines, 624 passing tests, a real paper and a real
contract — and in a single day of adversarial reading: four wrong
statistics shipping for months, a cold-clone install that could not
collect its own test suite, a documented detector that does not exist in
the code, a permission model wider than its documentation, a watch rule
that a trailing log line switches off, the manuscript's central invariant
false about its own system, its most defensible proposition already
published in 2005, and the raw measurement records the paper points
reviewers at absent from the repository.

None of that is a failure of skill. It is the absence of anyone pushing
back.

## Severity 2 — the verdict depends on how you logged, not what happened

Plateau fires on a still-improving run and misses every noisy plateau; the
same run logged per-step versus per-epoch gets opposite verdicts, and so
does the same series printed at `.2f` versus `.3f`. One interleaved
metric-free line — default Keras stdout produces one per epoch — disables
plateau entirely. Overfitting accepts a val rise of 1e-6 and prints
`+0.0000` as its own evidence, while its gap threshold is absolute, so the
identical relative curve is judged by loss scale. Three correct, idiomatic
training scripts drew four false positives from `audit`, one at error
severity: HuggingFace `set_seed` and `np.random.default_rng` are not
recognised as seeding, and `sklearn`'s `random_state=` is not either.

## Severity 1 — the manuscript

Verdict from the hostile review: **reject for TSE/TOSEM/ICSE as
submitted; major revision achievable. Accept after revision for INISTA.**
24 findings.

- **Proposition 2 is Chomicki & Marcinkowski 2005** (*Information and
  Computation* 197(1–2):90–121), stated with a ∎ and no citation, and the
  abstract calls it one of the two formal facts the design rests on. What
  survives is genuinely the authors': a database has no speaker, so
  insertion there is merely a different repair, while in narration it
  fabricates attribution. Recast as a transposition.
- **The §III-C invariant is false about the system it describes.** It
  claims any returned response quotes only values equal to the evidence.
  `narration` is a required free-text field Tier B never reads. §I states
  the correct channel-scoped version; §III-C does not.
- **The omission flag is unwired.** `omitted_critical_evidence` is
  produced at `leakage_investigator.py:748` and read by no code in `src/`.
  Proposition 2's whole point is strip-for-soundness, flag-for-
  completeness — and the flag half never reaches a user.
- **"The guarded path is the only path from narrator to user" is false
  twice.** `interpret_evaluation` is a second, unverified narrator over
  the same evidence, rendered *above* the contract panel; the MCP server
  hands raw evidence to an unguarded client model.
- **The raw run records are not in the repository**, though the paper's
  closing line says they are. One evidence JSON, zero JSONL. A reviewer
  attempting reproduction has nothing to read.
- **The value channel is close to unreachable by construction** —
  `statistic` is a one-element enum the verifier ignores — so the paper's
  stated reason for the 0/200 result is the wrong reason.
- **The pre-registered generic-retry control exists in the shipped code
  and was never run**, yet §V-B asserts the causal conclusion it was built
  to test.
- **"Production system" plus four wrong statistics**, with the sharpest
  point being that the AUC defect manufactured the paper's own trigger
  condition.

The review also carries a twelve-item list of things not to edit away.
First among them: Table II, the paraphrase sweep, is the strongest result
in the paper and belongs in the abstract's second sentence.

## What this changes about the plan

The earlier estimate — arXiv within one to two weeks — does not survive
these findings. Most of what remains is not text. The invariant, the
unwired flag, the two unguarded narration paths and the unreachable value
channel are code problems that the manuscript describes as solved.

The order is forced:

1. **Make the code match the claims.** Wire the omission flag. Either
   close the unguarded narration paths or scope them explicitly in the
   paper. Make the value channel reachable.
2. **Commit the raw records and repair the SHA pins.** Without this the
   reproducibility sentence has to be deleted rather than defended.
3. **Then the text surgery.** Proposition 2 as a transposition citing
   Chomicki; drop the occupied novelty conjunct; promote the paraphrase
   sweep to the first contribution; add the six concurrent papers and the
   data-to-text ancestry.
4. **Then arXiv.**

A month is the honest estimate. That is not bad news: a reviewer finding
any one of these would have ended the submission, and none of it is
published yet.

## The pattern worth naming

Nothing here was ever carried to an audience. The Show HN draft was
written and never posted. The demo recording was scripted and never made.
Fourteen releases went to PyPI unannounced. The paper has been submitted
nowhere. Each time, building the next thing won over finishing the last
one.

The highest-return change is not technical. It is to take one thing all
the way out the door.
