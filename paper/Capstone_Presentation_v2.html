The two-layer brain

05 / 13
Facts come from pure code. Narration comes from a Claude agent on top — never the other way around.

🧮 Deterministic Tool Layer

pure Python · always offline · same input ⇒ same output
  • Reads CSVs with pandas
  • Parses scripts with ast
  • Computes Pearson + Spearman + perfect-match
  • Returns structured dict — never free text
  • Cannot hallucinate by construction
src/mlcompass/tools/

🎙️ Optional Claude Narrator

opt-in via --llm · strict prompt + runtime schema
  • Receives the dict from below
  • Explains it in natural language
  • Runs under a 3-layer contract (next slide)
  • Bound at call time to the evidence's columns
  • Skipped entirely with --no-llm

The anti-hallucination contract

06 / 13
Three layers. Each alone is weak. Together they are strict.
Layer 1

Deterministic evidence

  • Pure Python, no LLM
  • Computes max(|ρ_P|, |ρ_S|)
  • Emits a dict E of candidates
strength: foundation
Layer 2

Strict prompt

  • Cite only items in E
  • Say cannot_determine if unsure
  • No code patches, manual checks
strength: advisory
Layer 3

Runtime schema boundary

  • Tool-input enum built from E
  • SDK rejects out-of-evidence columns
  • Worst-case guarantee
strength: enforcement
Prompts are advisory. Schemas are enforcement.

Worked example — Ames House Prices

07 / 13
A user accidentally includes log_price when training to predict saleprice. R² = 1.000.
Layer 1
Evidence
Pearson ρ_P ≈ 0.94 Spearman ρ_S = 1.00 perfect-match 98.7%
→ log_price flagged as candidate (max correlation ≥ threshold 0.97)
Layer 2
Narrator
"log_price has Spearman = 1.00 with the target — almost certainly a transformed leak.
Recommend manually checking the feature pipeline for any column derived from the target."
Layer 3
Boundary
columns_referenced enum = { log_price, feature_3, …, feature_12 }
log_price ∈ enum → response ships.
If LLM had emitted revenue, SDK would reject and retry.

Results — phantom-column fabrication rate

08 / 13
N = 200 narrator responses per configuration · Claude 3.5 Sonnet · Wilson 95% CIs
Layer 1 only (no prompt, no schema)
8.0%CI [4.93 , 12.66]
Layer 1 + 2 (strict prompt)
1.0%CI [0.27 , 3.56]
Layer 1 + 2 + 3 (schema-enforced)
0.0%CI [0.00 , 1.83]
Takeaway
Prompt engineering reduces fabrication 8× (8% → 1%) — but does not eliminate it. The runtime schema boundary brings the observed rate to 0 — a worst-case guarantee, not just an average.

Challenges we faced

11 / 13
Four problems we hit, and the lesson from each.
01

Prompt engineering wasn't enough

A week of prompt iteration: 8% → 1%. Still wrong 1% of the time. Lesson: enforce at the schema, not the prompt.
02

CLI and MCP drifted apart

Same Python, different behavior. CLI was writing to ledger, MCP wasn't. Shipped _persist_to_ledger + parity tests.
03

Synthetic tests missed bugs

11 Kaggle bugs surfaced — zero predicted by our test suite. Moved to a field-test-then-patch release cadence.
04

Reviewer feedback

3 peer reviewers found weak stats, missing baselines, implicit threat model. Released v0.8.1 with Wilson CIs + threat model doc.

Limitations & future work

12 / 13

⚠️ What we did NOT measure

  • Cross-model generalizationAll experiments use Claude 3.5 Sonnet only.
  • Constrained-generation baselineNo direct benchmark against Outlines or OpenAI strict mode.
  • External user studyUsed by authors + classmates only. No third-party eval.
  • Other hallucination typesMiscalibrated confidence, prompt injection — out of scope.

→ Planned for v0.9 / v1.0

  • OpenAI backendRepeat Table I on GPT-4 + strict mode.

  • N = 2000 live runTightens Wilson CIs. Reproducible via shipped scripts.
