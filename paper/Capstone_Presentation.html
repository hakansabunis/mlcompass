The problem

2 / 13

ML engineering is a chain of single-purpose tools — and none of them advise.

  • pandas-profiling shows you the data. It doesn't know which column you're trying to predict.
  • Weights & Biases tracks your runs. It doesn't tell you the loss curve looks like overfitting.
  • Copilot, Cursor, Devin complete your code. They'll happily generate Adam(momentum=0.9) — which is invalid.
  • Existing LLM assistants hallucinate. They invent column names that don't exist and propose fixes for problems that aren't real.
146,932 hallucinated citations were observed across arXiv, bioRxiv, and SSRN in 2025 alone [Zhao et al., 2026].

mlcompass in 30 seconds

The two-layer brain

5 / 13

Facts come from pure code.  Narration comes from a Claude agent on top — never the other way around.

Deterministic Tool Layer (pure Python)

  • Reads CSVs with pandas
  • Parses training scripts with ast
  • Computes Pearson + Spearman + perfect-match
  • Returns structured dict — never free text
  • Cannot hallucinate by construction
src/mlcompass/tools/

Optional Claude Narrator (--llm)

  • Receives the dict from below
  • Explains it in natural language
  • Runs under a 3-layer contract (next slide)
  • Bound at call time to the evidence's columns
  • Skipped entirely with --no-llm (offline path)
src/mlcompass/agents/

The anti-hallucination contract

6 / 13

Three layers.  Each one alone is weak.  Together they are strict.

Layer 1

Deterministic evidence

  • Pure Python. No LLM.
  • Computes max(|ρ_P|, |ρ_S|).
  • Emits a dict E of candidate leak columns.
Layer 2

Strict prompt

  • Cite only items in E.
  • Say cannot_determine when unsure.
  • No code patches — manual checks only.
Layer 3

Runtime schema boundary

  • Tool-input enum is generated from E.
  • SDK rejects any out-of-evidence column.
  • Worst-case guarantee, not just guidance.
Lesson Prompts are advisory.  Schemas are enforcement.

Worked example — Ames House Prices

7 / 13

A user accidentally includes log_price when training a model to predict saleprice.  R² = 1.000.

Layer 1 — Evidence
Pearson ρ_P(log_price, y) ≈ 0.94  ·  Spearman ρ_S = 1.00  ·  perfect-match 98.7 % → log_price flagged as candidate (max correlation = 1.00 ≥ threshold 0.97).
Layer 2 — Narrator
"log_price has Spearman = 1.00 with the target — almost certainly a transformed leak.
Recommend manually checking the feature pipeline for any column derived from the target."
Layer 3 — Boundary
columns_referenced enum = {log_price, feature_3, …, feature_12} log_price ∈ enum → response ships.  If the LLM had emitted revenue, SDK would reject and retry.

Results — phantom-column fabrication rate

8 / 13

Synthetic regression test set.  N = 200 narrator responses per configuration.  Claude 3.5 Sonnet.

Configuration Rate Wilson 95% CI
Layer 1 only   (no prompt, no schema) 8.0 % [ 4.93 , 12.66 ]
Layer 1 + 2   (strict prompt) 1.0 % [ 0.27 , 3.56 ]
Layer 1 + 2 + 3   (schema-enforced) 0.0 % [ 0.00 , 1.83 ]
Takeaway Prompt engineering reduces fabrication 8× (8.0 % → 1.0 %), but does not eliminate it.  The runtime schema boundary brings the observed rate to 0 — a worst-case guarantee, not just an average.

Challenges we faced

11 / 13

Four problems we hit, and what we learned from each one.

  • Prompt engineering wasn't enough. We spent a week trying to make the LLM stop fabricating columns through prompts alone.  Got from 8 % to 1 %.  Still wrong 1 % of the time.  Fix: enforce at the schema layer, not the prompt layer.
  • CLI and MCP server drifted apart. Same underlying functions, different behavior.  CLI was writing to the ledger, MCP wasn't.  Shipped a shared _persist_to_ledger helper + parity regression tests in v0.7.2 and v0.7.3.
  • Synthetic unit tests missed real bugs. Eleven bugs surfaced from five Kaggle datasets — zero predicted from our pre-existing test suite.  Moved to a field-test-then-patch release cadence.
  • Reviewer feedback on the paper. Three peer reviewers identified weak statistical claims, missing baselines, implicit threat model.  Released v0.8.1 with Wilson 95 % CIs, reproducibility scripts, threat model doc, limitations doc.

Limitations  +  future work

12 / 13

What we did NOT measure

  • Cross-model generalization All experiments use Claude 3.5 Sonnet.  GPT-4, Llama-3, Gemini unverified.
  • Constrained-generation baseline No direct benchmark against Outlines or OpenAI strict: true.
  • External user study Used by authors + classmates only.  No third-party evaluation.
  • Other hallucination types Miscalibrated confidence, prompt injection — out of scope.

Planned for v0.9 / v1.0

  • OpenAI backend Repeat Table I on GPT-4 + strict: true.  Report cross-provider rates.
  • Outlines benchmark Same task through Outlines on Llama-3-8B.  Side-by-side fabrication rates.
  • N = 2000 live run Tightens Wilson CIs.  Reproducible via scripts/reproduce_hallucination_ablation.py.
  • Plug-in system Domain-specific analyzers (HuggingFace, PyTorch Lightning) without modifying core.
