\begin{abstract}
Large language models (LLMs) narrate deterministic tool output, and a
narration can invent an item absent from that output or misfile a real item into
an inadmissible field. Prevailing defenses constrain decoding, which needs
decoding control that commercial interfaces deny callers, trust
provider schemas whose enforcement callers cannot verify, or match entities and
numbers against pooled evidence, which passes real items in wrong fields. We
propose evidence closed narration: every answer field admits only tool output
values bound at call time, numbers are keyed to entity and statistic, and host
code checks each answer. In mlcompass, one of three LLMs failed often; under the
bare instruction, 1,772 of its 1,831 violating answers used only evidence items,
mostly the metric name in a column field. A field description removed most such
errors; a list written for other data turned them into invention. Under the
contract, no inadmissible column or number reached the user in structured
fields. The check removed a small residue (10 of 600) from the best
configuration, and on leakage column names an evidence bound enumeration did as
well. We contribute a field level instrument, an account of narrator failure,
and a map of which check covers which error.
\end{abstract}

\begin{IEEEkeywords}
Tool use, faithfulness, hallucination, runtime verification, structured
output, guardrails, data leakage.
\end{IEEEkeywords}}

\section{Introduction}\label{sec:intro}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\IEEEPARstart{L}{arge} language models (LLMs) increasingly stand between
deterministic tools and whoever consumes the tools' results. An agent calls a
tool, reads the structured output, and narrates what the output
means~\cite{react,toolformer,mcp}. The narration borrows the authority of the
tool, yet LLMs produce content that their input does not support~\cite{ji,huang}.
This paper studies faithful narration in the setting where the tool's output is
fully known at the moment of narration, and asks what that knowledge allows a
system to guarantee.

In \textbf{mlcompass}, the open-source assistant for machine-learning pipelines
that serves as our testbed, a deterministic detector diagnoses target
leakage~\cite{leakage} and an LLM, the \emph{narrator}, explains the detector's
output, the \emph{evidence} $E$, in a structured answer. Without safeguards, one
of the narrators that we tested listed \texttt{r2}, the name of the metric under
investigation, among the columns cited as evidence in 42\,\% of its answers, and
mlcompass prints that field under the heading ``Evidence cited (verified against
the evidence)'' (Section~\ref{sec:example}). The narrator invented nothing: the
name is in $E$, in a field that does not admit the name. We call such an error
\emph{misfiling}, and an item that appears nowhere in $E$ \emph{invention}; in
the vocabulary of Ji \emph{et al.}~\cite{ji} and Maynez
\emph{et al.}~\cite{maynez2020faithfulness}, they are intrinsic and extrinsic
errors. A check that compares an answer with the evidence as a pool of names and
numbers passes a misfiled item by construction, because the item is in the pool.

Existing defenses act in three places (Table~\ref{tab:taxonomy}). Constrained
decoding run by the caller~\cite{outlines,gcd,scholak2021picard} needs control
over generation at every step, which commercial application programming
interfaces (APIs) do not give the caller, and the strict schema modes of
providers~\cite{structured} can be judged only by their observable behaviour.
Validate-and-reask toolkits such as Instructor~\cite{liu2023instructor} and
Guardrails~AI~\cite{guardrailsai} leave which values each field admits to the
author of the validators, and the entity and number checks of recent narration
checkers compare with pools drawn from the
evidence~\cite{gupta2026veritygate,du2026ledgermind}, which accept a misfiled
item.

For a narrator of a deterministic tool, which values each field admits has an
exact answer before the narrator is called: the columns, statistics, and values
that $E$ holds. We make that answer explicit. Admissibility is indexed by answer
field, and each number is keyed to the (column, statistic) pair whose value the
number claims to be. \emph{Tier~A} writes the admissible values of each field
into the JavaScript Object Notation (JSON) Schema of the narrator's answer tool,
as enumerations built from $E$ at call time, and \emph{Tier~B} checks the
returned answer in host code, sends the answer back with the violation named,
and deletes whatever still violates the contract. The loop is ordinary
validate-and-reask; what we study is the granularity of the check and what
measuring narrators at that granularity reveals. We ask three research questions.

\begin{itemize}
\item \textbf{RQ1}: How does an unconstrained narrator of tool evidence fail, and
which changes to its configuration remove the failure?
\item \textbf{RQ2}: What does the contract guarantee and cost, and how do the
alternatives in common use compare?
\item \textbf{RQ3}: Do the contract and the failure carry over to a second kind
of evidence?
\end{itemize}

We recorded 19{,}132 responses from three models on sixteen leakage tasks and a
dataset-profiling task, and 3{,}200 more in four registered runs. Only
\texttt{deepseek-chat} failed often, almost only by misfiling, which a pooled
check passes and one sentence describing the field nearly removed. Under the
contract, nothing inadmissible reached the user through the structured fields,
and where simpler mechanisms sufficed, the check removed only a small residue
(Findings 1 to 3 in Section~\ref{sec:results}).

The paper offers a contract and its empirical analysis, not a new verification
algorithm, in three contributions:
(i)~an instrument for measuring and enforcing the faithfulness of tool narration,
admissibility per answer field with each number keyed to an (entity, statistic)
pair, derived from the tool output at call time (Section~\ref{sec:contract});
(ii)~an empirical account of how a failing narrator breaks the instrument's
conditions: the dominant failure is structural misfiling, induced by an
undescribed field, which pooled checks pass and a field description largely
prevents (Section~\ref{sec:rq1}); and
(iii)~a map of which mechanism covers which kind of error, read from the
definitions of the checks and from the arms that ran, five of whose comparisons
were registered (Section~\ref{sec:rq2}). The replication
package~\cite{replication} holds every response, and an extended version of this
paper~\cite{extended} holds the full audit trail.

The study is a case study of one testbed. The failure occurred on one of three
models and centered on one string, so we claim no rate for LLMs in general. We
did not measure provider-enforced strict decoding or a host that fills in
numbers, and claim no superiority over either, nor over a call-time enumeration
on leakage column names, where the two tied; Section~\ref{sec:threats} collects
the remaining limits. Section~\ref{sec:example} gives a motivating example,
Section~\ref{sec:contract} the contract, Section~\ref{sec:design} the study
design, Section~\ref{sec:results} the results, Section~\ref{sec:discussion} the
implications, Section~\ref{sec:threats} the threats to validity, and
Section~\ref{sec:related} related work; Section~\ref{sec:conclusion} concludes.

the target has leaked into the features~\cite{leakage}. The mlcompass detector
measures how strongly each feature correlates with the target and ranks the
columns that may carry the target. The narrator answers with a verdict (leakage
likely, leakage uncertain, score legitimate, or cannot determine), the columns
cited as evidence, and claims of the form (column, statistic, value).
Fig.~\ref{fig:example} shows part of the evidence for our reference task and an
answer recorded without safeguards.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Evidence-Bound Contract}\label{sec:contract}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Evidence and admissibility}

In the leakage task, $E$ holds the suspicious metric and its value; the ten
features most correlated with the target, each with its correlation (whichever
of Pearson's and Spearman's coefficient is larger in magnitude, with its sign);
the ranked candidate leaks, the features whose correlation reaches 0.99 in
magnitude; and the rate at which predictions equal the target exactly.

\begin{definitionx}[Evidence-closed narration]\label{def:closed}
A narration task is \emph{evidence-closed} if the set of citable entities and
verifiable quantities is finite and machine-enumerable at the moment of the
narration call.
\end{definitionx}

The answer has two entity fields, the cited columns
(\texttt{columns\_referenced}) and the column of each claim
(\texttt{claims[].column}). From $E$ alone we derive the set $A_{E,\mathrm{col}}$
of admissible columns and a table $V_E$ of measured values keyed by (column,
statistic). The \emph{anchor} $a^*$ is the top-ranked candidate leak, and an
answer \emph{commits} when its verdict is neither empty nor ``cannot determine''.

\begin{definitionx}[Output conditions]\label{def:contract}
A structured response $r$ \emph{satisfies} $\mathcal{C}_E$, with tolerance
$\tau$, if \textbf{(C1, entity soundness)} every name in an entity field of $r$
lies in $A_{E,\mathrm{col}}$, and \textbf{(C2, value soundness)} every claim
$(e,s,v)$ in $r$ with $e \in A_{E,\mathrm{col}}$ has $(e,s) \in
\mathrm{dom}(V_E)$, $v$ finite, and $|v - V_E(e,s)| \le \tau$.
\end{definitionx}

\begin{definitionx}[Anchor coverage]\label{def:anchor}
When $E$ has an anchor, a committed response that does not reference $a^*$
raises the warning \textbf{(C3)}. When $E$ has no anchor, as on a negative
control, (C3) does not apply.
\end{definitionx}

We call the three conditions the entity, value, and omission \emph{channels}, and
a breach of (C1) or (C2) or a raised (C3) warning a \emph{violation}. An item is
\emph{misfiled} when $E$ carries the item but not where the response puts the
item: a name of $E$ in an entity field that does not admit the name, or a number
of $E$ under a pair whose value the number is not. A name that $E$ does not carry
is \emph{unlisted} if the data frame has a column of that name and
\emph{invented} otherwise. The verifier sees only $E$ and treats all of these
alike; the distinctions serve measurement. Misfiling is a structural notion: a
misfiled item breaks the contract whether or not a reader would draw a false
conclusion from the item.

\subsection{Two tiers and what they guarantee}

Fig.~\ref{fig:contract} shows the contract. Tier~A writes $A_{E,\mathrm{col}}$
and the statistic names of $V_E$ into the answer tool's schema as flat,
independent enumerations. An enumeration is a request to the model, not a check:
unless the provider enforces the schema during decoding, the model may ignore the
request. Tier~B therefore re-checks the returned answer in host code for (C1) and
(C2), with $\tau=0.005$, and for (C3). A violating answer goes back to the model,
at most twice, with the violation named. Whatever still violates (C1) or (C2)
after the retries is deleted, a cited name at a time or a claim as a whole; an
answer with no admissible verdict is aborted rather than completed on the
narrator's behalf. The (C3) check runs after deletion, because deleting a claim
can orphan the anchor, and only raises a flag: any repair would add a reference
that the model did not produce, so Tier~B suppresses without
inserting~\cite{ligatti2005edit}. The deterministic evidence panel is printed in
every case, with the anchor first.

\begin{figure}[!t]
\centering
\includegraphics[width=0.86\columnwidth]{fig1_contract.png}
\caption{The evidence-bound contract. Tier~A binds the answer schema's
enumerations to $E$ at call time. Tier~B re-checks the returned answer in host
code, retries with the offending items named, strips unsound content after the
budget, and flags a persistent omission. Only the narrator is untrusted; the free
text reaches the user marked unverified.}
\label{fig:contract}
\end{figure}

\begin{proposition}[Guarantee]\label{prop:guarantee}
Let $E$ be fixed and the returned payload be parsed into its fields. If every
name in an entity field and every structured claim passes through the final
filter of Tier~B, the delivered structured answer satisfies (C1) and (C2),
whatever the model returned.
\end{proposition}

\begin{IEEEproof}[Proof sketch]
The filter keeps a cited name exactly when the name lies in
$A_{E,\mathrm{col}}$, and a claim exactly when the claim's column lies in
$A_{E,\mathrm{col}}$, the claim's pair lies in $\mathrm{dom}(V_E)$, and the
claim's value is finite and within $\tau$ of the measured value; these are the
predicates of (C1) and (C2). The filter catches no exception, so a failure
inside the check propagates instead of releasing unchecked content.
\end{IEEEproof}

We therefore keep three claims apart: the \emph{guarantee} of
Proposition~\ref{prop:guarantee}, which holds by construction in the structured
fields and carries no interval; \emph{empirical reliability}, the rates that the
arms measured; and end-to-end \emph{correctness}, which we do not claim
(Section~\ref{sec:limits}).

\subsection{Implementation}

The check could also be written as an Instructor field validator that reads $E$
from the validation context~\cite{liu2023instructor}; we did not build that port,
so this is feasibility, not measured equivalence. In our implementation, the
contract is a layer that names no task: a specification of about forty lines says
which fields are entities, which statistics each entity has, and which entity is
the anchor, and leakage and a dataset profiler (Section~\ref{sec:rq3}) are two
such specifications. Checking an answer takes time linear in the sizes of the
answer and of $E$. Thirty-six mutation tests, ten fault-injection tests, and a
registered property-based search over $10^6$ generated (evidence, response) pairs
support the implementation without proving the implementation correct; the
search, built after the experiments, found a NaN value that passed and a
400-digit integer that crashed the value check, both fixed (the NaN after the
main runs) and carried by no recorded response.

\subsection{What the contract does not cover}\label{sec:limits}

The guarantee is consistency with $E$, not correctness, and (C2) checks
closeness, not provenance: a neighbour's value within $\tau$ of the pair's own
value passes. Our tasks hold such neighbours. On the reference task the two
candidates differ by 0.00026, and on the crowded task adjacent columns lie 0.003
apart; in two crowded answers of the choice-list arm, nine values copied from the
adjacent column pass the check at $\tau=0.005$, although one of the two answers
still violates through other values. A tolerance of $5\times10^{-4}$ would catch
the crowded shifts but not the reference pair. The verdict is checked for
admissibility but not for agreement with $E$, and the free-text narration reaches
the user marked unverified. The detector is trusted, so a mis-ranked candidate is
narrated faithfully. An optional interpretation panel, a tool-server command
whose client model narrates in the user's editor~\cite{mcp}, and the
\texttt{advise} command run without the contract. Column names come from the
user's data, so a crafted header is a prompt-injection
vector~\cite{greshake2023injection}, and Tier~A writes that header into the
enumerations, the channel that EnumAttack uses to evade safety
training~\cite{zhang2025cda}; rendered strings are escaped, and nothing more is
guaranteed about them.

\section{Study Design}\label{sec:design}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

We evaluated the contract in a controlled experiment over fixed evidence,
following the ACM SIGSOFT Empirical Standards~\cite{ralph2020standards}. The
manipulated variable is the enforcement mechanism, the instruction, or the
naming and description of the evidence; the outcome is what reaches the user.

\subsection{Research questions}

\emph{RQ1} matters because a hallucination rate alone cannot say whether a pooled
check would catch the failure or which change removes the failure. \emph{RQ2}
matters because a check is worth adding only where simpler mechanisms leave
errors that the check removes at an acceptable cost. \emph{RQ3} matters because a
layer that names no task should hold where numbers outnumber names.

\subsection{Subjects}

\paragraph{Tasks}
The \emph{reference} task is a frame of 1,000 rows and fourteen columns whose
target $y\sim\mathcal{N}(50,10^2)$ has leaked through a log-transformed copy,
\texttt{log\_target\_v2}, alongside a highly correlated distractor; $E$ lists ten
columns. The \emph{crowded} task has 1,200 rows, the anchor \texttt{sensor\_ref}
at a correlation of 0.995, and nine near-tied distractors; none of its ten
evidence columns appears in the reference task. Two real datasets are explained
after an ordinary least-squares fit: \emph{bodyfat}~\cite{penrose1985bodyfat},
whose documented leak is \texttt{Density}, and
\emph{sambanis}~\cite{muchlinski2016civilwar}, a negative control with no
candidate. Twelve more tasks were frozen in the analysis plan on 2026-07-07,
before any run of the registered campaign: six target-derived leaks, each planted
in two of four public
tables~\cite{lantz2013mlr,janosi1988heart,ibm2019telco,decock2011ames}. We wrote
the prompts, schemas, and contract against the reference task alone. The
profiling task of RQ3 is described in Section~\ref{sec:rq3}.

\paragraph{Narrators and sampling}
The narrators are \texttt{deepseek-chat}, \texttt{gpt-5.4-mini}, and a local
\texttt{qwen2.5:7b}, at temperature 1.0, the default of every endpoint and the
shipped setting. Each configuration ran 200 times per task on the hosted models
and 20 times on the local one; a count of 0 in 200 bounds the rate below 1.9\,\%
(Wilson, 95\,\%). The provider serves a rolling model name, so every rate carries
its run date, and we compare configurations within a date.

\subsection{Configurations}

An \emph{arm} fixes the system prompt, the answer schema, and the check. The
\emph{bare} prompt states the task with no faithfulness rule; the \emph{shipped}
prompt, the one mlcompass uses, adds seven rules and a verdict mapping; the field
description reads: ``Names of dataset columns (features) from the evidence that
you cite. Column names only, not the names of metrics or statistics.''
Table~\ref{tab:arms} groups the arms in four sets. \emph{Diagnostic controls}
run without a domain or with a wrong one: the \emph{floor} (bare prompt, open
schema, no check), the stock Guardrails~AI validators, a typed schema without a
column list, and a list written in advance. \emph{Interface fixes} change only
the prompt, the field description, or the temperature. \emph{Mechanisms bound to
$E$} state the domain without our verifier: a call-time enumeration, with or
without the provider's strict flag, a choice list on the cited field inside the
Guardrails loop (our reimplementation of the toolkit's acceptable-values
semantics), and the \emph{strong} configuration, which combines the shipped
prompt, the enumeration, and the field description. The \emph{contract} arms add
Tier~B. Every retry loop has a budget of 2. The typed-schema arms, the
strict-flag enumeration, and the lists of the coverage test sent the strict flag
to the provider's standard endpoint, whose documentation does not describe strict
mode; the records show that the flag was not enforced (Section~\ref{sec:rq2}), so
every enumeration in this study acted as a request.

\subsection{Measures}

We score every delivered answer once into one table, from which every count is
computed (\texttt{scripts/unified\_scoring.py}). An answer is \emph{flagged} on
the entity channel when the answer cites at least one inadmissible name. Each
violating answer also receives one \emph{kind}, the first that applies:
\emph{extrinsic} (a name or number that $E$ lacks), \emph{contradicts $E$} (for a
pair that $E$ carries, the value of another item), \emph{misplaced} (only items
of $E$, in an inadmissible place), or \emph{omission}. The middle two kinds are
misfiling. The kinds are exclusive, whereas the indicator ``contains a misfiled
name'' is not: an answer that misfiles one name and invents another counts as
extrinsic. A pooled check accepts only answers whose every name and number lies
in $E$, so pooled acceptance rests on the misplaced answers alone. \emph{Claims
matching $E$} counts, per answer, the claims whose pair $E$ carries and whose
value lies within $\tau$. The narrators copy numbers: 99{,}008 of 100{,}642
claims on carried pairs in the arms without a verifier reproduce the measured
value exactly, and the answers with a wrong number move only from 25 at
$\tau=5\times10^{-4}$ to 24 at $\tau=0.005$. Intervals are Wilson 95\,\%, with
raw counts. Two independently written scorers agree on every entity flag across
all 16{,}698 leakage records, and the seventeen faults that we found in our own
instruments changed derived numbers, never records~\cite{extended}.

\subsection{Registration and analysis}

The analysis plan and its amendments were frozen before the runs that they
govern. A result is \emph{confirmatory} only if the plan fixed its prediction
and test in advance; Table~\ref{tab:registered} lists the registered tests on
which the results rest, by content first and by plan code second. The plan
registered a 2-point equivalence band, and claims superiority only where the
interval excludes 0 and the point difference reaches 5 points; a significant
difference below 5 points is reported as significant and not material. When one
arm has a verifier, the arm's zero on (C1) and (C2) holds by construction, so a
test against that arm asks whether the other arm's rate exceeds zero. The test on
a channel other than names was void, because no such channel activated on
leakage; a comparison with NeMo Guardrails, a wording test on a second provider,
a test of omission, the shipped default narrator, two audits by hand, and the
first registered test of the verifier (A3) were not run or stopped; the rest are
in the extended version. The authors chose not to label their own blind audit
sheet (A7), kept for independent raters, and registered model judges instead. Of
the deviations, the stopped A3 runs weigh most, because the registered test of
the verifier on the twelve frozen tasks never ran; the panel, changed without an
amendment, limits generality; and the stock-loop comparison (X1), moved to the
synthetic task, is a control.

\paragraph{The failure is misfiling}
On the floor, \texttt{deepseek-chat} cited an inadmissible name in 42.0\,\%
[35.4, 48.9] of 200 answers on 2026-09-15, and four runs over nine days read
42.0, 43.0, 40.5, and 49.0\,\% ($\chi^2$, $p=0.34$). On the first four tasks,
all 1{,}012 flagged answers of the arms without a column domain cited a name that
$E$ contains: \texttt{r2} in the list of cited columns, and three times
\texttt{perfect\_match\_rate}. The pattern is not an artifact of synthetic data:
the floor misfiled in 21.5\,\% [16.4, 27.7] of answers on bodyfat and 20.5\,\%
[15.5, 26.6] on sambanis, every time with \texttt{r2}. On the twelve frozen
tasks, the floor cited an inadmissible name in 26.5 to 55.5\,\% of answers per
task, 817 of 1{,}888 in all: 795 misfiled, 18 cited only the frame's own target
column, which $E$ does not list, and 4 cited only an invented name, as
registered. Across all sixteen tasks, 1{,}807 of the 1{,}829 flagged answers
contain a misfiled name, and 13 used an invented name, 11 of them
\texttt{target} for the frame's own target column; the answers come from cells
that differ in arm, task, and date, so the composition is not an error rate. In
the floor run of 2026-09-19, whose narrations were recorded, 81 of 200 answers
listed \texttt{r2} among the cited columns, 73 of them beside all ten evidence
columns, and no narration called \texttt{r2} a column: the narrator appears to
read the undescribed field as a list of the evidence used, so the failure is a
property of the interface as much as of the model.

\paragraph{What the violations introduce}
On the bare leakage arms, 1{,}831 answers violate the contract, the 1{,}829
flagged answers and two that breach only (C2) or (C3). Of these, 1{,}772 are
misplaced, 57 extrinsic, one contradicts $E$, and one is an omission. Extrinsic
answers dominate in one place only, the enumeration written in advance for other
data, where 145 of 152 violating answers name columns that the frame lacks; those
names come from the enumeration itself. On this model, most violations introduce
nothing that $E$ lacks: the 1{,}772 misplaced answers use only items of $E$, so a
check against the pooled evidence would pass every one of them, and a contract
rate read as a hallucination rate would overstate invention many times over.

\paragraph{A semantic reading}
Whether a misfiled \texttt{r2} states a false relation is a semantic question.
In place of the blind audit (A7), whose 204-item sheet is in the replication
package with the key sealed, we registered automatic judges with one validity
check, at least 90\,\% correct in each direction on items whose truth is fixed by
construction. Two natural language inference models (A10) and two LLM judges
(A12) failed. The fifth judge, \texttt{gpt-5.5} pinned to the snapshot of
2026-04-23 (A13), passed, keeping 55 of 55 items that are not false and catching
73 of 79 false or absent items (64 of 65 after one instrument fault was
corrected). Contrary to our registered prediction that misfiled names would read
as right information in the wrong place, the judge classified all 40 misfiled
\texttt{r2} items (Wilson interval 91--100\,\%) as false relations. The validity
check held no item whose true label is ``right information, wrong place'', so
the check cannot validate the distinction on which the reading turns; we report
one model's classification, not a human judgment.

\paragraph{What a violation means}
Three quantities must therefore be kept apart: \emph{structural violations},
which the contract counts and enforces; \emph{semantic falsehood}, read here by
one judge not validated on the distinction at issue; and \emph{correct content rejected}, the price of a closed
world, since all 15 real columns that $E$ does not list were judged supported and
a correct class balance has no slot (Section~\ref{sec:rq3}). The contract
guarantees the first, bounds the second only through the first, and pays the
third.

\paragraph{What removes the failure}
The bare instruction says ``list every column from the evidence you cite'', and
the open schema says nothing about the cited-column field. A version of the
field description that names \texttt{r2}, run on the same day as the floor, and
the neutral description, run the next day, each took the rate from 49.0\,\%
(98/200, 2026-09-24) to 0.5\,\% [0.1, 2.8]. The arms were not interleaved, but the
drop far exceeds the floor's movement across four runs (40.5 to 49.0\,\%). The
shipped prompt gave 0/200 with or without its two sentences claiming that
violations are rejected; its first three rules alone left 7.0\,\% [4.2, 11.4];
and temperature 0 left 2.0\,\% [0.8, 5.0]. Our names do not explain the failure:
on the crowded task, whose columns all differ, the undescribed field gave
61.0\,\% [54.1, 67.5], every time with \texttt{r2}. Nor does every model fail:
\texttt{gpt-5.4-mini} never wrote \texttt{r2} into a column field in 200 answers,
nor did \texttt{qwen2.5:7b} in 20. Six rule-free rewordings of the bare
instruction, 100 answers each, ranged from 9.0 to 72.0\,\%, as sensitivity to
prompt format would predict~\cite{sclar2024formatspread}, and the number of
answers with a claim on a pair that $E$ does not carry followed how much of the
answer each wording specified, from 0 in 100 to 45.

\finding{Finding 1}{The failing narrator misfiled rather than invented: 1{,}772
of its 1{,}831 violating answers used only items of $E$, mostly \texttt{r2} in an
undescribed column field, and a pooled check passes all 1{,}772. On the reference
task, a field description, the shipped prompt, or temperature 0 lowered the rate
from 42--49\,\% to 0--2\,\%. The reading of the misfiled items as false rests on
one model judge.}

\paragraph{Every stated domain works on leakage column names}
On the reference task, every arm that told the model which columns are
admissible, through the shipped prompt, a field description, an enumeration, a
choice list, or our verifier, reached zero or one violation in 200; only the
shortened prompt, which states the domain in a rule, left 7.0\,\%. On the entity
channel of leakage, at this sample size, the contract therefore does not
outperform an enumeration or a choice list bound to $E$; on the profiling task,
the enumeration let column names through (Section~\ref{sec:rq3}), as did the best
configuration without the check in 6 of its 10 residual violations. Both arms of
X4 run our checks, so their tie holds by construction and shows only that the
check transfers to another toolkit's loop. The enumerations acted as requests:
the list written for the reference task was sent with the strict flag on the
crowded task, and 18 of its 200 answers named the anchor, which the list does not
contain, 5 of them beside columns from the list, which decoding enforced by the
provider could not have produced.

\paragraph{Diagnostic controls}
The controls show what a check without the right domain does, not what a strong
alternative does. On 2026-09-18, the stock Guardrails loop, which registers no
faithfulness validator, and the same loop with a choice list built from $E$ read
43.5\,\% against 0\,\%, with 88 answers repaired. On the crowded task, the choice
list, which checks only the cited columns, let three answers through, whereas our
checks in the same loop let none through (118 repairs). A typed schema without a
column list read 4.0\,\% in the registered run (X3) and up to 7.0\,\% in other
runs; the registered difference from the contract is significant and, on its
point difference, not material, although the interval (1.3 to 7.7 points) does
not exclude a material one. Schema text steers a model even where the schema
constrains nothing~\cite{le2026schemakey}.

\paragraph{Binding at call time}
On the reference task, a list written in advance equals the call-time list. On
the crowded task, that list covers none of the ten evidence columns, and the
model obeyed the list: 145 of 200 answers (72.5\,\% [65.9, 78.2]) cited columns
that exist only in the list, an invention that the undescribed field never
produced, and 132 of them omitted the anchor. The same task read 27.5\,\% with no
list and 0\,\% with the call-time list, which rejects the prediction registered
with the arm (A1) that a stale list would fall between the two. A registered,
interleaved test then varied the list's coverage (A14): lists covering 0, 3, 5,
8, or 10 of the ten evidence columns, each covering list including the anchor,
produced invented names in 143, 2, 0, 3, and 0 of 200 answers (Cochran--Armitage
trend, $p<10^{-76}$). The trend is carried by the list that covers nothing; at 8
of 10 columns, the residual could not be distinguished from the call-time list (3
against 0, Fisher $p=0.25$), and the test does not separate the anchor from the
other columns. Whether a list written in advance is safe thus depends on a
coverage that the list's author cannot check before the data arrive; binding at
call time removes that dependence.

\paragraph{Which check covers which error}
Table~\ref{tab:coverage} combines these results with the definitions of the
checks. A pooled check catches invention but passes both kinds of misfiling; a
check against the data frame catches the metric name but no number; the flat,
independent enumerations of our Tier~A steer names but do not express a value
that depends on a sibling field; and a choice list covers only its own field. The
field and pair check covers every column, except a neighbour's value within
$\tau$, flags rather than repairs an omission, and rejects true columns that the
evidence does not list. The comparison supports a claim about coverage, not about
rate: where a simpler check covers the errors that a narrator actually makes, the
simpler check suffices, and the field and pair check matters where the
configuration, the data, or the model changes.

\paragraph{The verifier in the best configuration}
The two strong arms read 0 in 200 on the reference, crowded, and both real
datasets on 2026-09-30, and the verifier never had to send a leakage answer back;
pooled over the four tasks, the difference is 0 with a Newcombe interval of $-0.5$
to 0.5 points. On the profiling task, an exploratory run left 4 of 200 unverified
answers in violation against none verified under natural names ($p=0.12$), and 0
against 0 under suffixed names the same day. A registered test of both tasks (A3)
stopped when the provider balance ran out, with no violation in its 93, 91, and
50 answers, and the plan forbade repeating that test, so we registered a new test
of the same design on the profiling task alone (A11), not pooled with A3: 600
answers per strong arm, interleaved on one harness commit, every attempt kept,
and one interim look on which no decision depended. The unverified arm delivered a violation in 10 of 600 answers
(1.7\,\% [0.9, 3.0]) and the verified arm in none (Fisher $p=0.002$; difference
1.7 points, Newcombe interval 0.7 to 3.0). The point difference lies below the
plan's 5-point bar, and so does the whole interval, so the difference is
significant but not material. A11 also does not exercise the tolerance of the
value channel: the ten violations are slips (two statistic names cited as
columns, four pairs that $E$ does not carry, such as the misspelled
\texttt{missding\_count}, and four columns that the frame lacks), and none is a
wrong number for a carried pair. Nine of the ten fall outside the enumerations
that Tier~A writes, so a provider that enforced the schema would also have
excluded them; the case for the check over such a schema rests on the values and
the anchor, which A11 did not exercise. The verifier cost 11 extra calls in 600,
and we saw no loss in what we measured: 29.4 claims matching $E$ per answer in
each arm, the anchor's value in every answer, and median latencies of 5.47 and
5.44\,s.

\paragraph{Cost and content}
Verification and stripping take a median of 17\,$\mu$s per answer (95th
percentile 41\,$\mu$s), and binding $E$ takes 15\,$\mu$s. End to end, the
contract arm took a median of 3.3\,s per answer against 2.8\,s for the floor, a
difference from the request, most likely the larger schema, not from the check,
although runs on different dates cannot separate schema from provider. One named
retry repaired every violation that the verifier met in the main runs; a second
was needed twice in 200 under a correction that names no problem and once in
A11, and arms that retried took 3.6 to 4.9\,s. The check did not buy compliance
by emptying answers: all but one reference answer delivered a claim, none
abstained, and the contract arms delivered as many claims matching $E$ per answer
as the floor. Nothing was stripped in a live run. In a registered leakage re-run
that kept every attempt (A9.2), retried answers carried 170 claims matching $E$
before the retry and 170 after, a measured count, not a check that the same
claims were kept; a script sharing no code with the verifier confirmed every kept
rejection, 24 on the profiling task and 17 in that re-run. The shipped prompt
delivered about a quarter as many claims matching $E$, so part of what that
prompt buys is a narrower answer.

\finding{Finding 2}{Under the contract, no (C1) or (C2) violation reached the
user, named retries repaired each violation, and the local check costs
microseconds. On leakage column names, an enumeration or choice list bound to $E$
did as well; a list written for other data turned misfiling into invention; and
in the best configuration the check removed 10 violations in 600, significant but
not material, none a wrong number for a carried pair. \texttt{gpt-5.4-mini}
showed no violation in the seven leakage arms that we ran on the model, so these
comparisons rest on \texttt{deepseek-chat}.}

\subsection{RQ3: A second evidence shape}\label{sec:rq3}

\paragraph{Misfiled values}
Under suffixed names, the failure moved from names to numbers
(Table~\ref{tab:rq6}): the floor put a wrong number in 9 of 200 answers
(4.5\,\% [2.4, 8.3]), and 11 of its 12 wrong numbers are the real measurement of
the column that shares the suffix, such as \texttt{cat\_feature\_07}'s missing
rate reported for \texttt{num\_feature\_07}. Under natural names, five days
later, the same model put a wrong number in none of 400 unverified answers. A
registered run that interleaved the two naming schemes on one harness commit
(A9.1) found 7 against 1 answers with a wrong number in 200 each ($p=0.068$), all
seven suffixed ones equal to the sibling's value. Name confusion is the likely
explanation, but the registered test did not reach significance, so the
explanation remains exploratory.

\paragraph{How the tiers separate}
The enumeration removed almost all claims on pairs that $E$ does not carry (20 to
1 under natural names), fewer inadmissible names (8 to 5), and no wrong numbers (9
against 11 under suffixed names). Tier~A's enumerations of columns and statistics
are flat and independent, so they can refuse a statistic name that no column has,
but neither a statistic that the chosen column lacks nor a number whose
admissible value depends on sibling fields. Tier~B caught both, since these
neighbours lay farther apart than $\tau$, and every contract arm read zero; a
pooled check would not have, since 11 of the 12 wrong numbers on the suffixed
floor and all seven in A9.1 are numbers that $E$ carries for a neighbouring
column; with the naming test short of significance and no host-filled or
per-pair schema arm, the claim holds among the arms that ran. Most claims on uncarried pairs
are the class balance, which the profiler reports for the whole task and the
narrator attaches to the target column; the contract offers that correct figure
no slot, and with the class shares admitted on the target column, the floor falls
from 26 to 10 violating answers under natural names and from 17 to 10 under
suffixed names.

\finding{Finding 3}{The contract carried over to a second evidence shape without
task-specific verification. Under suffixed names the failure moved to misfiled
values, which pooled checks and enumerations pass and the pair-keyed check caught
because the neighbours lay farther apart than $\tau$; under natural names the
violations were names and uncarried pairs, mostly a correct class balance without
a slot. The evidence for the value channel is exploratory.}

\section{Discussion}\label{sec:discussion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\paragraph{Design principles for tool narrators}
Four principles follow, stated for narrators like the one we studied, whose
failure was structural. \emph{Check at the granularity of fields and pairs}, since
pooled checks pass misfiling (Table~\ref{tab:coverage}). \emph{Bind the
admissible sets at call time}, since a list written in advance is safe only to the
extent of a coverage that the list's author cannot check. \emph{Describe every
field, and still check}: a one-sentence description was the cheapest fix, but
its effect is known only where measured, whereas the check's effect follows from
code in the caller's process. \emph{Report violations apart from what they
introduce}, as data-to-text evaluation already
does~\cite{pagnoni2021frank,thomson2020gold}; a model judge does not replace that
report, since four of our five judges failed a 90\,\% bar on items of known
truth, and the fifth costs about two cents per item.

\paragraph{Design alternatives}
Stripping without a retry would be cheaper, but would have deleted content from
6--16\,\% of \texttt{A-STRESS} answers and 41.5--59\,\% of the Guardrails arms'
answers, all of which one named retry repaired. If the model chose evidence
identifiers and the host filled in every number, the value channel would vanish
by construction wherever the host renders the answer, and a verdict derived from
$E$ would close the channel through which Huang and Deng show a verified verdict
being inverted~\cite{huang2026narration}. A strict mode with alternatives and
numeric bounds could express (C2) as one branch per pair, a schema that grows
with $|V_E|$ and is enforced inside the provider. We ran neither design, nor
grammar-constrained decoding, since the one open model that we ran did not fail.
The entity fields and the anchor would still be the model's choice, and where the
provider does not enforce the schema an enumeration is a request: 5 of 200
natural-name answers of \texttt{P-TIER-A-ONLY} put an inadmissible name into a
column field. Across a tool-server boundary, the tool can check and send back an
answer that a client model submits, but can neither fill in nor delete what the
client tells the user, so only the retry transfers; our tool-server path runs
without the contract. Host filling and the check are complements, and numbers
inside free sentences escape both.

\paragraph{Beyond leakage}
The design needs a deterministic producer, a finite set of observed entities and
values, a domain bound to that set at call time, and a tolerance for each kind of
quantity narrower than the gap between neighbours (Section~\ref{sec:limits}).
Narrators of static-analysis findings, continuous-integration failures, or
dependency-scanner reports meet these conditions, although their evidence may be
nested, relational, or larger; we have not measured them, and there, too, the
guarantee would be consistency with the tool's output, not correctness.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Threats to Validity}\label{sec:threats}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\paragraph{Construct}
We measure consistency with $E$; a contract violation is not always a false
statement, and the kinds are assigned by program. Under one strict and one
lenient policy for dataset-level quantities, 98.7\,\% of the violating bare
leakage answers (1{,}807 of 1{,}831) misfile under every policy, whereas the
lenient policy lowers the unverified profile counts from 36 to 19 and from 29 to
22. No person labeled any answer, so the effect of a misfiled item on what a
reader decides is not measured. In the unverified free text, a scan of 7{,}198
narrations found less ungrounded content where an arm can reject a claim (8.8
against 12.6\,\% on the reference task), but retried answers carried more than
first-pass answers, though not significantly (10.9 against 8.4\,\%, $p=0.19$;
8.6 against 5.2\,\%, $p=0.07$, on the crowded task), so some displacement into
the prose cannot be excluded; a misfiled name is in $E$ and so invisible to that
scan.

\paragraph{Internal}
Arms ran in blocks, except in the registered runs A9.1, A11, and A14, which
interleave their arms call by call, so drift within a day is controlled only
there. The provider serves a rolling model name and the harness changed between
runs; every record pins both, so a difference across dates cannot be attributed
to the provider alone.

\paragraph{External}
The failure occurred on one of three providers, at temperature 1.0, on particular
dates, and centered on one string, so every comparison rests on
\texttt{deepseek-chat} and one evidence schema, and the conclusions are limited to
the alternatives that ran. The contract arms ran on four of the sixteen leakage
tasks and on the profiling task; on the twelve frozen tasks, 512 of the floor's
2{,}400 calls were lost when the provider balance ran out. The shipped default
narrator, \texttt{claude-opus-4-7}, was registered and not measured for lack of
budget, and on the real datasets we called the narrator directly, so we evaluate
the narration component, not the product end to end. Provider limits on
enumeration size are unmeasured.

\paragraph{Conclusion validity}
Two hundred answers to one evidence dictionary measure one configuration's rate,
not 200 tasks. At 200 answers per arm, a comparison against a zero arm detects a
true rate of 4\,\% with power 0.8 but 2\,\% with power of only 0.21, which bounds
the A14 comparison at 8 of 10 columns; A11's 600 answers per arm detect 1.5\,\%
with power 0.89. Only the registered family is corrected for multiplicity, and
end-to-end latencies are medians.

\section{Related Work}\label{sec:related}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\paragraph{Faithfulness to a finite record}
Data-to-text generation measures faithfulness against a finite input record, with
slot error rates~\cite{dusek2020e2e}, relation-generation
precision~\cite{wiseman2017challenges}, and table-grounded
metrics~\cite{dhingra2019parent}; FRANK separates entity errors from
out-of-article errors~\cite{pagnoni2021frank}, Thomson and Reiter annotate wrong
numbers, entities, and contexts~\cite{thomson2020gold}, and generators have
reranked candidates for missing and redundant
slots~\cite{wen2015sclstm,juraska2018slot}. A misfiled item is an entity or
context error, and an invented one an out-of-article error; we claim neither the
categories nor the idea of a check. What differs for a tool narrator is the
setting: the check must run on the payload that a commercial API returns, without
control over decoding, before the user sees the answer. Our
evidence-closed assumption is a closed-world assumption~\cite{reiter1978closed};
the enforcement is a postcondition in the sense of Design by
Contract~\cite{meyer1992dbc}, and deletion is suppression in the edit-automaton
model~\cite{ligatti2005edit,schneider2000enforceable}.

\paragraph{Where constraints act}
Decode-time methods can bind constraints to the input: grammar-constrained
decoding admits input-dependent grammars~\cite{gcd}, PICARD and Synchromesh check
partial programs against a database schema or a program's
scope~\cite{scholak2021picard,poesia2022synchromesh}, and
CHyD~\cite{signe2026chyd} restricts output to spans of the retrieved context; all
need control over decoding, and ATLAS-RTC~\cite{cruz2026atlasrtc} intervenes
during decoding without a guarantee. What a schema enforces depends on the
engine~\cite{geng2025jsonschemabench}, and the wording of schema keys moves
accuracy~\cite{le2026schemakey}. Instructor and Guardrails~AI run
validate-and-reask loops whose validators can read call-time data, and NeMo
Guardrails~\cite{nemo} blocks or rewrites a response with output rails. Policy
contracts fix their domain when the harness is
written~\cite{ahn2026harness,zhang2025rvllm,winston2026solver}, whereas ours has
no domain until the evidence exists; Ahn and Kim find that prompts let violations
through, and our nearest observation is the residue of A11.
LedgerMind~\cite{du2026ledgermind}
checks entity and numeric grounding against the cited ledger entries with a
tolerance and restricts repair to edits that add nothing unprovenanced, our
repair asymmetry in another form; that ledger grows during a trajectory, whereas
ours is complete before the call. EviBound~\cite{chen2025evibound} gates a
research agent by querying the run tracker for the run that the agent claims.

\paragraph{Narration under a check}
Four recent preprints check what a model says about tool output.
FAX~\cite{kim2026fax} tests each claim of an agentic explanation against faithful
tools before the final answer. Huang and Deng~\cite{huang2026narration} show that
a verified verdict can be inverted in narration, which hardened prompts reduce
but do not remove; their channel is the verdict, which our contract leaves
unchecked. ProvenanceGuard~\cite{alvarez2026provenanceguard} targets claims
attributed to the wrong source, misfiling at the granularity of sources.
VERITYGATE~\cite{gupta2026veritygate}, posted while our runs were under way, is
the closest in setting: its gates check that a narration's evidence identifiers
exist, that each entity belongs to the set that the backend emitted, that each
number string matches some number string of the evidence exactly, and that each
claim type cites the evidence type that the type requires. The entity and number
gates compare with pools, so on evidence like ours a metric name in a column
field and a neighbouring column's value would both pass; the claim-type gate is a
coarse form of field indexing. None of these works keys a number to the entity
and statistic that the number claims, or measures how often a failing narrator
misfiles rather than invents.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Conclusion and Future Work}\label{sec:conclusion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

When an LLM narrates a deterministic tool's output, which values each field of
the narration admits has an exact answer at call time; we made that answer
explicit at the granularity of fields and of (entity, statistic) pairs. The one
narrator that failed often mostly misfiled rather than invented, which pooled
checks pass and a one-sentence field description removed where measured, and the
check let no inadmissible column or number reach the user through the structured
fields, at microseconds of local checking. On leakage column names an
enumeration bound to the evidence did as well, and in the best configuration the
check removed only a small residue. The study therefore contributes less a new
mechanism than an account of how a tool narrator fails, a map of which check
covers which error, and a design that catches the failure in the structured
fields, up to its tolerance, wherever the configuration does not. The results
come from one failing model on one testbed. Future work should compare the check
with a strict mode that the provider enforces and with host-filled values, run a
second producer and more failing narrators, have independent raters read the
audit sheet, and set the tolerance per statistic.
