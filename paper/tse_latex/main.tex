\begin{abstract}
When a large language model explains a deterministic analysis to an
engineer, a column or number the analysis never produced gets acted on. For
narration whose citable entities and checkable quantities are finite and
enumerable at call time, we bind each response field's admissible set to the
evidence and verify the returned payload in host code, with a named retry.
This is ordinary validate-and-reask. It ships in \textbf{mlcompass}, an
open-source ML-pipeline assistant, and we measured it over 12{,}960 live
responses. \texttt{gpt-5.4-mini} and a local \texttt{qwen2.5:7b} never fail
without enforcement; \texttt{deepseek-chat} does. Under the bare instruction
all 924 of its flagged responses on a data-leakage task \emph{misfile} a real
evidence name into a field that does not admit it; none invents a column.
One sentence of field description takes the rate from 49\,\% to 0.5\,\%,
even when it names no metric. The shipped prompt, which says violations are
rejected, gives 0\,\%; its three rules alone leave 7\,\%. Without a fix it
returns (61\,\% on a second task instance). An enum fixed at
authoring time turns misfiling into invention (72.5\,\%) on data it predates;
one built from the evidence at call time reads zero. The verifier held on two
task instances and two evidence shapes and repaired every violation with one
named retry, adding about half a second when nothing needed repair. It
certifies each response's structured channels for referential and value
soundness, which a measured rate cannot. Verdict and prose are outside it;
scanning the prose found nothing displaced there.
\end{abstract}

\begin{IEEEkeywords}
Large language models, faithfulness, runtime verification, structured
output, constrained generation, data leakage.
\end{IEEEkeywords}}

\section{Introduction}\label{sec:intro}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\IEEEPARstart{M}{achine-learning} practice runs on single-purpose tools:
profilers~\cite{ydata}, experiment trackers such as MLflow and
TensorBoard~\cite{mlflow,tensorflow}, and automated model
search~\cite{autosklearn}. None of them tells the engineer what the results
\emph{mean}. The now-standard answer is agentic: an LLM calls the tools, reads
their structured output and explains it~\cite{react,toolformer,mcp}. LLMs
produce content their input does not support~\cite{ji,huang}, and assistants
built on them still fail real software tasks~\cite{codex,swebench}.

A concrete case shows what is at stake. An engineer's regression model scores
$R^2=1.0$ on held-out data. \textbf{mlcompass}, the open-source ML-pipeline
assistant this paper studies, treats a score that high as a sign of data
leakage: it fires, for example, when $R^2>0.999$, $\mathrm{AUC}>0.995$ or
accuracy $>0.99$ on at least 50 rows, thresholds of our own motivated by the leakage problem
Kaufman \emph{et al.} describe~\cite{leakage}. A
deterministic detector then computes how strongly each feature correlates
with the target and ranks the columns that could be carrying the target into
the features. Its output is the \emph{evidence}, a dictionary we write $E$.
An LLM explains $E$ to the engineer by filling in a structured answer: a
verdict chosen from four labels (leakage likely, leakage uncertain, score
legitimate, cannot determine), the list of columns it cites, and claims of the
form (column, statistic, value). On the frame this paper studies
(Section~\ref{sec:design}), a sound answer cites the leak column
\texttt{log\_target\_v2} with its measured correlation of 0.999.

The narrated object is thus \emph{structured evidence}, and a structured
claim about it can be wrong in two ways. It can name an entity or quote a
quantity that appears nowhere in the evidence (an \emph{extrinsic} error). Or
it can put something the evidence really contains where it is not admissible,
such as the metric's name \texttt{r2} in the list of cited columns, or one
column's measurement on another (an \emph{intrinsic} error, which we call
\emph{misfiling}). On the model that
fails in this study, all 924 flagged responses under the bare instruction
are misfilings, and they come from a field whose admissible set nobody stated.
One sentence of field description or the prompt mlcompass ships removes the
failure,
the prompt's rules without its claim of enforcement leave 7\,\%, and two other
providers never show it. Where no fix is present, it returns.

Each of these fixes is cheap and works where it was measured. A tool author
cannot measure every combination of prompt, schema, user data, provider and
date the tool will meet. What the narrator may cite, however, is \emph{finite
and machine-enumerable at the moment of the call}.

\begin{definitionx}[Evidence-closed narration]\label{def:closed}
A narration task is \emph{evidence-closed} if the set of citable entities and
verifiable quantities is finite and machine-enumerable at the moment of the
narration call.
\end{definitionx}

For such a task, checking the structured claims against the evidence takes a
membership test per field and a numeric comparison per claim, so their
soundness can be enforced instead of measured. We keep to this narrower scope
throughout. A free-text sentence can name only real columns and quote only
real values and still assert a causal story the evidence does not support,
and the evidence itself can be wrong.

Constrained decoding~\cite{outlines,lmql,gcd,guidance,scholak2021picard} needs
the token distribution, which commercial APIs withhold, and nobody outside
the provider can observe whether a provider-side schema~\cite{structured} was
honoured. Our mechanism is an \textbf{evidence-bound runtime contract}. The
narrator answers by calling a tool whose input is described by a JSON Schema,
and a schema's \texttt{enum} lists the only values a field may take.
\emph{Tier~A} builds these lists from the evidence at call time, so the column
field admits exactly the columns in $E$; an enum is a request to the model,
not a check. \emph{Tier~B} re-checks the returned
payload in plain code for entity soundness, value soundness of \{column,
statistic, value\} claims, and coverage of the top-ranked candidate, and
answers a violation with a named corrective retry, residual stripping and
omission flagging. Toolkits such as Instructor~\cite{liu2023instructor} and
Guardrails AI~\cite{guardrailsai} already support this validate-and-reask
pattern, and we do not claim the mechanism as new. It is the default narration
path of mlcompass (MIT licence), where it guards the leakage investigation
described above; static leakage detectors for notebook code address the same
problem before training~\cite{yang2022leakage,truong2025leakagedetector}. We
describe it as shipped rather than in production, because we have no
deployment telemetry.

We ask five research questions (RQs). \textbf{RQ1}: how does an
unconstrained narrator of evidence-closed material fail, and what produces the
failure? \textbf{RQ2}: does the contract prevent it on the checked channels,
and at what cost? \textbf{RQ3}: how do the alternatives a practitioner would
reach for compare, namely a stock guardrail toolkit, a provider schema, an
enum written in advance and a rule-bearing prompt? \textbf{RQ4}: how far do
instruction wording and specification move compliance? \textbf{RQ5}: do the
contract and the failure carry over to a second kind of evidence?

The paper makes four contributions. (i) It formulates field-indexed
admissibility for evidence-closed narration (Definitions~\ref{def:closed}
and~\ref{def:contract}), which separates misfiling from invention and lets a
generic membership check enforce soundness. (ii) It measures what enforcement
is up against. On the one model that fails, the failure is misfiling caused by
under-specification; cheap fixes remove it but do not carry across
configurations, while a verifier holds on two task instances and two evidence
shapes and repairs every violation with one named retry. (iii) It compares the
alternatives inside one guardrail toolkit and one provider. An author-time
enum applied to data it predates does worse than no enum, and the toolkit's
own choice semantics bound to the evidence match our validator on the field
they check and miss what they do not check. (iv) It provides a replication
package~\cite{replication} with every model reply, one record per live
response, the frozen analysis plan with its amendments and deviations, the
registered falsifier, and fourteen instrument faults with what each moved.

\section{Background and Related Work}\label{sec:related}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Closed-world faithfulness, and where it has been measured}

Definition~\ref{def:closed} is a closed-world assumption~\cite{reiter1978closed}
over $E$: whatever the evidence does not carry is false as far as the
narrator is concerned. The setting is old. Data-to-text and
meaning-representation-to-text generation narrate a finite record and measure
faithfulness against it offline, with slot error rate over the input's
slots~\cite{dusek2020e2e}, relation-generation precision against the source
table~\cite{wiseman2017challenges}, and table-grounded
scoring~\cite{dhingra2019parent}. In the taxonomy of Ji \emph{et
al.}~\cite{ji} and of Maynez \emph{et al.}~\cite{maynez2020faithfulness}, a
name absent from $E$ is an \emph{extrinsic} error and a real evidence item
asserted in the wrong place is an \emph{intrinsic} one. We use \emph{invented}
and \emph{misfiled} for these two classes on a structured channel and claim
neither category as new. Xu~\cite{xu2025openworld} argues that hallucination
is unavoidable under an open world and can be mitigated under a closed one,
and Luo \emph{et al.}~\cite{luo2026removal} repair a model's own explanations
by removal. An evidence-closed tool narrator changes only where the check
runs: at call time, on the payload the user will see, instead of offline on a
corpus.

Tool-use frameworks~\cite{react,toolformer,mcp} govern how an agent acts and
say nothing about what it may afterwards claim about a tool's output.
Provenance work reconstructs evidence support from traces after the
fact~\cite{wang2026agenttraces}, and Ng \emph{et
al.}~\cite{ng2026runtimecontract} argue that agent safety belongs in a runtime
contract. The enforcement mechanism itself is classical. Tier~B is a
postcondition in the sense of Design by Contract~\cite{meyer1992dbc}, and
deleting what violates it is \emph{suppression}, the weakest edit an edit
automaton can make~\cite{ligatti2005edit}. Schneider~\cite{schneider2000enforceable}
and Falcone \emph{et al.}~\cite{falcone2012verify} characterise which
properties a monitor can enforce at all.

Decode-time methods can bind constraints to the input as well.
Grammar-constrained decoding admits input-dependent grammars~\cite{gcd}.
PICARD, a constrained decoder for text-to-SQL, and Synchromesh, its
counterpart for code generation, check partial programs against a database
schema or a program's scope~\cite{scholak2021picard,poesia2022synchromesh};
monitor-guided decoding consults static analysis of the
repository~\cite{agrawal2023mgd}; and CHyD~\cite{signe2026chyd}, a decoder
for retrieval-augmented generation, restricts output to spans of the
retrieved context. All of them need the token distribution, which a
commercial endpoint withholds. ATLAS-RTC~\cite{cruz2026atlasrtc}, a
token-level runtime controller for agent output, intervenes during decoding
with masking and rollback, and Life-Harness~\cite{xu2026lifeharness}, which
adapts the harness around a fixed model, improves 116 of 126 settings; both
report empirical gains and give no guarantee. Le~\cite{le2026schemakey} shows that schema-key wording moves
accuracy in both directions, which is a reason to distrust a schema whose
effect has not been checked.

Other tools already sit in this paper's row of Table~\ref{tab:taxonomy}.
Instructor~\cite{liu2023instructor}, a Python library for structured LLM
output, validates a response against context supplied at call time and
re-asks on failure. Guardrails AI~\cite{guardrailsai}, an open-source
validation framework, and NVIDIA's NeMo Guardrails~\cite{nemo} ship
validate-and-reask loops whose validators can read call-time metadata. Our mechanism is one
instance of that practice. We add three things: the field-indexed admissible
domain, derived from a deterministic producer's output, which separates
misfiling from invention and which a generic membership check can then
enforce; measurements of which failure actually occurs, what enforcement costs
and which alternatives reach the same result; and a shipped artifact whose
narration path is the one we measured.

Three pieces of work are closest. Ahn and Kim~\cite{ahn2026harness} vary the
enforcement layer with the model fixed and find what we find: prompts let
violations through, a bolt-on guardrail over-refuses (88/120 utility against
120/120), and code-owned enforcement keeps both, over 270 runs on three hosted
models. Their contract is a policy fixed when the harness is written, whereas
ours has no admissible domain until the evidence exists.
LedgerMind~\cite{du2026ledgermind} lets claims cite only active ledger
entries, checks entity and numeric grounding, and restricts repair to
transitions that add no unprovenanced content. That covers three of our
channels and our repair asymmetry (Proposition~\ref{prop:asym}), which we
derived independently; its ledger grows during a trajectory, while ours is
complete before the call. EviBound~\cite{chen2025evibound} gates an ML
research agent by querying MLflow for a run, its artifacts and a terminal
status, with bounded retries, eleven months before our measurements. It checks
that a claimed \emph{action} occurred, for instance that a training run the
agent reports really finished. We constrain what may be \emph{said} about a
measurement already taken: the narrator may report \texttt{log\_target\_v2}'s
correlation as 0.999, but may not list \texttt{r2} as a column or quote a
correlation $E$ does not contain.

\section{Evidence-Closed Narration}\label{sec:theory}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{The evidence, and why admissibility is per field}

In the leakage investigation, the evidence dictionary $E$ holds the
suspicious metric and its
value; per-feature correlations against the target $y$, taking whichever of
$\rho_P$ and $\rho_S$ has the larger magnitude and keeping its sign; a ranked
candidate-leak set $C=\{c:\max(|\rho_P(c,y)|,|\rho_S(c,y)|)\ge 0.99\}$; and
the perfect-match rate $P(\hat y=y)$. We report Spearman because monotone
target transforms pull $\rho_P$ down while $\rho_S$ stays at 1. Our log-target
leak sits at $\rho_P=0.93$ against $\rho_S=0.999$ and would slip under a
Pearson-only filter.

Let $N_E$ be every name $E$ carries, its keys and its string values. The
obvious formalisation admits any member of $N_E$ in any reference field. Under
it, a column field reading \texttt{r2} counts as sound, because
\texttt{r2} is in $E$ as the name of the \emph{metric}. We therefore index
admissibility by field.

\subsection{The contract, stated as an invariant}

Let $F$ be the answer's reference-bearing fields: in the leakage contract,
the list of cited columns and the column and statistic of each claim
(\texttt{columns\_referenced}, \texttt{claims[].column} and
\texttt{claims[].statistic} in the schema). Their entries, the \emph{leaves},
are names compared as strings. $E$ determines an admissible set $A_{E,f}$ per
field, with the column and statistic domains disjoint, and a value table $V_E$
with $\mathrm{dom}(V_E)\subseteq A_{E,\mathrm{col}}\times A_{E,\mathrm{stat}}$.
A leaf is \emph{misfiled} when it lies in $N_E$ but not in the $A_{E,f}$ of
its own field, and \emph{invented} when it is not in $N_E$ at all. A
response \emph{commits} when its verdict is admissible and is not the
abstention ``cannot determine''; the entities it \emph{references} are its
leaves in the column fields.

\begin{definitionx}[Evidence-bound runtime contract]\label{def:contract}
A structured response $r$ \emph{satisfies} $\mathcal{C}_E$, with tolerance
$\tau$ and anchor $a^*$, if \textbf{(C1, entity soundness)} every leaf of
$r$ in a field $f \in F$ lies in $A_{E,f}$; \textbf{(C2, value soundness)}
every claim $(e,s,v)$ in $r$ has $(e,s) \in \mathrm{dom}(V_E)$, $v$ a finite
number, and $|v - V_E(e,s)| \le \tau$; and \textbf{(C3, completeness)} if $r$
commits, the anchor $a^*$, the top-ranked candidate, is among the entities
$r$ references.
\end{definitionx}

(C1) and (C2) together state \emph{referential and value soundness with
respect to $E$} on the structured channels. This is narrower than
faithfulness in general: the verdict, the free-text narration and the
suggested checks lie outside it, and $E$ itself is trusted. Tier~B enforces
(C1) and (C2). A response that violates either is sent back, at most twice,
with the violation named, and whatever still violates it after that is
deleted. A response with no admissible verdict is retried the same way and,
if the problem persists, aborted instead of completed on the narrator's
behalf. Hence \emph{no structured claim that Tier~B returns violates (C1) or
(C2)}. This is a property of the verifier, checked by 36 offline mutation
tests and by a property-based search over $10^6$ generated (evidence,
response) pairs that the analysis plan registered before the study
(Section~\ref{sec:instruments}). Because it does not come from sampling, we
report an enforced arm's clean result as what the verifier did and attach no
interval to it. (C3) cannot be enforced in the same way.

\begin{proposition}[Repair asymmetry]\label{prop:asym}
Soundness is safe-repairable by deletion: the projection $\Pi_E(r)$ removing
every violating element is sound, idempotent, and the identity on sound
responses. Completeness is not: any repair must add a reference the model did
not produce.
\end{proposition}

\begin{IEEEproof}[Proof sketch]
Deletion preserves membership and tolerance and can remove every violating
element. For completeness, deleting the verdict would discharge the
obligation, but the schema requires a verdict, and substituting ``cannot
determine'' would attribute to the narrator a stance it did not take. Both premises are stipulations of this contract, and the artifact
honours them by aborting instead of substituting. Given them, every remaining
repair inserts an anchor reference absent from $r$.
\end{IEEEproof}

Tier~B therefore strips unsound content and only \emph{flags} a persistent
omission, which in edit-automaton terms is suppression without
insertion~\cite{ligatti2005edit}. In the security setting insertion is simply
a stronger primitive; over a narrator, an inserted reference would fabricate
attribution. The check runs in linear time. Hashing each $A_{E,f}$ and $V_E$
once turns every entity, claim and anchor test into one lookup, so a response
costs $O(|r|)$ after $O(\sum_f|A_{E,f}|+|V_E|)$ preprocessing. This matters for
feasibility only. The step that needed care was keying $V_E$ on the pair,
which our own scorer once failed to do (Section~\ref{sec:instruments}).

\section{The Artifact}\label{sec:contract}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Architecture and the trust boundary}

Figure~\ref{fig:contract} splits the system at a trust boundary. One side
holds everything deterministic: the pure-Python evidence producer, $E$, the
Tier~B verifier and the user-facing output. The other side holds the LLM
narrator, which we treat as untrusted whoever serves it. The system has three
\emph{layers}: evidence production, a narrator told the rules in words
(Section~\ref{sec:rq3} measures what that is worth), and the evidence-bound
schema, through whose submission tool the answers arrive.
The contract spans the last two layers as two enforcement \emph{tiers}.
Tier~A restricts the cited-column list and each claim's column to enums
built from $E$ at call time. It remains a request. On
\texttt{deepseek-chat} every Tier~A arm in the main battery ran without the
provider's strict decoding flag, and we report the one arm run with the flag
separately. Tier~B re-checks the returned tool input in plain code for (C1),
for (C2) within $\tau=0.005$, and for (C3).

A failed check earns a corrective retry that names the offending items
(budget 2). Whatever is still unsound after that is stripped, a persistent
omission is flagged, and completeness is re-checked after stripping, because
deleting an unsound claim can orphan the anchor. A response with no
admissible verdict (no tool call, unparsable arguments, or a verdict outside
the enum) is retried with a fixed correction and, if the problem persists,
aborted. In that case no verdict, claim or prose is shown, and the user sees
the deterministic evidence panel, which is printed unconditionally. A provider
exception propagates. The abort path is recent; the earlier code passed a
response with no admissible verdict as an empty answer. In the records such
responses occur only on arms without a verifier (4 on \texttt{deepseek-chat},
8 on \texttt{qwen2.5:7b}), so no reported number depends on the change.

\subsection{One contract, two instances}\label{sec:generic}

For most of this study the code handled a single instance: one column set,
each claim's statistic fixed to correlation, and each claim
checked by looking its column up in the correlation map. The contract is now a
layer. A specification says how to read one evidence shape, binding yields the
field-indexed domains, the value table and the anchor, and the verifier,
stripper, retry text and schema builder name no task. Leakage is one specification of
about forty lines. A dataset profiler is a second: every column of the frame
is admissible, each column has up to thirteen statistics, and the statistic
set is computed per call because a categorical column carries a cardinality
and no mean. The profile narrator runs in the measurement harness, and the
leakage narrator is the one the product ships.

Extracting the layer exposed something the single task could not: the value
table must be keyed on $(\text{entity}, \text{statistic})$. With one statistic
per column the two keyings coincide. In a profile, the column \texttt{age}
has mean 38.5 and missing fraction 0.012, and a table keyed on the column
alone checks a claim about one against the other. That is one of the scorer defects in
Section~\ref{sec:instruments}, reappearing in the production path. The
evidence's surface shape also has to match the flat claim slot: narrators
handed a nested quantity invented a flattening, five different ones in all.

\subsection{What the invariant does not cover, and a threat model}

Four things fall outside the invariant. The first is the verdict and the
prose. The verdict is checked for admissibility and not for agreement with
$E$, so a narrator may cite the planted leak and still answer
``score legitimate''. None did: of the 6{,}500 leakage responses in this
study whose verdict is one of the four labels, all on tasks with a planted
leak, 6{,}403 say ``leakage likely'', 51 say ``leakage uncertain'' and 46
abstain.
That is an observation and not a property of the contract. The free-text
narration and the suggested checks are printed beneath the validated content
and marked unverified; Section~\ref{sec:threats} measures what they carry.

The second is the correctness of $E$. If the leakage detector mis-ranks a
candidate, the contract faithfully narrates a wrong finding. The producer is
trusted and not verified, and (C3) names one anchor rather than every finding.

The third is the other narration surfaces. The product prints two other
narrations of the same evidence that no contract governs: an optional LLM
interpretation panel printed by the evaluation command, and a tool-server
command whose
calling model narrates in the user's editor~\cite{mcp}. The interpretation
panel is marked unverified. The tool-server narration carries no mlcompass
marker at all, because the client model writes it. mlcompass guarantees the
contract panel and nothing else.

The fourth is adversarial evidence. Column names come from the user's data
and reach the schema's enums, the prompt, the corrective retry and the
rendered panel. Membership in $E$ does not make a string safe. A crafted
header is a prompt-injection vector~\cite{greshake2023injection}, and a
schema's keys and enums are part of the model's
instructions~\cite{le2026schemakey}. The contract guarantees only that what is
shown is in $E$. Rendered strings are escaped, because a header written as
markup restyled the panel. Bounding name length and screening
instruction-like headers before binding are not implemented.

\section{Study Design}\label{sec:design}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Following the ACM SIGSOFT Empirical Standards~\cite{ralph2020standards},
the community checklists for what an empirical software-engineering study
should report, the study is a controlled experiment over fixed evidence
dictionaries. The
manipulated variable is the enforcement mechanism (RQ1--RQ3, RQ5), the
instruction wording (RQ4), or the naming and description of the evidence (the
controls of RQ1 and RQ5). The analysis plan and its amendments were frozen
before the runs they govern and are in the replication package, and
Table~\ref{tab:registered} reports what the plan registered and what became of
each item.

\subsection{Subjects}

The subject is the shipped leakage-investigation path. The \emph{reference}
task is a 1,000-row frame of fourteen columns (target, prediction and twelve
candidate features). The target is $y\sim\mathcal{N}(50,10^2)$, and the frame
carries a monotone transformed leak,
$\texttt{log\_target\_v2}=\log(y-\min y+1)+\varepsilon$ with
$\varepsilon\sim\mathcal{N}(0,0.01^2)$, the kind of column left behind when a
log-transformed copy of the target stays among the features, and a
high-correlation distractor. Its evidence has ten columns and the anchor
\texttt{log\_target\_v2}. A second, \emph{crowded} instance has 1,200 rows,
an anchor \texttt{sensor\_ref} correlating at 0.995 with the target, and nine
near-tied distractors \texttt{sensor\_00}\ldots\texttt{sensor\_08} at
0.900--0.924. A column list written while authoring against the reference task
covers none of its ten evidence columns. In every arm the shipped leakage
detector produces $E$. Section~\ref{sec:rq6} describes
the profile task of RQ5.

\subsection{Arms}

An \emph{arm} is one experimental condition: a fixed system prompt, tool
schema and check on the returned answer. Table~\ref{tab:armsdef} lists them.
The names follow the analysis plan and the replication package, so every
number can be traced to its records. The \emph{bare} prompt states the task
and no faithfulness rule. The \emph{shipped} prompt, the one mlcompass uses,
states seven rules (among them: cite only items in $E$, copy numbers exactly,
address the top candidate) and a verdict mapping, and tells the model that the
schema restricts the column field and that violations are rejected; on the
arms without enforcement neither is true. An \emph{open} schema has the
answer's fields and lists no admissible values. \texttt{A-CONTRACT} runs the
shipped enforcement under the bare prompt, so that mechanism is not
confounded with instruction. \texttt{A-STRESS} removes the Tier~A enums so
that every Tier~B catch is observable. \texttt{A-GR-CHOICES} is our
reimplementation of the toolkit's acceptable-values validator with its list
built from $E$ at call time, because a fresh install of Guardrails~AI~0.11
registers no validator. Every arm with a retry loop has a budget of 2.

\paragraph{Sample size and dates}
Each arm on \texttt{deepseek-chat} and \texttt{gpt-5.4-mini} has $N=200$,
fixed in the analysis plan; the local \texttt{qwen2.5:7b} arms have $N=20$ and
the RQ4 variants $N=100$. One arm's responses on one task instance and date
form a \emph{cell}, and the arms run together on one date a \emph{battery}.
A count of 0 in 200 bounds
the rate below 1.9\,\% (Wilson, 95\,\%), and two arms about 4 percentage
points apart are told apart with power 0.8 (Section~\ref{sec:threats}). The
provider serves a rolling model name, so the same arm can read differently on
different days. Every rate therefore carries its run date, and arms are
compared within a date.

For RQ4 the bare instruction was rewritten six ways (\emph{terse},
\emph{baseline}, \emph{cautious}, \emph{expert}, \emph{helpful},
\emph{mechanical}), with $N=100$ per variant. None contains a faithfulness
rule, and all were written before the September runs. A June pilot measured
the same sweep (fault 5 in Table~\ref{tab:corrections}).

\subsection{Measures}

We score three structured channels on every response that reaches the user.
An \emph{entity} violation is a leaf outside its field's admissible set; a
\emph{value} violation is a claim whose column is in $E$ but whose value
misses the measurement by more than $\tau$, or whose pair $E$ does not carry;
an \emph{omission} is a committed verdict that never references the anchor.
We report percentages with Wilson 95\,\% intervals and the raw $k/N$. For an
arm with a verifier we report what the verifier did (Table~\ref{tab:retry})
and do not read its zero as a rate. The entity channel decomposes into
\emph{invented} and \emph{misfiled}, and the value channel into wrong numbers
and pairs $E$ does not carry. We exclude artifacts, namely a \texttt{null}
column and several real names in one string, and exclude transport errors from
$N$ while reporting them.

The tolerance decides almost nothing. Of 49{,}253 claims scored before any
verification could act on them (every unenforced leakage and profile arm, all
runs), 46{,}552 reproduce the measured value exactly and 2{,}675 round it by
less than $5\times10^{-4}$, so only a tolerance below that would begin to flag
rounding. One claim drops a correlation's sign ($|\Delta| = 0.039$), and the
remaining 25 miss by more than 0.05. The number of responses with a value
violation is 22 at every $\tau$ from $5\times10^{-4}$ to $0.01$ and 21 at
$0.05$ (\texttt{scripts/tau\_sensitivity.py}).

\texttt{deepseek-chat} is the model on which the failure occurs;
\texttt{gpt-5.4-mini} and a local \texttt{qwen2.5:7b} are the null providers
(Section~\ref{sec:rq3-second}). Temperature is 1.0 everywhere, sent
explicitly and recorded. That is every endpoint's default and the shipped
narrator's setting. It also works against our thesis where it matters, since
a contract arm with no violation at the noisiest temperature cannot be an
artefact of a quiet one. For the baselines it cuts the other way: their rates
are conditioned on $T=1.0$.

\section{RQ1: How the Unconstrained Narrator Fails}\label{sec:rq1}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

On the bare arm \texttt{deepseek-chat} cited a name outside the column
domain in 42.0\,\% [35.4, 48.9] of 200 responses on 2026-09-15 (84/200). Four
runs over nine days read 42.0, 43.0, 40.5 and 49.0\,\%, with no detectable
heterogeneity ($\chi^2$, $p=0.34$). Decomposed, the rate contains no
fabricated column.

\paragraph{Composition of the failures}
We looked at every arm that runs the bare instruction with no column domain,
in every run: thirteen cells of 200 on two task instances, with 924 flagged
responses. Each of those
responses places a real evidence name where it is not admissible. The name is
\texttt{r2}, which $E$ carries as the name of the suspicious metric, written
into the list of cited columns; three times it is \texttt{perfect\_match\_rate},
the name of another quantity in $E$.
One response also cites \texttt{target}, a real column of the frame that $E$
does not list, and no response names a column that does not exist. In the
terms of Section~\ref{sec:related} the failure is intrinsic. Our measure is
strictly \emph{out-of-evidence}, which is weaker than \emph{non-existent}: a
real column that $E$ omits scores as outside it, as \texttt{target} does.

\paragraph{Cause: an undescribed field}
The bare instruction says ``list every column from the evidence you cite'',
and the open schema says nothing about the cited-column field. The
suspicious metric is the thing under investigation, so the model cites it.
One sentence of field description takes the rate from 49.0\,\% (98/200,
\texttt{A-L1} on 2026-09-24) to 0.5\,\% [0.1, 2.8] (1/200), whether the
sentence names \texttt{r2} (\texttt{A-L1-DESCRIBED}, same day) or only says
``not the names of metrics or statistics'' (\texttt{A-L1-DESCRIBED-NEUTRAL},
next day). Rules do less on their own. The shipped prompt's first three rules,
stated without enforcement claims, leave 7.0\,\% [4.2, 11.4] (14/200,
\texttt{A-L2-RULES}), every one \texttt{r2}. The full shipped prompt gives
0\,\% (0/200, below 1.9\,\% at 95\,\% confidence; \texttt{A-L2}), which the
analysis plan predicted when it chose the bare prompt for the comparison
(Table~\ref{tab:registered}). It differs from the rules in more than its claim
that violations are rejected (Section~\ref{sec:design}), and we did not
separate those differences. Our reference names do not explain
the misfiling: on the crowded instance, whose columns all have different
names, the undescribed field gives 61.0\,\% [54.1, 67.5] (122/200), every one
\texttt{r2}. Nor does it occur on every model. \texttt{gpt-5.4-mini} never
writes \texttt{r2} into a column field in 200 responses, and a local
\texttt{qwen2.5:7b} never does so in 20.

\paragraph{Consequences}
On this model the characteristic failure is the evidence's own vocabulary
leaking into a field whose admissible set nobody stated, and that changes
what the number may be called. It remains a violation: a consumer that drops,
correlates or flags \texttt{r2} as a leak candidate acts on something that is
not a column. It also leaves every arm comparison intact, since every arm faced
the same instruction. For the case for enforcement it adds one specific point.
The failure disappears under a cheap, reasonable fix and comes back whenever
the fix is missing, and whether a deployed schema is specified well enough is
known only where someone has measured it.

\paragraph{Abstention}
A narrator that retreated into ``cannot determine'' would score zero on
every channel for free. Of the 46 abstentions in the study, 41 are on the
crowded instance's stale-enum arm, whose list contains none of the evidence's
columns, 2 on that instance's contract arm, and 3 on \texttt{qwen2.5:7b}
(of 40 responses on its two contract arms); \texttt{gpt-5.4-mini} never abstains. A further
12 responses carry an empty verdict (8 of 160 on \texttt{qwen2.5:7b}, 4 on
\texttt{deepseek-chat}), all on arms without a verifier. The median response
carries ten structured claims. The zeros of the enforced arms therefore come
from narrators that committed to a verdict.

\subsection{Comparing the mechanisms}

On the reference task, every arm that states the admissible column set
reaches zero or one violation in 200, whether it states the set in the
shipped prompt, a description on the field, an enum in the schema, a choice
list in a guardrail loop, or our verifier. The one exception is the shipped
prompt's first three rules on their own, at 7.0\,\%. A typed schema without a
column enum reads 4.0\,\%, and the arms that state nothing read 35--49\,\%
across runs. The cleanest comparison is the same-date one inside a single
toolkit. On 2026-09-18, \texttt{A-GR-STOCK} and \texttt{A-GR-CHOICES} ran the
same Guard, reask loop, budget, prompt and model, and read 43.5\,\% (87/200)
against 0\,\% (0/200, with 88 responses sent back and repaired). The stock
configuration validates structure and has no faithfulness validator, because a
fresh install registers none, so nothing in it could reject \texttt{r2}. The
choice arm is our reimplementation of the toolkit's acceptable-values
semantics with its list built from $E$ at call time. It checks the
cited-column list and nothing else. On the reference task it matched
our validator (\texttt{A-GR-OURS}, where no violation reached the user and 84
responses were repaired). On the crowded instance it let three responses
through, one with a misfiled name in a claim's column field and two with
misquoted values, while our validator in the same loop let none through (118
repairs). The binding does the work on the field it covers, and Tier~B's
other checks cover the fields a choice list leaves open.

\texttt{A-STRICT-STATIC}, a schema with types and required fields and no
column enum, reads 4.0--7.0\,\% across runs against the floor's 42\,\%. A
schema therefore steers a model strongly even where it constrains nothing,
which rejects the registered hypothesis H8 (Table~\ref{tab:registered}). The evidence-bound enum without verification
left no violation on the reference task with or without the provider's strict
flag, so hypothesis H9 holds on the entity channel. Neither result amounts to a
guarantee. In the non-strict arms the enum ran as a request, and whether a
strict flag is honoured is up to the provider.

\paragraph{An author-time enum on new data}
On the reference task the author-time list is the evidence's own column set,
which makes the stale-enum arm the call-time arm under another name. The two
diverge on the crowded instance. There the list written against the reference
task covers none of the ten evidence columns, and the model obeys it. It cites
reference-task columns that do not exist in this frame in 145 of 200
responses (72.5\,\% [65.9, 78.2]). Every one of these is an invention, a
failure the undescribed field never produced. In addition, 132 responses omit
the anchor, which the list does not allow them to name, and 41 abstain. The
same instance reads 27.5\,\% (55/200) with no column enum and 0\,\% (0/200)
with the enum built at call time. On evidence the list predates, the
author-time list produces the failure it was supposed to prevent.

\subsection{Cost of verification}

Table~\ref{tab:retry} shows what an enforced arm's zero consists of. One named
retry repaired every violation the verifier met; only the content-free
correction of \texttt{A-STRESS-GENERIC} ever needed a second, twice in 200.
Nothing was stripped anywhere in the study, so the deletion that guarantees
(C1)--(C2) remained a worst case that never occurred. With nothing to repair,
the full contract adds about half a second over the unenforced arm (3.3
against 2.8\,s) and no calls. Arms whose responses need retries cost more on
average: 3.6\,s per response on \texttt{A-STRESS} and 4.5--4.9\,s on the
Guardrails arms. Removing the enum while keeping the loop and verifier raises
the number of retried responses from 0 to 12 on leakage and from 6 to 13 on
the profile task. The schema does not strengthen the guarantee; it reduces
retries on the channel it can express. Retry counts also vary between runs:
\texttt{A-STRESS} repaired 12, 23, 32 and 19 responses in four runs, and on
the same day a content-free correction (\texttt{A-STRESS-GENERIC}) needed 29
retried responses where the named one needed 19, with no violation reaching
the user in either. The cost therefore has to be reported per run, while the
guarantee does not depend on it. Some arms appear in neither table:
\texttt{A-L2-DESCRIBED} and \texttt{A-L2-DESCRIBED-NEUTRAL} read 0/200; the
shipped contract under the RQ4 wording that fails most often without
enforcement returned no violation on the reference task with the strict flag and on the
crowded instance; and on the crowded instance \texttt{A-STRESS},
\texttt{A-GR-CHOICES} and \texttt{A-GR-OURS} retried 25, 101 and 118 of 200
responses. We do not report token counts because the
contract path does not surface them.

\paragraph{Why Tier~B is still needed}
Two of the three channels cannot be expressed in a schema. A column domain can
be, which is why the enum arms tie the contract on leakage. A value's
admissible set, however, is a tolerance band around a float chosen by a sibling
field, and ``a committed verdict addresses the anchor'' is a property of the
whole response; neither can be written as an \texttt{enum}. Even on the
channel a schema reaches, nobody outside the provider can observe whether
Tier~A was honoured. Tier~B runs the same check in our own process, and 36
mutation tests and the property-based falsifier of
Section~\ref{sec:instruments} pin it down.

\subsection{Providers without failures}\label{sec:rq3-second}

On \texttt{gpt-5.4-mini} (same evidence, prompts, scorer and budget, and no
transport errors) all seven arms that existed at the time show no violation in
200, the floor included. That model cites exactly the ten evidence columns in
199 of 200 responses and never writes \texttt{r2} into a column field. A local
\texttt{qwen2.5:7b} ($N=20$) shows none except \texttt{A-STRICT-STATIC} at
10\,\% (2/20). Those providers offer nothing to compare, so the comparative
claims of this section rest on one model, and its rates describe
\texttt{deepseek-chat} on particular dates, not LLMs in general. An engineer
who benchmarked prompt-level reliability only on \texttt{gpt-5.4-mini} would
conclude, correctly for that model and date, that the problem does not exist.

\paragraph{Wording and specification}
Six rule-free variants of the bare instruction, over identical evidence and
schema, move the blended entity rate from 9.0\,\% to 72.0\,\%. It is already
established that wording moves behaviour this much~\cite{sclar2024formatspread}.
The variants also differ in how much of the answer they specify, and that
ordering predicts the unverifiable channel exactly. It reads 0 and 1 per
hundred where the instruction names the statistic, 8 and 10 where it mentions
correlations, 26 where it names the field without saying what goes in it, and
45 where it says nothing. On the entity channel, the baseline instruction's
``list every column from the evidence you cite'' produces pure misfiling, and
Section~\ref{sec:rq1} shows that describing the field removes it.

\paragraph{Out-of-evidence names}
Of the 20 names in 600 responses that $E$ does not carry, 18 are
\texttt{target}, a real column of the frame that $E$ omits. Only two are
genuine inventions, both from \emph{expert}, and misquotation of a carried
number occurs once. Across variants the out-of-evidence and misfiled counts
show no detectable association (Spearman $\rho=-0.25$, $p=0.63$), though with
six variants the test has almost no power. \emph{Terse} has the lowest blended
rate and the most out-of-evidence names, but 7 against \emph{mechanical}'s 1
is not significant ($p=0.065$).

\paragraph{Interpretation}
Measured compliance belongs to a configuration: the wording, what the schema
says about each field, the names in the data, the provider and the date. The
shipped prompt removes the failure entirely on this model (\texttt{A-L2}),
its first three rules alone leave 7.0\,\% (\texttt{A-L2-RULES}), and a field
description removes the misfiling (Section~\ref{sec:rq1}). The prompt and the
description are cheap and worth using. Neither carries a guarantee to the next
configuration, because its effect is known only where it
was measured. Two diagnostic arms show the same from inside the contract. The
evidence-bound enum alone, with no verification, left no violation in 200
(\texttt{A-TIER-A-ONLY}), and the full contract under the variant that fails
most often without enforcement produced no violation on any first attempt.
Tier~B is the part whose effect does not have to be measured again for each
configuration, because it runs in our process over the returned payload.

\section{RQ5: Does the Contract Transpose?}\label{sec:rq6}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

The second narrated artifact is a deterministic dataset profiler that ships
in the same tool. It reports per-column type, missing
counts and rates, descriptive statistics, cardinality and outlier counts, plus
a task-level class balance. We bind it through the contract layer of
Section~\ref{sec:generic}, with no branch that names either task. The shape
differs from leakage: the entity domain is every column of the frame (24
against 10), the statistic domain has 13 names against 1 and depends on the
column, and $E$ carries 196 measured quantities against 10. The evidence comes
from running the profiler on a frame with ordinary data-quality problems:
mixed types, missingness that rises across the categorical block, and injected
outliers. That frame named its columns \texttt{num\_feature\_$k$} and
\texttt{cat\_feature\_$k$}. We also ran the unverified arms on the same data
under distinct natural names (\texttt{age}, \texttt{region}, \ldots) that
share no suffix.

\paragraph{Wrong numbers and column naming}
On the suffixed frame the unconstrained arm put a wrong number in 9 of 200
responses (4.5\,\% [2.4, 8.3]). Eleven of its 12 wrong numbers are a real
measurement of the column that shares the suffix, such as
\texttt{cat\_feature\_07}'s missing rate reported for
\texttt{num\_feature\_07}, and one appears nowhere in $E$. Under distinct names
the same model, on the same data, puts a wrong number in none of 400
unverified responses. The failure the original frame measured came from names
our generator chose.

\paragraph{Correct quantities in inadmissible slots}
Every other value violation, on both frames, quotes a number $E$ really
carries, and quotes it correctly. Most are the class balance. The profiler
reports it at task level, the narrator attaches it to the target column as
\texttt{class\_balance}, and the contract admits only per-column statistics, so
the correct figure has no admissible slot. Counting these as an invented
quantity kind, on the belief that the profiler computes no class balance, was
fault 13 in Table~\ref{tab:corrections}. Under Definition~\ref{def:contract}
such a
claim is misfiled, a real item placed where it is not admissible, and the
verifier rejects it. A reader loses nothing from it, whereas a program that
consumes the claim slot receives a wrongly keyed value. Excluding it is a
design choice of ours, and a richer binding would admit it.

\paragraph{How the tiers separate}
Binding the enum removes misplaced claims almost entirely (26 to 4 under
natural names) and leaves wrong numbers in place (9 against 11 under suffixed
ones). An enum can refuse a pair outside the admissible statistics, but it
cannot constrain a number whose admissible set is a band around a value chosen
by a sibling field. Tier~B handles both. \texttt{P-CONTRACT} returned no
violation and sent back 6 responses, and \texttt{P-STRESS}, with the enum
removed, sent back 13. A re-run of \texttt{P-CONTRACT} that recorded every
attempt (200 responses, 8 catches) found no entity violation on any first
attempt. The enum therefore held on 399 of 400 first attempts there, and we
have no explanation for the one exception. It did not hold everywhere: without
the strict flag, 2 of 200 natural-name \texttt{P-TIER-A-ONLY} responses wrote
statistic names into the column field. The re-run also caught an interquartile-range outlier count claimed for
\texttt{cat\_feature\_03}: the column and the statistic are each admissible,
but $E$ does not carry the pair; a per-field enum cannot
express that relation, and (C2)'s domain check does.

\paragraph{Scope of the result}
The contract binds to a second evidence shape without task-specific
verification, and the two tiers separate once the failing channel is one a
schema cannot express. The result does not show that misfiling numbers is a
general property of narrators. On this model it followed our naming, and what
survived distinct names reflects our binding choices as much as model error.
Two tabular summaries from one tool are two members of the class, which is
not the same as covering it.

Three of the faults show patterns the others repeat. In faults 2, 12 and 13 a
scorer reported the narrator wrong for being right: it compared every claim
with its column's correlation whatever statistic the claim named, compared
\texttt{abs\_corr} with a signed value, and called a class balance invented
although the profiler reports one. We found fault 2 because two readers
disagreed about what a channel measured. Fault 9 is a control that silently
received the treatment. The profile floor ran the deletion step
unconditionally and read 0\,\% on a task that fails, and we noticed only
because the arm printed sixty Tier~B catches although it has no Tier~B. The
corrections also had a direction. The first four that moved the downstream
checklist all moved it toward our hypothesis, because false positives
concentrate in careful code and the treatment arms write more of it. The two
that broke the pattern came from procedures designed to look for it: a second
scorer written with a different technique, which agreed with the first on 856
of 858 rule instances before fault 6 was fixed and on all 858 afterwards, and
an arm whose adverse outcome we wrote down before it ran.

because the artifact is not an instrument. A claim value of NaN passed
the verifier, because every comparison with NaN is false. The property-based
falsifier that the analysis plan registered, which we built late, reproduces
that refutation at its third generated case on the earlier code. It then found a second defect: a 400-digit integer, which a
JSON parser returns as an exact integer, crashed the value check. Both are
fixed, and the fixed verifier passes $10^6$ generated cases. No recorded
response carries either value, so no reported number changes.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Discussion}\label{sec:discussion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\paragraph{Cheap fixes and their reach}
The misfiling of Section~\ref{sec:rq1} disappears with the shipped prompt
(0\,\%) or one sentence of field description (0.5\,\%), and the prompt's
rules alone leave 7.0\,\%. The shipped prompt also tells the model that
violations are rejected, which is true only when a verifier runs; we did not
measure how much of its effect that claim carries. The wrong numbers of
Section~\ref{sec:rq6} disappear under distinct column names, and the whole
failure disappears on another provider. Each one comes back where its fix is
absent: 61\,\% on a differently named instance, and 49\,\% on the same model
nine days later. A tool author controls the prompt and the schema. The names
in the user's data, the provider behind an endpoint and the date are outside
their control, and they cannot know that every field is specified well enough
for every model without measuring each combination. This is the argument for
Tier~B, and it concerns certification rather than rates. A prompt or a
description may work perfectly, but its effect is known only where it was
measured, whereas the verifier's effect follows from code that runs in our
process.

\paragraph{Binding at call time}
The crowded instance shows what binding at call time buys. An enum declared
while authoring against one dataset turned a 61\,\% misfiling rate into a
72.5\,\% invention rate on the next dataset and blocked the anchor in two
responses out of three. An enum built from $E$ at call time read zero on the
same instance. A stale
schema actively introduces errors, and nothing in a static schema tells its
author that the data has changed.

\paragraph{Simpler designs}
Two alternatives are worth naming. If every structured fact were rendered
deterministically and the model wrote only prose, the structured guarantee
would be trivial and the model would be left with the one channel no check
reaches. Stripping without retry is cheaper, but it would have deleted content
from 6--16\,\% of \texttt{A-STRESS} responses and 41.5--59\,\% of the
Guardrails arms' responses, all of which a single named retry repaired
(Table~\ref{tab:retry}).

\paragraph{A downstream benchmark this paper does not report}
A pre-registered benchmark asked whether handing a model the tool's
deterministic findings reduces six checklist defects in the training scripts
it writes (175 scored runs, four models, three datasets). The findings reduced
flagged defects from 31 to 8. An arm told only the names of the six scored
rules reached 1, but its scripts executed in 50\,\% of runs (17 of 34, with
two failed API calls excluded) against 78--83\,\% elsewhere, and held-out scores showed no consistent improvement. We
draw no claim from it. Its protocol, amendments, runs and both scorer
implementations are in the replication package.

\paragraph{Where the contract transposes}
The contract needs a deterministic producer, a finite set of observed entities
and values, and a runtime domain bound to that set with independent
verification. Narrators of static-analysis findings, CI failures or
dependency-scanner reports meet these conditions. There, too, the guarantee
would be consistency with the tool's output, and it would say nothing about
whether the tool is right.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Threats to Validity}\label{sec:threats}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\paragraph{Construct} The guaranteed property is referential and value
soundness on the structured channels. The verdict, the prose and the
correctness of $E$ lie outside it (Section~\ref{sec:contract}). The free text
could in principle absorb what enforcement removes from the structured fields.
Every run since the record normaliser was fixed (fault 8) keeps the narration:
5{,}998 narrations on \texttt{deepseek-chat} in 30 cells. We checked every
number in each against every quantity in $E$, and every identifier against
every name in $E$ and in the system prompt. On the reference task, arms that
can reject a claim carry ungrounded content in 9.2\,\% [7.9, 10.7] of
narrations and arms that cannot in 12.7\,\% [11.4, 14.1]. Within the
rejecting arms, responses that went through a retry read 10.9\,\% [7.7, 15.4]
against 8.9\,\% [7.5, 10.5] for the rest (Fisher $p=0.29$). On the crowded
instance the rejecting arms read 6.9\,\% [5.5, 8.6] and the others
5.5\,\% [4.1, 7.3], leaving aside the stale-enum arm, whose narrations repeat
the invented names of its structured fields (58.8\,\%); retried responses read
8.6\,\% against 6.3\,\% ($p=0.25$). Most of what remains is true bounds
(``below 0.05'') and shortened or pluralised real names
(\texttt{log\_target}, \texttt{candidate\_leak\_column}). A first pass over
these runs had three faults (fault 14) and put the shipped-prompt arms at
91 and 97.5\,\%. The retried responses lean the way displacement predicts, by two
points and within noise, so we observe no displacement at the scale this
instrument can see.
The instrument has one blind spot: a misfiled name is in $E$ and so counts as
grounded in prose, so misfiling displaced into the narration would not
register. No enforced arm stripped anything, which means the pressure we
tested is correction and not deletion, and unsupported causal prose would need
human raters.

\paragraph{Internal} We compare arms within one date. The provider serves a
rolling model name, and the unconstrained rates move between runs:
\texttt{A-GR-STOCK} read 35.0, 43.5 and 47.5\,\% over nine days
(heterogeneity $p=0.035$), and \texttt{A-STRESS} repaired 12, 23, 32 and 19
responses in four runs ($p=0.012$), with 32 against 19 on the same date
($p=0.07$), so the date does not account for all of the variation. The harness and adapter also
changed between runs, and the provenance of every record pins both, so a
difference across dates cannot be attributed to the provider alone.
\texttt{A-L1} did not move ($p=0.34$).

\paragraph{External} The failure occurs on one of three providers, so every
comparative claim rests on a single provider, and every rate is conditioned on
\texttt{deepseek-chat}, $T=1.0$ and the date. Both leakage instances are
synthetic, and the profile frame is synthetic data under two naming schemes.
We did not measure the shipped default narrator model. We did measure schema
cost: from 10 to 1{,}000 columns the enum costs 38 bytes per column, against
344 for the evidence that produced it. We did not measure provider limits on
enum size, and because the corrective retry inlines the whole list, its cost
grows with the width of the domain.

\paragraph{Conclusion validity} At $N=200$ a comparison against a zero arm
reaches $p<0.05$ at six events, so the design resolves differences of about 4
percentage points (power 0.8) and cannot separate mechanisms that are closer
than that. Only the registered family is corrected for multiplicity
(Table~\ref{tab:registered}); every other interval is descriptive.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Conclusion}\label{sec:conclusion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

For narration whose citable entities and checkable quantities are finite and
enumerable at call time, referential and value soundness on the structured
channels can be enforced in host code behind an API that exposes no logits.
The method is to bind each field's admissible set to the evidence and check the
returned payload. The mechanism is ordinary validate-and-reask; this study
measures what it is up against and what it costs. On the one model that fails,
the failure under the bare instruction is the evidence's own vocabulary
misfiled into an under-specified field, and no column is invented. The
shipped prompt, a field description, distinct names or another provider each
remove it, the prompt's rules alone leave 7\,\%, and it returns wherever the
fix is absent. The verifier held in every configuration in which it ran,
repaired every violation it met with one named retry, and added about half a
second when nothing needed repair. We report fourteen faults in our own instruments and two defects in
the verifier, found by readers and by a falsifier we had registered but not
built, together with what each moved. The main gap between what this paper
guarantees and what a user of the tool receives is that the check does not yet
extend across the tool-server boundary to a client model that reads the same
evidence.
