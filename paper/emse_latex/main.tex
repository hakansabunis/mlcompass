\begin{abstract}
Software tools increasingly let a large language model (LLM) explain the
output of a deterministic analysis to an engineer. An explanation naming a
column or number the analysis never produced can mislead the engineer.
Existing defenses constrain decoding, which needs token probabilities that
commercial APIs withhold, or check answers against rules fixed in advance; evaluations usually treat every unsupported item as one kind of error.
We bind, for each field of the narrator's structured answer, the evidence items the field may contain, check every answer in host code, and return
violations with the problem named. The mechanism is ordinary
validate-and-reask, used here mainly to measure how narrators fail. We study
the narrator of \textbf{mlcompass}, an open-source machine-learning assistant,
on three models, sixteen leakage-analysis tasks, and a dataset-profiling task.
The one model that fails often under a bare instruction rarely invents. Instead, the
model misfiles, placing an item the evidence contains, most often the
investigated metric's name, in a field that does not admit the item. A
one-sentence field description, the shipped prompt, a lower temperature, or
another model removes most misfiling; an allowed-column list written in
advance turns misfiling into invention when the data change. The check held in
every configuration and costs microseconds; its benefit in an already well-specified configuration remains open. Our contributions are an
empirical account of misfiling as distinct from invention, a field-indexed
definition of admissibility that makes the distinction measurable and
enforceable, a comparison of common alternatives, and a replication package.
\keywords{Large language models \and faithfulness \and runtime verification \and structured output \and constrained generation \and data leakage}
\end{abstract}

\section{Introduction}\label{sec:intro}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Machine-learning practice relies on single-purpose tools:
profilers \citep{ydata}, experiment trackers such as MLflow and
TensorBoard \citep{mlflow,tensorflow}, and automated model
search \citep{autosklearn}. These tools report numbers, but none of them tells
the engineer what the numbers \emph{mean}. A common remedy is agentic: a large
language model (LLM) calls the tools, reads their structured output, and
explains the results \citep{react,toolformer,mcp}. LLMs, however, produce
content that their input does not support \citep{ji,huang}, and assistants
built on LLMs still fail real software tasks \citep{codex,swebench}.

A concrete case shows what is at stake. Suppose that an engineer's regression
model scores $R^2=1.0$ on held-out data. \textbf{mlcompass}, the open-source
assistant for machine-learning pipelines that this paper studies, treats a
score that high as a sign of data leakage. The tool raises the alarm, for
example, when $R^2>0.999$, when the area under the receiver operating
characteristic curve (AUC) exceeds 0.995, or when accuracy exceeds 0.99 on at
least 50 rows. We chose these thresholds ourselves, motivated by the leakage
problem that \citet{leakage} describe. A deterministic
detector then measures how strongly each feature correlates with the target
and ranks the columns that may be carrying the target into the features. The
detector's output is the \emph{evidence}, a dictionary that we write as $E$.
An LLM, the \emph{narrator}, explains $E$ to the engineer by filling in a
structured answer: a verdict chosen from four labels (leakage likely, leakage
uncertain, score legitimate, cannot determine), a list of cited columns, and
claims of the form (column, statistic, value). On the reference task of this
study (Section~\ref{sec:design}), a sound answer cites the leak column
\texttt{log\_target\_v2} with its measured correlation of 0.999.

A structured claim about $E$ can be wrong in two ways. The claim can name an
entity or quote a number that appears nowhere in $E$. The literature calls
such an error \emph{extrinsic} \citep{ji,maynez2020faithfulness}, and we call
the error \emph{invention}. Alternatively, the claim can place an item that $E$
really contains where $E$ does not admit that item, such as the metric's name
\texttt{r2} in the list of cited columns, or one column's measurement under
another column. This is an \emph{intrinsic} error, which we call
\emph{misfiling}. The two kinds of error call for different remedies.
Invention calls for grounding the narrator in the evidence, whereas misfiling
calls for telling the narrator which field admits what. A single hallucination
rate that counts both kinds together can therefore point a tool author to the
wrong remedy.

Existing defenses act at three points (Table~\ref{tab:taxonomy}). Constrained
decoding restricts the tokens that a model may
emit \citep{outlines,lmql,gcd,guidance,scholak2021picard}, but this approach
needs the token distribution, which commercial APIs withhold. A provider-side
schema \citep{structured} constrains the structure of each answer, and the
caller can check every returned payload against the schema. How the provider
produced a conforming payload, and whether the provider will do so for the
next request, cannot be observed from outside. Validate-and-reask toolkits,
such as Instructor \citep{liu2023instructor} and Guardrails
AI \citep{guardrailsai}, check the returned answer in the caller's code and ask
again when a check fails. These toolkits supply the loop, but what each field
of the answer may contain is left to the tool author, and a stock installation
checks structure only (Section~\ref{sec:rq3}).

For the narration of a deterministic tool's output, however, what each field
may contain is known when the narrator is called.

\begin{definition}[Evidence-closed narration]\label{def:closed}
A narration task is \emph{evidence-closed} if the set of citable entities and
verifiable quantities is finite and machine-enumerable at the moment of the
narration call.
\end{definition}

For an evidence-closed task, checking the structured claims against the
evidence takes one membership test per field and one numeric comparison per
claim, so the soundness of those claims can be enforced rather than merely
measured. We build an \textbf{evidence-bound runtime contract} on this
observation. The narrator answers by calling a tool whose input is described by
a JSON Schema, in which an \texttt{enum} lists the only values that a field
may take. \emph{Tier~A} builds these lists from $E$ at call time, so that the
column field admits exactly the columns in $E$. An enum, however, is a request
to the model and not a check. \emph{Tier~B} therefore re-checks the returned
payload in plain code for entity soundness, for value soundness of (column,
statistic, value) claims, and for coverage of the top-ranked candidate. Tier~B
answers a violation with a corrective retry that names the problem. Content
that still violates the contract after the retries is stripped, and a
persistent omission is flagged. The mechanism is ordinary validate-and-reask,
and we do not claim the mechanism as new. What this paper adds is a
field-indexed definition of admissibility, which separates misfiling from
invention, and the use of the contract as an instrument for measuring how
narrators fail. The contract is the default narration path of mlcompass (MIT
license), where the contract guards the leakage investigation described above.
We describe the contract as shipped rather than as in production, because we
have no deployment telemetry. We keep to this narrow scope throughout: a
free-text sentence can name only real columns and quote only real values and
still assert a causal story that $E$ does not support, and $E$ itself can be
wrong.

We ask five research questions (RQs). \textbf{RQ1}: How does an unconstrained
narrator of evidence-closed material fail, and which changes to the narrator's
configuration remove the failure? \textbf{RQ2}: Does the contract prevent
violations on the channels that the contract checks, and at what cost?
\textbf{RQ3}: How do the alternatives that a practitioner would reach for
compare, namely a stock guardrail toolkit, a provider schema, an allowed-value
list written in advance, and a prompt that states the rules? \textbf{RQ4}: How
far do the wording and the specificity of the instruction move compliance?
\textbf{RQ5}: Do the contract and the failure carry over to a second kind of
evidence?

We answer these questions with 19{,}132 recorded responses from three models,
on sixteen leakage instances drawn from eight sources and on a
dataset-profiling task. Without enforcement, \texttt{deepseek-chat} fails often and the other two
models rarely, and on \texttt{deepseek-chat} the failure is almost always
misfiling. Under the bare
instruction, 1{,}807 of the 1{,}829 flagged responses misfile, and 13 use a
name that neither $E$ nor the data contains. A one-sentence description of the
cited-column field, or the prompt that mlcompass ships, removes nearly all
misfiling; temperature 0 removes most of the misfiling; and the failure
returns wherever the fix is absent. An allowed-column list written in advance
turns misfiling into invention on data that the list predates. Under the
contract, no violation of the checked channels reached the user in any
configuration, one named retry repaired every violation, and the check takes
microseconds per response.

The paper makes four contributions.
\begin{enumerate}
\item An empirical account of how an unconstrained narrator of structured
evidence fails. On the one model of three that fails often, the failure is misfiling into an under-specified field rather than invention. We report
contract violations separately from what the violations introduce
(Section~\ref{sec:rq1}).
\item A field-indexed definition of admissibility for evidence-closed narration
(Definitions~\ref{def:closed} and~\ref{def:contract}). The definition
separates misfiling from invention, makes the distinction measurable, and lets
a generic membership check enforce soundness.
\item A comparison, inside one guardrail toolkit and one provider, of the
alternatives that a practitioner would reach for, by what each alternative
checks. An allowed-column list written in advance does worse than no list on
data that the list predates. The toolkit's choice semantics, bound to the
evidence, match our validator on the field that they check and miss what they
do not check.
\item A replication package \citep{replication} with one record per live
response, the frozen analysis plan with its amendments and deviations, the
registered falsifier, and sixteen faults in our own instruments, with what each
fault changed.
\end{enumerate}

One question remains open and is not among the contributions: whether a
verifier adds a measurable benefit to a configuration that is already well
specified. Exploratory runs observed no difference on leakage (0 against 0
violating responses in 200 on each of four instances) and a small,
statistically uncertain difference on profiling. The registered test of the
question stopped when the provider budget ran out (Section~\ref{sec:rq3}).
The diagnosis itself rests on one failing model, sixteen leakage instances, and
one profiling frame.

\section{Background and Related Work}\label{sec:related}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Closed-world faithfulness and its measurement}

Definition~\ref{def:closed} is a closed-world assumption \citep{reiter1978closed}
over $E$: whatever the evidence does not carry is not admissible under the
contract. The setting is old. Data-to-text and
meaning-representation-to-text generation narrate a finite record and measure
faithfulness against that record offline, using the slot error rate over the
input's slots \citep{dusek2020e2e}, relation-generation precision against the
source table \citep{wiseman2017challenges}, or table-grounded
scoring \citep{dhingra2019parent}. In the taxonomy of \citet{ji} and of \citet{maynez2020faithfulness}, a
name absent from $E$ is an \emph{extrinsic} error, and a real evidence item
asserted in the wrong place is an \emph{intrinsic} one. We use
\emph{invented} and \emph{misfiled} for these two classes on a structured
channel and claim neither category as new. \citet{xu2025openworld} argues
that hallucination is unavoidable in an open world but can be mitigated in a
closed one. \citet{luo2026removal} repair a model's own
explanations by removal, and AVA \citep{karnatak2026ava} verifies citations
against a curated report corpus and abstains when the corpus cannot support an
answer. For an evidence-closed tool narrator, what changes is where the check
runs: at call time, on the payload that the user will see, rather than offline
on a corpus.

Tool-use frameworks \citep{react,toolformer,mcp} govern how an agent acts, but
they say nothing about what the agent may afterwards claim about a tool's
output. Provenance work reconstructs evidence support from traces after the
fact \citep{wang2026agenttraces}, and \citet{ng2026runtimecontract} argue that agent safety belongs in a runtime
contract. Static leakage detectors for notebook code address the leakage
problem itself before training \citep{yang2022leakage,truong2025leakagedetector};
our narrator explains a detector's findings after training. The enforcement
mechanism is classical. Tier~B is a postcondition in the sense of Design by
Contract \citep{meyer1992dbc}, and deleting what violates the postcondition is
\emph{suppression}, the weakest edit that an edit automaton can
make \citep{ligatti2005edit}. \citet{schneider2000enforceable} and
\citet{falcone2012verify} characterize which properties a
monitor can enforce at all.

Decode-time methods can also bind constraints to the input. Grammar-constrained
decoding admits input-dependent grammars \citep{gcd}. PICARD, a constrained
decoder for text-to-SQL, and Synchromesh, its counterpart for code
generation, check partial programs against a database schema or a program's
scope \citep{scholak2021picard,poesia2022synchromesh}. Monitor-guided decoding
consults a static analysis of the repository \citep{agrawal2023mgd}, and
CHyD \citep{signe2026chyd}, a decoder for retrieval-augmented generation,
restricts the output to spans of the retrieved context. All of these methods
need the token distribution, which a commercial endpoint withholds.
ATLAS-RTC \citep{cruz2026atlasrtc}, a token-level runtime controller for agent
output, intervenes during decoding with masking and rollback and reports
empirical gains without a guarantee. \citet{le2026schemakey} shows that the
wording of schema keys moves accuracy in both directions, and
JSONSchemaBench \citep{geng2025jsonschemabench}, which measures
constrained-decoding frameworks on 10{,}000 real-world schemas, finds that the
frameworks differ in which schema features they cover. What a schema enforces
therefore depends on the engine that applies the schema, which is a reason to
distrust a schema whose effect has not been checked. A valid schema does not
make an answer right either: on OrderBench \citep{li2026orderbench}, the
strongest of four ordering agents produces schema-valid output every time and
still gets about one order in five wrong.

Other tools already occupy this paper's row of Table~\ref{tab:taxonomy}.
Instructor \citep{liu2023instructor}, a Python library for structured LLM
output, validates a response against context supplied at call time and re-asks
on failure. Guardrails AI \citep{guardrailsai}, an open-source validation
framework, and NVIDIA's NeMo Guardrails \citep{nemo} ship validate-and-reask
loops whose validators can read call-time metadata. Our mechanism is one
instance of that practice, and we add three things to the practice. The first
is the field-indexed admissible domain, derived from a deterministic
producer's output, which separates misfiling from invention and which a
generic membership check can enforce. The second is a set of measurements:
which failure actually occurs, what enforcement costs, and which alternatives
reach the same result. The third is a shipped artifact whose narration path is
the one that we measured.

Three pieces of work are closest. \citet{ahn2026harness} vary the
enforcement layer with the model fixed and find what we find: prompts let
violations through, a bolt-on guardrail over-refuses (88/120 utility against
120/120), and code-owned enforcement keeps both safety and utility, over 270
runs on three hosted models. Their contract is a policy fixed when the harness
is written, whereas ours has no admissible domain until the evidence exists.
The same difference separates our contract from RvLLM \citep{zhang2025rvllm},
which checks outputs at runtime against constraints that domain experts write
in a specification language. The difference also separates our contract from
the work of \citet{winston2026solver}, who translate
natural-language policies into satisfiability-modulo-theories (SMT)
constraints and check each tool call before the call runs. LedgerMind \citep{du2026ledgermind} lets claims cite only
active ledger entries, checks entity and numeric grounding, and restricts
repair to transitions that add no unprovenanced content. LedgerMind thus
covers three of our channels and our repair asymmetry
(Observation~\ref{prop:asym}), which we derived independently. LedgerMind's
ledger grows during a trajectory, whereas ours is complete before the call.
EviBound \citep{chen2025evibound}, which appeared eleven months before our
measurements, gates a machine-learning research agent by querying MLflow for a
run, its artifacts, and a terminal status, with bounded retries, and checks
metric values when its acceptance criteria name them. EviBound verifies that
what an agent claims to have done and achieved meets criteria written for the
task. We instead derive, from a fixed tool output, which entity and which
quantity each field of a narration may hold, and we measure how narrators fail
that binding. Under that binding, the narrator may report
\texttt{log\_target\_v2}'s correlation as 0.999, but may not list \texttt{r2}
as a column or quote a correlation that $E$ does not contain.

\section{Evidence-Closed Narration}\label{sec:theory}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{The evidence, and why admissibility is per field}

In the leakage investigation, the evidence dictionary $E$ holds four things:
the suspicious metric and its value; the correlation of each feature with the
target $y$, taking whichever of $\rho_P$ and $\rho_S$ has the larger magnitude
and keeping its sign; a ranked candidate-leak set
$C=\{c:\max(|\rho_P(c,y)|,|\rho_S(c,y)|)\ge 0.99\}$; and the perfect-match
rate $P(\hat y=y)$. We report Spearman's coefficient because a monotone
transform of the target pulls $\rho_P$ down while $\rho_S$ stays at 1. Our
log-target leak has $\rho_P=0.93$ and $\rho_S=0.999$, so a filter that used
Pearson's coefficient alone would miss the leak.

Let $N_E$ be every name that $E$ carries: its keys and its string values. The
obvious formalization admits any member of $N_E$ in any reference field. Under
that formalization, a column field reading \texttt{r2} counts as sound,
because \texttt{r2} is in $E$ as the name of the \emph{metric}. We therefore
index admissibility by field.

\subsection{The contract, stated as an invariant}

Let $F$ be the answer's entity fields: the list of cited columns and the
column of each claim (\texttt{columns\_referenced} and
\texttt{claims[].column} in the schema). Their entries, the \emph{leaves}, are
names compared as strings. $E$ determines the admissible column set
$A_{E,\mathrm{col}}$ and a value table $V_E$ keyed by (column, statistic). The
statistic names that $V_E$ uses form $A_{E,\mathrm{stat}}$, which Tier~A also
binds into the schema's statistic field, so
$\mathrm{dom}(V_E)\subseteq A_{E,\mathrm{col}}\times A_{E,\mathrm{stat}}$. A
statistic outside $A_{E,\mathrm{stat}}$ is therefore a pair that $E$ does not
carry, which condition (C2) below rejects. Column and statistic sets may share
a name, as when a frame has a column called \texttt{mean}; each name is
checked in its own field.

A leaf outside $A_{E,\mathrm{col}}$ is \emph{misfiled} when the leaf lies in
$N_E$. Otherwise, the leaf is outside the evidence, and for measurement we
split that case by the data. A real column of the frame that $E$ does not list
is \emph{unlisted}, and a name that exists in neither $E$ nor the frame is
\emph{invented}. The verifier sees only $E$ and treats all three cases alike.
A response \emph{commits} when its verdict is not empty and is not the
abstention ``cannot determine''. The entities that a response
\emph{references} are its leaves in the column fields.

\begin{definition}[Evidence-bound runtime contract]\label{def:contract}
A structured response $r$ \emph{satisfies} $\mathcal{C}_E$, with tolerance
$\tau$ and anchor $a^*$, if \textbf{(C1, entity soundness)} every leaf of
$r$ in a field of $F$ lies in $A_{E,\mathrm{col}}$; \textbf{(C2, value
soundness)} every claim $(e,s,v)$ in $r$ with $e \in A_{E,\mathrm{col}}$ has
$(e,s) \in \mathrm{dom}(V_E)$, $v$ a finite number, and
$|v - V_E(e,s)| \le \tau$; and \textbf{(C3, anchor coverage)} if $r$
commits, the anchor $a^*$, the top-ranked candidate, is among the entities
$r$ references.
\end{definition}

Conditions (C1) and (C2) together state \emph{referential and value soundness
with respect to $E$} on the structured channels. This property is narrower
than faithfulness in general: the verdict, the free-text narration, and the
suggested checks lie outside the property, and $E$ itself is trusted. Tier~B
enforces (C1) and (C2). A response that violates either condition is sent
back, at most twice, with the violation named, and whatever still violates the
contract after that is deleted. A response with no admissible verdict is
retried in the same way and, if the problem persists, aborted rather than
completed on the narrator's behalf. Hence \emph{no structured claim that
Tier~B returns violates (C1) or (C2)}; this follows from the deletion step
(Observation~\ref{prop:asym}).

Whether our Python implementation realizes this algorithm is a separate,
empirical question. Thirty-six hand-written mutation tests and a
property-based search over $10^6$ generated (evidence, response) pairs support
the implementation without proving the implementation correct. The search was
registered in the analysis plan before the study but built after the study,
and the search found two defects in an earlier version
(Section~\ref{sec:instruments}). The search draws evidence with 1 to 12
columns and 1 to 5 statistics. The responses that the search generates use
names that are admissible, taken from another field, or random, and values
that sit inside or just outside $\tau$ or are non-finite, non-numeric,
missing, or a 400-digit integer. Each mutation test disables one check; one of
these tests covers a case in which stripping creates an omission. Ten
fault-injection tests then drive the shipped path end to end with a narrator
that repeats one fault on every attempt: an inadmissible cited or claimed
column; a wrong, non-finite, or 400-digit number; an omission; an
inadmissible verdict; or a missing tool call. The tests check the delivered
payload, its flags, and the text that the panel prints, and six of them fail
when the deletion step is disabled. Stripping, the omission flag, the abort,
and the post-strip re-check are therefore exercised on the delivery path,
although no live response reached them. Deletion removes whole claims, so a
delivered claim never lacks a field.

Because the (C1)--(C2) guarantee does not come from sampling, we report an
enforced arm's clean result on those conditions as what the verifier did, and
we attach no interval to that result. The (C3) result is an observation like
any other. Condition (C3) cannot be enforced in the same way, so the contract
reports (C3) but does not guarantee the condition: a committed response that still omits
the anchor after the retries reaches the user with the omission flagged. When
$E$ has no candidate, there is no anchor, and (C3) holds vacuously.

\begin{observation}[Repair asymmetry]\label{prop:asym}
Soundness is safe-repairable by deletion: the projection $\Pi_E(r)$ removing
every violating element is sound, idempotent, and the identity on sound
responses. Anchor coverage is not: any repair must add a reference the model
did not produce.
\end{observation}

\begin{proofsketch}
Deletion preserves membership and tolerance and can remove every violating
element. For anchor coverage, deleting the verdict would discharge the
obligation, but the schema requires a verdict, and substituting ``cannot
determine'' would attribute to the narrator a stance that the narrator did not
take. Both premises are stipulations of this contract, and the artifact honors
them by aborting rather than substituting. Given these premises, every
remaining repair inserts an anchor reference that is absent from $r$.
\end{proofsketch}

Tier~B therefore strips unsound content and only \emph{flags} a persistent
omission, which in edit-automaton terms is suppression without
insertion \citep{ligatti2005edit}. In the security setting, insertion is simply
a stronger primitive; applied to a narrator, an inserted reference would
fabricate attribution. With each $A_{E,f}$ and $V_E$ hashed once, checking a
response costs $O(|r|)$. The step that needed care was keying $V_E$ on the
pair, which our own scorer once failed to do (Section~\ref{sec:instruments}).

\label{fig:contract}
\end{figure}

\subsection{Architecture and the trust boundary}

Figure~\ref{fig:contract} splits the system at a trust boundary. One side holds
everything deterministic: the pure-Python evidence producer, $E$, the Tier~B
verifier, and the user-facing output. The other side holds the LLM narrator,
which we treat as untrusted whoever serves the model. The system has three
\emph{layers}: evidence production; a narrator told the rules in words
(Section~\ref{sec:rq3} measures what that is worth); and the evidence-bound
schema, through whose submission tool the answers arrive. The contract spans
the last two layers as two enforcement \emph{tiers}. Tier~A restricts the
cited-column list and each claim's column to enums built from $E$ at call
time, and an enum remains a request to the model. On \texttt{deepseek-chat},
every Tier~A arm in the main battery ran without the provider's strict
decoding flag, and we report the one arm that ran with the flag separately.
Tier~B re-checks the returned tool input in plain code for (C1), for (C2)
within $\tau=0.005$, and for (C3).

\begin{algorithm}[t]
\caption{Evidence-bound narration (budget $k=2$)}\label{alg:contract}
\footnotesize
\begin{algorithmic}[1]
\State $B \gets \mathrm{bind}(E)$ \Comment{$A_{E,f}$, $V_E$, $\tau$, $a^*$}
\State $S \gets$ schema with enums from $B$ \Comment{Tier~A}
\State $c \gets$ empty correction
\For{$i = 0,\dots,k$}
  \State $r \gets \mathrm{model}(\text{prompt} + c, S)$ \Comment{provider errors propagate}
  \If{$r$ has no admissible verdict}
    \State $c \gets$ fixed correction; \textbf{continue}
  \EndIf
  \State $\mathit{viol} \gets \mathrm{verify}(r, B)$ \Comment{(C1), (C2), (C3)}
  \If{$\mathit{viol} = \emptyset$} \textbf{break} \EndIf
  \State $c \gets$ correction naming $\mathit{viol}$
\EndFor
\If{$r$ has no admissible verdict} \Return abort \Comment{evidence panel only}
\EndIf
\State $r \gets \mathrm{strip}(r, B)$ \Comment{delete leaves violating (C1), (C2)}
\State $\mathit{flag} \gets r$ commits $\wedge\, a^* \neq \bot \wedge a^* \notin \mathrm{refs}(r)$
\State \Return $(r, \mathit{flag})$ \Comment{(C3) flagged, never repaired}
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:contract} gives the control flow. Anchor coverage is
checked after stripping, because deleting an unsound claim can orphan the
anchor. A response with no admissible verdict (no tool call, unparsable
arguments, or a verdict outside the enum) is aborted after the budget, and no
verdict, claim, or prose is shown. The deterministic evidence panel is printed
in every case and lists the candidate leak columns with the anchor first, so
neither an abort nor a flagged omission hides the anchor. The abort path is
recent: the earlier code passed such a response as an empty answer. In the
records, such responses occur only on arms without a verifier (5 on
\texttt{deepseek-chat} and 8 on \texttt{qwen2.5:7b}), so no reported number
depends on the change.

\subsection{One contract, two instances}\label{sec:generic}

For most of this study, the code handled a single instance: one column set,
each claim's statistic fixed to correlation, and each claim checked by looking
up its column in the correlation map. The contract is now a layer. A
specification says how to read one evidence shape; binding yields the
field-indexed domains, the value table, and the anchor; and the verifier, the
stripper, the retry text, and the schema builder name no task. Leakage is one
specification of about forty lines. A dataset profiler is a second: every
column of the frame is admissible, each column has up to thirteen statistics,
and the statistic set is computed per call, because a categorical column
carries a cardinality and no mean. Each specification also names its anchor:
the top-ranked candidate for leakage, and the column with the most missing
data for the profile. The profile narrator runs in the measurement harness,
and the leakage narrator is the one that the product ships.

Extracting the layer exposed something that the single task could not: the
value table must be keyed on $(\text{entity}, \text{statistic})$. With one
statistic per column, keying on the column and keying on the pair coincide. In a profile, however, the
column \texttt{age} has mean 38.5 and missing fraction 0.012, and a table
keyed on the column alone checks a claim about one of these quantities against
the other. That error is one of the scorer defects in
Section~\ref{sec:instruments}, reappearing in the production path. The
evidence's surface shape also has to match the flat claim slot: narrators
handed a nested quantity invented a flattening, five different ones in all.

\subsection{What the invariant does not cover, and a threat model}

Four things fall outside the invariant. The first is the verdict and the
prose. The verdict is checked for admissibility but not for agreement with
$E$, so a narrator may cite the planted leak and still answer ``score
legitimate''. None did. Of the 16{,}698 leakage responses, 9{,}162 carry one
of the four labels; the other 7{,}536 come from open-schema arms, whose verdict
is free text (7{,}523) or empty (13). Of the 8{,}363 labeled responses on
instances with a leak, planted or real, 8{,}263 say ``leakage likely'', 54 say
``leakage uncertain'', and 46 abstain. On the negative control, none of the
799 responses says ``leakage likely'': 381 abstain, as the shipped prompt asks
when there is no candidate, 238 say ``uncertain'', and 180 say ``score
legitimate''. These counts are observations, not a property of the contract.
The free-text narration and the suggested checks are printed beneath the
validated content and marked unverified; Section~\ref{sec:threats} measures
what they carry.

The second is the correctness of $E$. If the leakage detector mis-ranks a
candidate, the contract faithfully narrates a wrong finding. The producer is
trusted and not verified, and (C3) names one anchor rather than every
finding. A response that addresses the second of two nearly tied candidates
would be flagged; no instance that we ran has such a tie.

The third is the other narration surfaces. The product prints two other
narrations of the same evidence that no contract governs: an optional LLM
interpretation panel printed by the evaluation command, and a tool-server
command whose calling model narrates in the user's editor \citep{mcp}. The
interpretation panel is marked unverified. The tool-server narration carries
no mlcompass marker at all, because the client model writes that narration.
mlcompass guarantees the contract panel and nothing else.

The fourth is adversarial evidence. Column names come from the user's data and
reach the schema's enums, the prompt, the corrective retry, and the rendered
panel, and membership in $E$ does not make a string safe. A crafted header is
a prompt-injection vector \citep{greshake2023injection}. Schema keys and enums
are part of the model's instructions \citep{le2026schemakey}, and through
Tier~A's enum values a header reaches the channel that the EnumAttack of \citet{zhang2025cda} uses to carry a harmful request past a
model's safety training. The contract guarantees only that what is shown is in
$E$, and rendered strings are escaped. Capping name length, restricting names
to an identifier-like character set, and quoting names as data would each
reject or alter some legitimate headers; we have neither implemented nor
measured these defenses.

\subsection{Subjects}

The subject is the shipped leakage-investigation path. The \emph{reference}
task is a 1,000-row frame of fourteen columns: the target \texttt{y\_true},
the prediction, and twelve candidate features. The target is
$y\sim\mathcal{N}(50,10^2)$. The frame carries a monotone transformed leak,
$\texttt{log\_target\_v2}=\log(y-\min y+1)+\varepsilon$ with
$\varepsilon\sim\mathcal{N}(0,0.01^2)$, which is the kind of column left behind
when a log-transformed copy of the target stays among the features, and a
high-correlation distractor. The evidence lists ten columns and has the
anchor \texttt{log\_target\_v2}. A second, \emph{crowded} instance has 1,200
rows, an anchor \texttt{sensor\_ref} that correlates at 0.995 with the target,
and nine near-tied distractors, \texttt{sensor\_00} to \texttt{sensor\_08}, at
0.900--0.924. A column list written against the reference task covers none of
the crowded instance's ten evidence columns.

Two further instances use real data, each narrated after an ordinary
least-squares fit on all numeric features. \emph{Bodyfat}, with 252
men \citep{penrose1985bodyfat}, has a documented leak: body fat is computed from
body density by Siri's equation, so the fit reaches $R^2=0.978$, and the
detector names \texttt{Density} ($|\rho|=0.993$) as the only candidate.
\emph{Sambanis} is the civil-war onset data of Hegre and Sambanis as
distributed by \citet{muchlinski2016civilwar} (7{,}140
country-years). The fit reaches $R^2=0.204$, and no column is a candidate, so
this instance is a negative control with no anchor. Neither score reaches the
product's trigger ($R^2>0.999$), so on both datasets we call the narrator
directly. The prompts, schemas, and contract were written against the
reference task; the crowded instance and the two datasets played no part in
their design.

Twelve more instances were frozen in the plan on 2026-07-07, before any live
run, and were first run for this revision. Each instance plants one of six
registered target-derived leaks (monotone transform, noisy proxy, exact copy,
inverse, binned copy, duplicated rows) in one of four public tables, so that
each leak appears in two tables. The tables are insurance
charges \citep{lantz2013mlr} (simulated from census figures), Cleveland heart
disease \citep{janosi1988heart}, IBM telco churn \citep{ibm2019telco}, and Ames
housing \citep{decock2011ames}. In every arm, the shipped leakage detector
produces $E$. Section~\ref{sec:rq6} describes the profile task of RQ5.

\subsection{Arms}

An \emph{arm} is one experimental condition: a fixed system prompt, tool
schema, and check on the returned answer. Table~\ref{tab:armsdef} lists the
arms. Their names follow the analysis plan and the replication package, so
every number can be traced to its records. The \emph{bare} prompt states the
task and no faithfulness rule. The \emph{shipped} prompt, the one that
mlcompass uses, states seven rules (among them: cite only items in $E$, copy
numbers exactly, and address the top candidate) and a verdict mapping. The
shipped prompt also tells the model that the schema restricts the column field
and that violations are rejected; on the arms without enforcement, neither
statement is true. An \emph{open} schema has the answer's fields and lists no
admissible values.

Several arms isolate one mechanism. \texttt{A-CONTRACT} runs the shipped
enforcement under the bare prompt, so that the mechanism is not confounded
with the instruction. \texttt{A-STRESS} removes the Tier~A enums, so that
every Tier~B catch is observable. \texttt{A-GR-CHOICES} is our
reimplementation of the toolkit's acceptable-values validator, with its list
built from $E$ at call time, because a fresh install of Guardrails~AI~0.11
registers no validator. \texttt{A-GR-CHOICES} is therefore not the library's
own implementation, and we did not test the arm against the validator that the
Guardrails Hub offers. Every arm with a retry loop has a budget of 2. Tier~B
and \texttt{A-GR-OURS} check (C1) and (C2) and flag (C3);
\texttt{A-GR-CHOICES} checks (C1) on the cited list only; and
\texttt{A-GR-STOCK} checks structure only. The comparisons therefore measure
what each configuration checks, not what each library can be made to check.
\texttt{A-GR-STOCK} and \texttt{A-STATIC-ENUM-STALE} are controls rather than
competitors of equal strength. They are what a practitioner gets by default:
a toolkit's stock validators, which check structure, and a column list written
once while authoring. The competitor of equal strength is \texttt{A-GR-OURS},
which runs the same checks as Tier~B inside the toolkit's loop.

\paragraph{Sample size and dates}
Each arm on \texttt{deepseek-chat} and \texttt{gpt-5.4-mini} has $N=200$,
fixed in the analysis plan. The local \texttt{qwen2.5:7b} arms have $N=20$,
and the RQ4 variants have $N=100$. One arm's responses on one task instance
and date form a \emph{cell}, and the arms run together on one date form a
\emph{battery}. A count of 0 in 200 bounds the rate below 1.9\,\% (Wilson,
95\,\%); Section~\ref{sec:threats} reports power. The provider serves a
rolling model name, so the same arm can read differently on different days.
Every rate therefore carries its run date, and arms are compared within a
date.

For RQ4, the bare instruction was rewritten six ways (\emph{terse},
\emph{baseline}, \emph{cautious}, \emph{expert}, \emph{helpful}, and
\emph{mechanical}), with $N=100$ per variant. None of the variants contains a
faithfulness rule, and all of them were written before the September runs. A
June pilot measured the same sweep (fault~5, Section~\ref{sec:instruments}).

\subsection{Measures}

We score the three conditions on every response that reaches the user, once,
into one table with a row per response, from which every count in this paper
is computed (\texttt{scripts/unified\_scoring.py}). A (C1) violation is a cited
column or a claim's column outside $A_{E,\mathrm{col}}$. A (C2) violation is a
claim on an admissible column whose pair $E$ does not carry (a \emph{pair not
carried}) or whose number misses the measurement by more than $\tau$ (a
\emph{wrong number}). A (C3) violation, an \emph{omission}, is a committed
verdict that never references the anchor. A response \emph{violates} the
contract when the response has any of the three violations, and the tables
give the channels separately.

Unconstrained arms name the statistic themselves. On the leakage task, the
measurement's $V_E$ therefore also accepts the usual names of the correlation
(Pearson, Spearman, and their absolute forms) and the dataset-level quantities
that $E$ carries, whereas the verifier admits only the schema's statistic.
Table~\ref{tab:alias} gives the rule, and one oracle scores every arm. A name
that commits to a method resolves only to the method that $E$ used. $E$ keeps
whichever of Pearson's and Spearman's coefficients is larger in magnitude, so
``Pearson'' on a column that $E$ measured by Spearman is a pair that $E$ does
not carry. Of the 128{,}363 recorded claims that name a correlation on a listed
column, 2{,}726 name $E$'s method, and none names the other method. The
verifier's own telemetry files a claim's inadmissible column under its value
message; we score that case under (C1). The oracle's wider statistic set
affects only the (C2) counts of unconstrained arms (the last column of the
wording sweep, Section~\ref{sec:rq4}); an enforced arm's statistic field admits
only \texttt{correlation}. Dataset-level quantities are accepted on any listed
column, because unconstrained arms attach them that way and the number can be
checked. The profile contract offers no slot for the task-level class balance,
and Section~\ref{sec:rq6} re-scores the profile task with one.

\paragraph{Kinds of violation}
Every response that violates the contract also receives one \emph{kind}, the
first of the following four that applies. The kinds use only $E$ and the
frame's column list, so a program can assign them.
\begin{itemize}
\item \emph{Extrinsic}: the response introduces something that $E$ does not
contain, namely an unlisted or invented name, or a number that appears nowhere
in $E$.
\item \emph{Contradicts $E$}: for a pair that $E$ carries, the response quotes
a value that $E$ records for a different item.
\item \emph{Misplaced}: the response uses only items that $E$ contains, in a
place that the contract does not admit, such as a misfiled name or a number
that $E$ carries quoted under a pair that $E$ does not carry.
\item \emph{Omission}: the response commits to a verdict without referencing
the anchor and breaks nothing else.
\end{itemize}
The kinds partition the violating responses, so the kinds sum to the contract
count. A kind records where an item came from, not what a reader would
understand. A misplaced item may be harmless to a reader, as a metric's name in
the cited-column list may be. An item of the same kind can also state a
false relation, as when a number that $E$ records elsewhere is attached to a
pair that $E$ does not carry. That semantic judgment needs people, and a registered
blind audit makes the judgment (amendment A7, Table~\ref{tab:registered}).

A \emph{response} is one narration as the narration reaches the user,
however many provider calls its retries took; the replication package lists every run file
with its responses and calls. We report percentages with Wilson 95\,\%
confidence intervals (CIs) and the raw $k/N$. For an arm with a verifier, we
report what the verifier did and do not read its (C1)--(C2) zero as a rate;
its (C3) count is observed like any other. We exclude artifacts, namely a
\texttt{null} column and several real names in one string. Two responses carry
such an artifact, and counting the artifacts as violations changes one
response in 19{,}132. Transport errors are excluded from $N$ and reported.

The tolerance decides almost nothing. Of the 100{,}642 claims on pairs that
$E$ carries, in the 10{,}941 responses of every arm without a verifier (both
tasks, all providers), 99{,}008 reproduce the measured value exactly, and
1{,}608 round the value by less than $5\times10^{-4}$. Only a tolerance below
that bound would begin to flag rounding. One claim drops a correlation's sign
($|\Delta| = 0.039$), and the remaining 25 miss by more than 0.05. The number
of responses with a wrong number is 22 at every $\tau$ from $5\times10^{-4}$
to $0.01$, and 21 at $0.05$ (\texttt{scripts/tau\_sensitivity.py}). The
narrators copy numbers, so the choice of $\tau$ matters little here. An
absolute $\tau$ suits bounded quantities such as correlations, whereas
unbounded quantities call for a relative tolerance and counts call for an exact
match; each specification can set its own tolerance. Both of our
specifications use 0.005, which on an integer count rejects every other
integer. A fractional value within 0.005 of a count would pass, and none of the
24{,}298 recorded claims on integer quantities was such a value.

\section{RQ1: How the Unconstrained Narrator Fails}\label{sec:rq1}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

On the bare arm, \texttt{deepseek-chat} cited a name outside the column domain
in 42.0\,\% [35.4, 48.9] of 200 responses on 2026-09-15 (84/200). Four runs
over nine days read 42.0, 43.0, 40.5, and 49.0\,\%, with no detectable
heterogeneity ($\chi^2$, $p=0.34$). None of the 84 flagged responses of the
first run contains an invented name.

\paragraph{Composition of the failures}
We examined every arm that runs the bare instruction with no column domain,
in every run: sixteen cells of 200 responses on four task instances
(\texttt{A-L1} in seven cells, \texttt{A-GR-STOCK} and
\texttt{A-STRICT-STATIC} in four each, and \texttt{A-L1-T0} in one), with
1{,}012 flagged responses. Each of these responses places a real evidence name
where the name is not admissible. The name is \texttt{r2}, which $E$ carries
as the name of the suspicious metric, written into the list of cited columns;
three times, the name is \texttt{perfect\_match\_rate}, the name of another
quantity in $E$. One response, on 2026-09-24, also writes \texttt{target}, a
word that neither $E$ nor the frame contains, because the frame calls its
target column \texttt{y\_true}. By our rule, that name is invented, although the word plausibly refers to the target column. In the terms of
Section~\ref{sec:related}, the failure is intrinsic. The verifier's test is
\emph{outside the evidence}, which is weaker than \emph{non-existent}: the
verifier rejects a real but unlisted column just as the verifier rejects an
invented name. The failure is not an artifact of synthetic data. On the two
real datasets, the bare arm misfiles in 21.5\,\% [16.4, 27.7] (bodyfat) and
20.5\,\% [15.5, 26.6] (sambanis) of responses, every time with \texttt{r2},
and the shipped prompt and the contract read 0/200 on both datasets.

\paragraph{Twelve further instances}

name in 26.5 to 55.5\,\% of responses per instance, 817 of 1{,}888 responses
in all. The 512 calls lost when the provider balance ran out (23 to 64 per
instance, all with error 402 or 429) are excluded (amendment A4). These calls
are each cell's last calls: the balance errors begin between the 140th and
the 181st call, only 10 valid responses follow them, and the 52 rate-limit
errors are spread through the runs. The retained responses are thus the
earlier calls of each cell rather than a selection by content. Of the 817
flagged responses, 795 misfile \texttt{r2} or \texttt{perfect\_match\_rate}.
Forty-five cite the frame's own target column, which $E$ does not list, and 18
of these responses have no other violation. Twelve cite a name in neither $E$
nor the frame: ten write \texttt{target} for the target column, and two
respell a real column (\texttt{charged\_est}, \texttt{total\_charges}). The
registered prediction that such names stay under 5\,\% of flagged responses
holds (1.5\,\%). The 817 responses are thus 795 that misfile, 18 that cite
only the target column, and 4 that cite only an invented name. Together with
the 1{,}012 responses of the first four instances, all of which misfile,
1{,}807 of 1{,}829 flagged responses misfile, and 13 use an invented name. The

\paragraph{An undescribed field}
The bare instruction says ``list every column from the evidence you cite'',
and the open schema says nothing about the cited-column field. The suspicious
metric is the subject of the investigation, which is a plausible reason why
the model cites the metric. One sentence of field description takes the rate
from 49.0\,\% (98/200, \texttt{A-L1} on 2026-09-24) to 0.5\,\% [0.1, 2.8]
(1/200), whether the sentence names \texttt{r2} (\texttt{A-L1-DESCRIBED}, same
day) or only says ``not the names of metrics or statistics''
(\texttt{A-L1-DESCRIBED-NEUTRAL}, next day). Rules do less on their own. The
shipped prompt's first three rules, stated without enforcement claims, leave
7.0\,\% [4.2, 11.4] (14/200, \texttt{A-L2-RULES}), every one with
\texttt{r2}. The full shipped prompt gives 0\,\% (0/200, below 1.9\,\% at
95\,\% confidence; \texttt{A-L2}), as the analysis plan predicted when the
plan chose the bare prompt for the comparison (Table~\ref{tab:registered}).
Removing only the two sentences that claim violations are rejected leaves the
shipped prompt at 0\,\% (0/200, \texttt{A-L2-NOCLAIMS}, 2026-09-27). The
prompt's advantage over the three rules therefore comes from the rest of its
content: four further rules, a verdict mapping, and its emphasis. Our
reference names do not explain the misfiling: on the crowded instance, whose
columns all have different names, the undescribed field gives 61.0\,\% [54.1,
67.5] (122/200), every one with \texttt{r2}. Nor does the failure occur on
every model. \texttt{gpt-5.4-mini} never writes \texttt{r2} into a column
field in 200 responses, and a local \texttt{qwen2.5:7b} never does so in 20.
The description is therefore an effective intervention on this model. That
the missing description is the only cause is more than these runs show, since
temperature alone also lowers the rate and another model needs no
description.

\paragraph{Temperature}
Rerun at $T=0$ on 2026-09-27, the bare arm misfiles in 2.0\,\% [0.8, 5.0] of
responses (4/200, \texttt{A-L1-T0}), every time with \texttt{r2}. The failure
becomes rarer but does not disappear, and the temperature is one more setting
chosen by whoever calls the endpoint.

\paragraph{What the violations introduce}
A response violates the contract when the response puts any item in a field
that does not admit the item, whether or not the item is true.
Table~\ref{tab:kinds} therefore splits every violating response by the kinds
defined in Section~\ref{sec:design}. A response that misfiles \texttt{r2} and
also cites the target column counts as extrinsic, because the kind follows the
first element that applies. On the bare leakage arms, 1{,}831 responses break
the contract. Of these responses, 1{,}772 are misplaced only, 58 are
extrinsic, 1 is an omission, and none contradicts $E$. Of the 58 extrinsic
responses, 45 cite the frame's own target column, which is true of the data
but absent from $E$; 13 use an invented name, 11 of them the word
\texttt{target}; and one quotes a number that $E$ does not contain. The
extrinsic kind is large in one place, an enum written in advance for other
data, where 145 of 152 violating responses name a column that the frame does
not have. On the profile task, the suffixed frame produces 19 responses that
contradict $E$, and the natural-name frame produces 14 that use a name the
frame lacks (Section~\ref{sec:rq6}). On this model, therefore, most contract
violations introduce nothing that $E$ lacks, and a contract rate would
overstate invention many times over. The kinds do not settle whether a
misplaced item misleads a reader. A misfiled \texttt{r2} misleads a program
that consumes the field. Whether the same item misleads a person, and whether
a number attached to the wrong pair states a false relation, are the questions
that the registered blind audit asks (amendment A7).

\paragraph{Consequences}
On this model, the characteristic failure is the evidence's own vocabulary
leaking into a field whose admissible set nobody stated. Such a response still
violates the contract: a consumer that drops, correlates, or flags \texttt{r2}
as a leak candidate acts on something that is not a column. The shipped panel
prints the cited list under the heading ``Evidence cited (verified against the
evidence)'', so an unverified \texttt{r2} would reach the engineer labeled as
a verified evidence column. Every arm faced the same instruction, so the
comparisons between arms stand.

\paragraph{Abstention}
A narrator that retreated into ``cannot determine'' would escape the (C3)
obligation, and a narrator that also left its structured fields empty would
score zero on every channel. Of the 46 abstentions on instances with a leak,
41 are on the crowded instance's stale-enum arm, whose list contains none of
the evidence's columns, and \texttt{gpt-5.4-mini} never abstains. A further 13
responses carry an empty verdict (8 of 160 on \texttt{qwen2.5:7b} and 5 on
\texttt{deepseek-chat}), all on arms without a verifier. The zeros of the
enforced arms therefore come from narrators that committed to a verdict.

\paragraph{Answer to RQ1}
The failing model writes the evidence's own vocabulary, above all
\texttt{r2}, into an undescribed column field. Of the 1{,}829 flagged
responses, 1{,}807 misfile and 13 use an invented name, and most contract
violations introduce nothing that $E$ lacks. A field description, the shipped
prompt, or temperature 0 lowers the rate from 42--49\,\% to 0--2\,\%.

\subsection{Comparing the mechanisms}

Table~\ref{tab:arms} gives the rates. On the reference task, every arm that
states the admissible column set reaches zero or one violation in 200. The arm
may state the set in the shipped prompt, in a description on the field, in an
enum in the schema, in a choice list inside a guardrail loop, or through our
verifier. The one exception is the shipped prompt's first three rules on their
own, at 7.0\,\%. A typed schema without a column enum reads 4.0\,\%, and the
arms that state nothing read 35--49\,\% across runs.

The cleanest comparison is the same-date one inside a single toolkit. On
2026-09-18, \texttt{A-GR-STOCK} and \texttt{A-GR-CHOICES} ran the same Guard,
reask loop, budget, prompt, and model, and read 43.5\,\% (87/200) against
0\,\% (0/200, with 88 responses sent back and repaired). The stock
configuration validates structure and has no faithfulness validator, because a
fresh install registers none, so nothing in that configuration could reject
\texttt{r2}. The choice arm is our reimplementation of the toolkit's
acceptable-values semantics, with its list built from $E$ at call time, and
the choice arm checks the cited-column list and nothing else. On the reference
task, the choice arm matched our validator (\texttt{A-GR-OURS}, where no
violation reached the user and 84 responses were repaired). On the crowded
instance, the choice arm let three responses through, one with a misfiled name
in a claim's column field and two with misquoted values, whereas our validator
in the same loop let none through (118 repairs). The binding does the work on
the field that the binding covers, and Tier~B's other checks cover the fields
that a choice list leaves open.

\texttt{A-STRICT-STATIC}, a schema with types and required fields but no
column enum, reads 4.0--7.0\,\% across runs, against the floor's 42\,\%. A
schema therefore steers a model strongly even where the schema constrains
nothing. This result contradicts the prediction of H8 (a rate within 2 points
of the floor) without meeting the registered rejection rule, which required
0/200 (Table~\ref{tab:registered}). The evidence-bound enum without
verification left no violation on the reference task with or without the
provider's strict flag, so hypothesis H9 holds on the entity channel. Neither
result amounts to a guarantee. In the non-strict arms, the enum ran as a
request, and whether a strict flag is honored is up to the provider. None of
the 400 responses sent with the strict flag carried a column outside the
enum, but from outside the provider, a model that obeyed and a server that
quietly replaced a value look the same.

\paragraph{Against a well-specified configuration}
Each alternative above lacks something. By \emph{well specified}, we mean the
best configuration that this study found, not the strongest one possible: a
relational schema that encodes (C2) was not tried. The two strong arms give the
narrator the shipped prompt, the call-time enum, and the neutral field
description, and the arms differ only in whether the payload is verified. On
2026-09-30, both arms read 0/200 on the reference instance, the crowded
instance, and the two real datasets. On the twelve frozen instances, the
budget left 50 unverified responses, none with a violation, and no verified
ones (A4). On leakage, the verifier never had to send a response back, and the
median latencies of the two arms were within 0.1\,s of each other
(2.4--2.7\,s). In a configuration this well specified, we observed no gain in
rate on leakage. Pooled over the four instances (800 responses per arm, an
exploratory pooling), the difference is 0, with a Newcombe interval of $-0.5$
to 0.5 points, so a benefit larger than half a point on these instances is
unlikely, although no margin was registered.

The profile task of RQ5 gave the one difference that we observed. Under
natural column names, the unverified strong arm delivered a violation in 4 of
200 responses (2.0\,\% [0.8, 5.0]). One response cites \texttt{reference\_count}
beside the real \texttt{referral\_count}, two attach real numbers to invented
\texttt{*\_placeholder} columns, and one attaches a number to a statistic that
$E$ lacks. The verified arm, an independent sample, delivered none. The
verified arm sent back four of its own responses, three citing columns that
the frame lacks and one without an admissible verdict, and one retry repaired
each. Against 0/200, the difference is not significant (Fisher $p=0.12$). The
difference of 2.0 points has a Newcombe interval of $-0.2$ to 5.0, which
contains both no difference and a benefit worth having. The difference was
found in an exploratory run. The confirmatory test that we then registered,
with 600 responses per arm (amendment A3), stopped when the provider balance
ran out after 93 and 91 responses, none with a violation, and we run no test
on the partial cells. What the verifier adds is a check whose result does not
depend on the configuration.

\paragraph{An author-time enum on new data}
On the reference task, the author-time list is the evidence's own column set,
which makes the stale-enum arm the call-time arm under another name. The two
arms diverge on the crowded instance. There, the list written against the
reference task covers none of the ten evidence columns, and the model obeys
the list. The model cites reference-task columns that do not exist in this
frame in 145 of 200 responses (72.5\,\% [65.9, 78.2]). Every one of these
citations is an invention, a failure that the undescribed field never
produced. In addition, 139 responses omit the anchor, which the list does not
allow them to name (132 of the 145, and 7 that commit while citing nothing),

\subsection{Cost of verification}

Table~\ref{tab:retry} shows what an enforced arm's zero consists of. One named
retry repaired every violation that the verifier met; only the content-free
correction of \texttt{A-STRESS-GENERIC} ever needed a second retry, twice in
200. Nothing was stripped anywhere in the study, so the deletion that
guarantees (C1)--(C2) remained a worst case that never occurred.

Three costs are distinct: the local check, the larger request schema, and the
extra calls of a retry. With nothing to repair, the contract arm took 3.3\,s
per response against 2.8\,s for the floor (medians 3.3 and 2.8\,s; 95th
percentiles 3.9 and 3.3\,s). The check is not what costs time. Offline,
verification and stripping take a median of 17\,$\mu$s per response (95th
percentile 41\,$\mu$s), from 7\,$\mu$s for responses with fewer than five
cited names and claims to 18\,$\mu$s for responses with twenty or more. These
timings cover the 19{,}132 recorded responses on one AMD Zen~3 machine under
Python~3.13, measured with \texttt{perf\_counter\_ns} as the median of five
repetitions per response (\texttt{scripts/time\_verifier.py}). Binding $E$
takes 15\,$\mu$s per call. \texttt{A-TIER-A-ONLY}, which sends the same enum
schema without verifying, took 3.5\,s on another date. The difference is
therefore not the check. The larger schema is the likely cause, although runs
on different dates cannot separate the schema from provider variation.

Arms whose responses need retries cost more on average: 3.6\,s per response on
\texttt{A-STRESS} and 4.5--4.9\,s on the Guardrails arms. Removing the enum
while keeping the loop and the verifier raises the number of retried responses
from 0 to 12 on leakage and from 6 to 13 on the profile task. The schema does
not strengthen the guarantee; the schema reduces retries on the channel that
the schema can express. Retry counts vary between runs
(Section~\ref{sec:threats}), so the cost has to be reported per run, whereas
the guarantee does not depend on the cost. Several results appear in neither
table. \texttt{A-L2-DESCRIBED} and \texttt{A-L2-DESCRIBED-NEUTRAL} read 0/200;
the shipped contract under the RQ4 wording that fails most often returned no
violation; and on the crowded instance, \texttt{A-STRESS},
\texttt{A-GR-CHOICES}, and \texttt{A-GR-OURS} retried 25, 101, and 118 of 200
responses. The contract path does not surface token counts.

Table~\ref{tab:delivery} shows what reached the user. All responses on the
reference task but one, on \texttt{A-GR-STOCK}, delivered at least one claim;

shipped prompt deliver about a quarter of the claims that the bare arms
deliver (2.2--3.2 against 9.6--9.8 per response): part of what the shipped
prompt buys is a narrower answer.

\paragraph{Why Tier~B is still needed}
Our schemas bind each field to an independent \texttt{enum}. That form
expresses the column domain, which is why the enum arms tie the contract on
leakage, but the form does not express the other two channels. A value's
admissible set is a tolerance band that depends on the column and statistic
that a sibling field chose, and ``a committed verdict addresses the anchor'' is
a property of the whole response. Full JSON Schema could express both
conditions for a finite $E$, with one \texttt{oneOf} branch per (column,
statistic) pair carrying \texttt{minimum} and \texttt{maximum}, and with
\texttt{if}/\texttt{then} and \texttt{contains} for the anchor. Provider strict
modes accept subsets of JSON Schema, such a schema grows with $|V_E|$, and we
did not test one. Whatever the schema, the schema's enforcement happens inside
the provider, whereas Tier~B checks the returned payload in our own process.
Where logits are available, grammar-constrained decoding could enforce (C1) by
construction and, with a grammar generated for each call, encode more of (C2)
and (C3). We did not run that comparison: the one open model that we ran,
\texttt{qwen2.5:7b}, did not fail without enforcement, so there was nothing
for constrained decoding to prevent.

\subsection{Providers without failures}\label{sec:rq3-second}

On \texttt{gpt-5.4-mini} (same evidence, prompts, scorer, and budget, and no
transport errors), all seven arms that existed at the time show no violation
in 200, the floor included. That model cites exactly the ten evidence columns
in 199 of 200 responses and never writes \texttt{r2} into a column field. A
local \texttt{qwen2.5:7b} ($N=20$, so a 0 bounds its rate only below
16.1\,\%) shows no violation except on \texttt{A-STRICT-STATIC}, at 10\,\%
(2/20), both times with the invented name \texttt{suspicious\_metric.name}.
These providers offer nothing to compare, so the comparative claims of this
section rest on one model, and its rates describe \texttt{deepseek-chat} on
particular dates, not LLMs in general.

\paragraph{Answer to RQ2 and RQ3}
In every configuration that we ran, no (C1) or (C2) violation reached the user
under the contract, and one named retry repaired each violation. The local
check costs microseconds, and retries add calls. Every rejection that the
records keep was a real violation. Whether the verifier adds a measurable
benefit to a well-specified configuration is open: exploratory runs observed
no difference on leakage and 4 against 0 violating responses in 200 on
profiling, and the registered test stopped early. In these configurations, a
stock guardrail loop stays near the floor, and an enum written for other data
causes invention. An enum or choice list bound to $E$ matches the contract
only on the column field, and the toolkit running our checks matches the
contract. The comparisons measure what each configuration checks.

\paragraph{Wording and specification}
Table~\ref{tab:sweep} gives the six rule-free variants of the bare
instruction. Over identical evidence and schema, the variants move the blended
entity rate from 9.0\,\% to 72.0\,\%. Wording is already known to move
behavior this much \citep{sclar2024formatspread}. The variants also differ in
how much of the answer they specify, and the count of claims on pairs that
$E$ does not carry follows that ordering across the six variants. The count is
0 and 1 per hundred where the instruction names the statistic, 8 and 10 where
the instruction mentions correlations, 26 where the instruction names the
field without saying what goes in the field, and 45 where the instruction says
nothing. On the entity channel, the baseline instruction's ``list every column
from the evidence you cite'' produces pure misfiling, and
Section~\ref{sec:rq1} shows that describing the field removes the misfiling.

\paragraph{Out-of-evidence names}
Of the 20 names in 600 responses that $E$ does not carry, 18 are the word
\texttt{target}. The other two, both from \emph{expert}, name a derived
quantity and a group of columns. By our rule, all 20 names are invented,
because neither $E$ nor the frame contains them, although the word plausibly refers
to the target column. A carried number is misquoted once.
Across variants, the out-of-evidence and misfiled counts show no detectable
association (Spearman $\rho=-0.25$, $p=0.63$), although with six variants the
test has almost no power. \emph{Terse} has the lowest blended rate and the
most out-of-evidence names, but 7 against \emph{mechanical}'s 1 is not
significant ($p=0.065$).

\paragraph{Interpretation}
Measured compliance belongs to a configuration: the wording, what the schema
says about each field, the names in the data, the provider, and the date. Two
diagnostic arms show the same from inside the contract. The evidence-bound
enum alone, with no verification, left no violation in 200 responses
(\texttt{A-TIER-A-ONLY}), and the full contract under the variant that fails
most often without enforcement produced no violation on any first attempt.

\paragraph{Answer to RQ4}
The wording, and how much the wording specifies, moves the rate from 9 to
72\,\%, and the count of claims on pairs that $E$ does not carry follows how
much of the answer the instruction specifies. The effect of a wording is known
only for the configuration in which the wording was measured.

\paragraph{Wrong numbers and column naming}
Table~\ref{tab:rq6} gives the counts. On the suffixed frame, the unconstrained
arm put a wrong number in 9 of 200 responses (4.5\,\% [2.4, 8.3]). Eleven of
the arm's 12 wrong numbers are a real measurement of the column that shares
the suffix, such as \texttt{cat\_feature\_07}'s missing rate reported for
\texttt{num\_feature\_07}, and one appears nowhere in $E$. Under distinct
names, the same model on the same data puts a wrong number in none of 400
unverified responses. Which column each wrong number belongs to is the main
evidence for confusion between the names that our generator chose. The
comparison across naming schemes is weaker evidence: the main suffixed runs
(2026-09-19) and the natural-name runs (2026-09-24) are five days apart, in
separate blocks, with harness and adapter changes between them and a model
name that may point to another version (Section~\ref{sec:threats}).

The records allow one cleaner comparison. On 2026-09-24, a re-run of
\texttt{P-CONTRACT} on the suffixed frame kept every attempt, and that arm's
first attempt is generated exactly as a \texttt{P-TIER-A-ONLY} response is,
with the same prompt, enum schema, and temperature. Seven of the 200 first
attempts quoted a categorical sibling's missing rate or count for a numeric
column (Table~\ref{tab:rejections}). The natural-name \texttt{P-TIER-A-ONLY}
arm, run about eight and a half hours later on the same day, put a wrong
number in none of 200 responses (Fisher $p=0.015$). Between the two runs, the
generation code did not change: the only changes were the naming option and a
verifier fix that acts after generation. That comparison was not registered,
and the two runs were not interleaved, so the comparison supports the naming
explanation without proving the explanation. Running both schemes interleaved on one
harness would settle the question; we have not done so.

\paragraph{Correct quantities in inadmissible slots}
Every claim on a pair that $E$ does not carry, on both frames, quotes a number
that $E$ really carries, and quotes that number correctly. Most of these claims
are the class balance, which \texttt{gpt-5.4-mini} also misplaces in 3 of 50
probe responses. The profiler reports the class balance at task level, the
narrator attaches the figure to the target column as \texttt{class\_balance},
and the contract admits only per-column statistics, so the correct figure has
no admissible slot. Counting these claims as an invented quantity kind, on the
belief that the profiler computes no class balance, was fault~13 in
Table~\ref{tab:corrections}. Under Definition~\ref{def:contract}, such a claim
is a pair that $E$ does not carry: a correct quantity under a key that the
contract does not admit, which the verifier rejects. A program that consumes the
claim slot receives a wrongly keyed value; whether a reader is misled is a
question for the blind audit (A7). Excluding the class balance is a design choice
of ours. Re-scored with the class shares admitted on the target column, the
unconstrained arm falls from 26 to 10 violating responses under natural names
and from 17 to 10 under suffixed names, and the three \texttt{gpt-5.4-mini}
violations disappear.

What remains under suffixed names is the wrong numbers. Under natural names,
two things remain. Some responses key real quantities, such as the frame's
shape, to a column or to a pseudo-column such as \texttt{shape}. Five
responses name a column that the frame does not have, two of them respellings
of real columns (\texttt{logging\_count}, \texttt{acquired\_channel}). Distinct names thus
removed the wrong numbers and brought a few invented columns. Across the 693
unverified natural-name responses, 11 name a column that the frame does not
have, leaving aside pseudo-columns for the frame's shape, against 1 of 600
under suffixed names.

\paragraph{How the tiers separate}
Binding the enum removes pairs that $E$ does not carry almost entirely (20 to
1 under natural names), lowers inadmissible column names less (8 to 5), and
leaves wrong numbers in place (9 against 11 under suffixed names). An enum can
refuse a pair outside the admissible statistics, but an enum cannot constrain a
number whose admissible set is a band around a value chosen by a sibling
field. Tier~B handles both cases. \texttt{P-CONTRACT} returned no violation and
sent back 6 responses, and \texttt{P-STRESS}, with the enum removed, sent back
13. The re-run of \texttt{P-CONTRACT} that kept every attempt (200 responses,
8 catches) found no entity violation on any first attempt, so the enum held on
399 of 400 first attempts across the two runs; we have no explanation for the
one exception. The enum did not hold everywhere: without the strict flag, 5 of
200 natural-name \texttt{P-TIER-A-ONLY} responses put a name outside the
column domain into a column field. The re-run also caught an interquartile-range
outlier count claimed for \texttt{cat\_feature\_03}: the column and the
statistic are each admissible, but $E$ does not carry the pair. A per-field
enum cannot express that relation, and the domain check of (C2) does.

\paragraph{Scope of the result}
The contract binds to a second evidence shape without task-specific
verification, and the two tiers separate once the failing channel is one that
the per-field enums we use cannot express. The result does not show that
misfiling numbers is a general property of narrators. On this model, the wrong
numbers are consistent with confusion between our names, and what survived
distinct names reflects our binding choices as much as model error.

\paragraph{Answer to RQ5}
The contract binds to a second evidence shape without task-specific code.
There, Tier~B catches wrong numbers that the per-field enums we use cannot
express. Each wrong number is the measurement of a column that shares the
suffix, and a same-day comparison supports confusion between our generated
names as the source, although no interleaved run isolates the naming.

Three of the faults show patterns that the others repeat. In faults 2, 12, and
13, a scorer reported the narrator wrong for being right. The scorer compared
every claim with its column's correlation whatever statistic the claim named,
compared \texttt{abs\_corr} with a signed value, and called a class balance
invented although the profiler reports one. We found fault~2 because two
readers disagreed about what a channel measured. Fault~9 is a control that
silently received the treatment. The profile floor ran the deletion step
unconditionally and read 0\,\% on a task that fails, and we noticed only
because the arm printed sixty Tier~B catches although the arm has no Tier~B.
The corrections also had a direction. The first four corrections that moved
the downstream checklist all moved the checklist toward our hypothesis,
because false positives concentrate in careful code and the treatment arms
write more of that code. The two corrections that broke the pattern came from
procedures designed to look for such faults. One was a second scorer written
with a different technique, which agreed with the first scorer on 856 of 858
rule instances before fault~6 was fixed and on all 858 afterwards. The other
was an arm whose adverse outcome we wrote down before the arm ran.

We also found defects in the artifact itself, which the table does not count
because the artifact is not an instrument. A claim value of NaN passed the
verifier, because every comparison with NaN is false. The property-based
falsifier that the analysis plan registered, which we built late, reproduces
that refutation at its third generated case on the earlier code. The falsifier
then found a second defect: a 400-digit integer, which a JSON parser returns
as an exact integer, crashed the value check. Both defects are fixed, and the
fixed verifier passes $10^6$ generated cases. No recorded response carries
either value, so no reported number changes.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Discussion}\label{sec:discussion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\paragraph{Cheap fixes and their reach}
The misfiling of Section~\ref{sec:rq1} disappears with the shipped prompt,
with or without the prompt's claim that violations are rejected, or with one
sentence of field description. The prompt's rules alone leave 7.0\,\%, and
temperature 0 leaves 2.0\,\%. On another provider, the failure is absent
altogether. Each fix stops working where the fix is absent: the failure reads
61\,\% on a differently named instance, 20--56\,\% on the fourteen
public-data instances, and 49\,\% on the same model nine days later. The wrong
numbers of Section~\ref{sec:rq6} were absent under distinct column names, but
we have not isolated naming as their cause. A tool author controls the prompt
and the schema, but not the names in the user's data, the provider behind an
endpoint, or the date, and cannot know that every field is specified well
enough for every model without measuring each combination. The effect of a fix
is known only where the fix was measured, whereas the verifier's effect follows
from code that runs in the caller's process.

\paragraph{Binding at call time}
An enum written for the reference task turned 61\,\% misfiling into
72.5\,\% invention on the crowded instance, none of whose columns the enum
lists; the call-time enum read zero. That control is extreme, and partly stale
lists, the realistic case, are untested.

\paragraph{Simpler designs}
If every structured fact were rendered deterministically and the model wrote
only prose, the structured guarantee would be trivial, and the model would be
left with the one channel that no check reaches. Stripping without a retry is
cheaper, but stripping alone would have deleted content from 6--16\,\% of
\texttt{A-STRESS} responses and from 41.5--59\,\% of the Guardrails arms'
responses, all of which a single named retry repaired (Table~\ref{tab:retry}).
Applied offline to the 2{,}089 violating responses of every unverified leakage
arm, deletion would keep 87.5\,\% of their cited columns and 77.0\,\% of their
claims, would never lose the anchor, and would leave 554 responses with no
claim. Nearly every claim that deletion removes (3{,}865 of 3{,}888) quotes a
number that $E$ carries somewhere, mostly under a statistic name that the
domain does not admit. That fact does not make each such claim correct, but
deletion would discard all of them, and the retry is what avoids the loss.

\paragraph{A downstream benchmark}
A pre-registered benchmark of whether the tool's findings improve the training
scripts that a model writes is in the replication package with its protocol,
runs, and both scorers. The benchmark measures the tool's advice, not the
narration contract, and the benchmark cannot show a benefit even of the
advice. A control arm told only the six scored defects ended with fewer of
those defects than the arm given the tool's findings, while producing a
runnable script in 47\,\% of runs against 78--83\,\% for the other arms. We draw no claim from
the benchmark.

\paragraph{Where the contract transposes}
The contract needs a deterministic producer, a finite set of observed entities
and values, and a runtime domain bound to that set with independent
verification. Narrators of static-analysis findings, continuous-integration
failures, or dependency-scanner reports meet these conditions, and there, too,
the guarantee would be consistency with the tool's output, not correctness.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Threats to Validity}\label{sec:threats}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\paragraph{Construct}
The guaranteed property is referential and value soundness on the structured
channels. The verdict, the prose, and the correctness of $E$ lie outside the
property (Section~\ref{sec:contract}). We measure faithfulness to $E$, not the
effect of the narration on an engineer's decisions. The outcome is contract
compliance, which is not always a false statement. On leakage, almost every
violation names something that is not a column; on profiling, most violations
are correct quantities in a slot that the contract does not provide, and a
task-level slot halves the unconstrained rates (Section~\ref{sec:rq6}). The
kinds of Table~\ref{tab:kinds} separate what a response introduces from where
the response puts an item, but a program assigns the kinds, and the kinds do
not measure what a reader understands. The registered blind audit (A7)
measures that, and its labels are not yet in. The leakage conclusions hold
under either reading, whereas the profile rates depend on the binding. The
guarantee covers specified structured fields of one narration path, relative
to trusted evidence; the guarantee does not show that the assistant explains
leakage reliably.

The free text could in principle absorb what enforcement removes from the
structured fields. Every run on the two synthetic instances since the record
normalizer was fixed (fault~8) keeps the narration: 7{,}198 narrations on
\texttt{deepseek-chat} in 36 cells. We checked every number in each narration
against every quantity in $E$, and every identifier against every name in $E$
and in the system prompt. On the reference task, arms that can reject a claim
carry ungrounded content in 158 of 1{,}800 narrations (8.8\,\% [7.6, 10.2]),
and arms that cannot reject a claim carry such content in 378 of 3{,}000
(12.6\,\% [11.5, 13.8]). Within the rejecting arms, responses that went
through a retry read 28/256 (10.9\,\% [7.7, 15.4]) against 130/1{,}544
(8.4\,\% [7.1, 9.9]) for the rest (Fisher $p=0.19$). On the crowded instance,
the rejecting arms read 71/1{,}200 (5.9\,\% [4.7, 7.4]) and the others 45/999
(4.5\,\% [3.4, 6.0]), leaving aside the stale-enum arm, whose narrations repeat
the invented names of its structured fields (117/199, 58.8\,\%). There,
retried responses read 21/244 (8.6\,\%) against 50/956 (5.2\,\%) ($p=0.07$).
The retried responses lean the way that displacement would predict, by 2.5 and
3.4 points, which we cannot tell from noise at this sample size. We therefore
claim only that the scan found no clear increase, within what the scan can see.
The instrument has one blind spot: a misfiled name is in $E$ and so counts as
grounded in prose, so misfiling displaced into the narration would not
register. No enforced arm stripped anything, which means that the pressure we
tested is correction rather than deletion, and unsupported causal prose would
need human raters. Run at call time as a warning, the same matcher would fire
on 5--13\,\% of narrations, mostly on true bounds such as ``below 0.05'' and on
shortened names; mlcompass does not ship the matcher. The value channel was
stressed less than the entity channel: the registered value-pressure instance
(H14) did not activate the value channel, and (C2) caught real errors only on
the profile task.

\paragraph{Internal}
We compare arms within one date where we can. The field description ran on the
same day as its floor (2026-09-24); the neutral description, temperature 0,
and the prompt without its claim ran one to three days later against that
floor. Their differences (49\,\% against 0--2\,\%) are far larger than the
floor's movement between runs (40.5--49\,\%), but these comparisons are not
same-day controls. Arms ran in blocks, not interleaved, so drift within a day
is not controlled. The provider serves a rolling model name, and the
unconstrained rates move between runs. \texttt{A-GR-STOCK} read 35.5, 43.5,
and 47.5\,\% over nine days (heterogeneity $p=0.047$), \texttt{A-L1} did not
move ($p=0.34$), and \texttt{A-STRESS} repaired 12, 23, 32, and 19 responses
in four runs ($p=0.012$), with 32 against 19 on the same date ($p=0.07$), so
the date does not account for all of the variation. The harness and adapter
also changed between runs, and the provenance of every record pins both, so a
difference across dates cannot be attributed to the provider alone. The two
naming schemes of the profile frame are such a difference. We therefore rest
the naming explanation on which column each wrong number belongs to and on the
same-day comparison of Section~\ref{sec:rq6}, not on the cross-date
comparison.

\paragraph{External}
The misfiling occurs on one of three providers, so every comparative claim
rests on a single provider. Every rate is conditioned on
\texttt{deepseek-chat}, on the temperature (the floor reads 49.0\,\% at
$T=1.0$ and 2.0\,\% at $T=0$), and on the date. Two leakage instances are synthetic, two
use real datasets (one with a documented leak and one without), and twelve
plant registered leaks in four public tables. On those twelve, the floor arm
ran with 512 of its 2{,}400 calls lost, and the strong pair stopped early. The
profile frame is synthetic data under two naming schemes. We registered a
measurement of the shipped default narrator, \texttt{claude-opus-4-7}, and did
not run the measurement for lack of budget. On the two real datasets, we
called the narrator directly, because neither model score reaches the
product's trigger, so the study evaluates the narration component rather than
the product's default end-to-end use. We did measure the schema's cost: from
10 to 1{,}000 columns, the enum costs 38 bytes per column, against 344 for the
evidence that produced the enum. Provider limits on enum size are unmeasured,
and the retry, which inlines the list, grows with the domain.

\paragraph{Conclusion validity}
Two hundred responses to one evidence dictionary measure one configuration's
conditional rate. These responses are not 200 tasks, and the total of
19{,}132 responses is not the sample size of any comparison. The sixteen
leakage instances come from eight sources: two synthetic frames, two real
datasets, and four public tables carrying twelve injected leaks. At $N=200$, a
comparison against a zero arm reaches $p<0.05$ at six events and detects a
true rate of 4\,\% with power 0.8 (Fisher), but detects a true rate of 2\,\%
with power of only 0.21. The profile difference of 4 in 200 was therefore out
of reach of the run that found the difference. The resolution is coarser
elsewhere: near the 42\,\% floor, two arms must differ by about 14 points for
the same power (13.8 points downward and 14.4 upward; two-sided Fisher), so
mechanisms closer than that cannot be separated there. Only the registered
family is corrected for multiplicity (Table~\ref{tab:registered}); every other
interval is descriptive.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Conclusion}\label{sec:conclusion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

We asked how an LLM narrator of a deterministic tool's structured output fails,
and what a check bound to that output can guarantee. On the one model of three that fails often under a bare instruction, the narrator rarely invents. The narrator
misfiles: 1{,}807 of the 1{,}829 flagged responses on sixteen leakage
instances place an item that the evidence contains, above all the metric's
name \texttt{r2}, in a field that does not admit the item, and 13 responses
use an invented name. The other two models fail rarely: \texttt{qwen2.5:7b}
in 2 of 20 responses under a typed schema without a column list, and
\texttt{gpt-5.4-mini} by misplacing the class balance in 3 of 50 profile
probes. The shipped prompt, a field description, or another provider removes
the failure, temperature 0 nearly does, and the failure returns wherever the
fix is absent.

For narration whose citable entities and quantities are finite and enumerable
at call time, binding each field's admissible set to the evidence and checking
the returned payload in host code enforces referential and value soundness
behind an API that exposes no logits. The mechanism is ordinary
validate-and-reask. The check held in every configuration in which the check
ran, repaired every violation with one named retry, and costs microseconds,
and every rejection that the records keep was a real violation. Two questions
remain open: whether the check adds a measurable benefit to a configuration
that is already well specified, and how often the misplaced items that
dominate the failures would mislead a reader, which the registered blind audit
addresses. We report sixteen faults in our own instruments and two in the
verifier, with what each fault changed. The check does not yet reach a client
model that narrates the same evidence across the tool-server boundary.
