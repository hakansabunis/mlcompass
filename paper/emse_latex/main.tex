\abstract{%
\textbf{Context.} Software tools increasingly place a large language model
between a deterministic analysis and the engineer who acts on it. When the
explanation cites a column, defect or number the analysis never produced, the
engineer acts on something that was never observed.

\textbf{Objective.} We ask whether this failure can be \emph{prevented} rather
than statistically reduced, and whether prevention buys anything a
general-purpose guardrail toolkit does not.

\textbf{Method.} We identify a class of narration tasks we call
\emph{evidence-closed}: the citable entities and checkable quantities are
finite and machine-enumerable at the moment of the call, which makes
faithfulness decidable. A two-tier \emph{evidence-bound runtime contract} built
on that property ships in the narration path of \textbf{mlcompass}, an
open-source ML-pipeline assistant. We evaluate it over 3,800 live responses and
175 scored runs: an eight-arm controlled experiment on three providers, a
six-variant paraphrase sweep, two diagnostic arms, and a five-arm
pre-registered benchmark of downstream code quality.

\textbf{Results.} The failure is not the one the literature names: the
unconstrained narrator \emph{misfiles} real evidence names at 4--71\,\% while
\emph{inventing} names at 0--7\,\%, and the two rates do not co-vary
consistently under rewording --- at the extremes they run opposite, so the
prompt that looks safest invents most. Varying only the
validator inside one guardrail toolkit --- same loop, budget, prompt and model
--- takes 35.0\,\% to 0/200, and so does that toolkit's own generic
choice-list check once the list is bound to the evidence: what does the work is
the binding, not our validator. The rate itself is not a property of anything
stable --- a second provider scores 0/200 on the unconstrained arm, and the
same model name re-run three days later moves the toolkit's default from
35.0\,\% to 43.5\,\%. Downstream, over 175 scored runs, a fifth arm given only
the names of the six scored rules and nothing about its own code beats the arm
given the tool's real findings on the checklist (1 flagged defect against 8),
so we withdraw the causal attribution an earlier version of this abstract made
--- while writing code that executes 47\,\% of the time against 83\,\%.

\textbf{Conclusions.} For evidence-closed narration, faithfulness on the
validated channels is enforceable by construction and independent of the
provider. The contract's value is not that it lowers a rate, but that the rate
it replaces is not a stable property of anything.
}

\keywords{Large language models, Hallucination, Faithfulness,
Constrained generation, Runtime verification, Data leakage}

\section{Introduction}\label{sec:intro}

Machine-learning practice runs on single-purpose tools. A profiling library
inspects the dataset~\cite{ydata}, experiment trackers record training
runs~\cite{mlflow,tensorflow}, automated model search picks an
estimator~\cite{autosklearn}. Each covers one slice of the pipeline and none
tells the engineer what the results \emph{mean}. The now-standard answer is
agentic: put an LLM on top, let it call the tools, read their structured
output, and explain --- the pattern formalised by ReAct~\cite{react} and
Toolformer~\cite{toolformer} and operationalised by tool-integration
standards~\cite{mcp}.

The trouble is that LLMs hallucinate~\cite{ji,huang}, and assistants built on
the same foundation models~\cite{codex} still fail real software tasks at
substantial rates~\cite{swebench}. In an advisory ML setting the failure takes
a specific shape. The narrated object is \emph{structured evidence} --- a
dictionary of facts a deterministic tool actually measured --- and the narrator
can report members of it that are not there: a column the data does not
contain, a defect nobody detected, a number that contradicts the report. The
cost is concrete, because a wrong diagnosis delivered fluently is worse than no
diagnosis: the practitioner acts on it.

This paper is built on one observation about that setting. What the narrator
may cite is \emph{finite and machine-enumerable at the moment of the call}. We
name the class:

\begin{definitionx}[Evidence-closed narration]\label{def:closed}
A narration task is \emph{evidence-closed} if the set of citable entities and
verifiable quantities is finite and machine-enumerable at the moment of the
narration call.
\end{definitionx}

Once a task is evidence-closed, faithfulness checking \emph{on its structured
claim channels} stops being a modelling problem. Entity citations become
set-membership tests against the domain admissible for the field they appear in,
quantitative claims become numeric comparisons, and coverage of the critical
finding is one more membership test. The narrowing matters and we hold to it
throughout: a free-text sentence can name only real columns, quote only real
values, and still assert a causal story the evidence does not support. That
sentence is outside the decidable fragment, it reaches the user, and
Section~\ref{sec:contract} says so again where the guarantee is stated. The check is \emph{decidable}, which changes the sensible goal
from \emph{mitigation} --- pushing a probability down --- to \emph{prevention}:
making an unfaithful answer impossible to return on the channels that carry the
actionable content.

Constrained generation looks like the natural instrument. Outlines~\cite{outlines},
LMQL~\cite{lmql}, grammar-constrained decoding~\cite{gcd} and
Guidance~\cite{guidance} restrict what a model may emit during decoding, and
provider tool-use APIs validate calls against a declared JSON
schema~\cite{structured}. Two things go wrong here. Decoding-time enforcement
needs the token distribution, and commercial APIs do not expose it. A per-call
schema, in turn, only helps if the provider's enforcement is trusted, and for a
safety claim it should not be.

\paragraph{The artifact.} Our answer is a two-tier \textbf{evidence-bound
runtime contract}. \emph{Tier~A} generates the \texttt{enum} domains of the
narrator's tool-input fields from the deterministic evidence dictionary at call
time, constraining generation as far as a closed API allows. \emph{Tier~B}
takes over where trust ends: plain code re-checks the returned answer on three
channels --- entity soundness, value soundness of structured
\{column, statistic, value\} claims, and completeness with respect to the
top-ranked candidate --- with corrective retry, residual stripping, and
omission flagging. It is not a research prototype built for this paper: it is
the narration path of the released tool, on by default, and the measurements
below run against that path rather than a reimplementation of it. We say
\emph{shipped} and not \emph{production}, because we have no deployment
telemetry to offer --- no user counts, no incident record, no operational
duration --- and a claim of production use should be backed by those. It is
\textbf{mlcompass}, an open-source (MIT) ML-pipeline assistant, guarding the
investigation that fires when an evaluation metric looks too good to be true
--- mlcompass fires at its own heuristic thresholds,
$R^2>0.999$ or $\mathrm{AUC}>0.995$, motivated by the leakage problem
Kaufman et al.\ describe~\cite{leakage} rather than by any threshold they
propose.

\paragraph{On reporting our own mistakes.} Three of the results below
contradict what we believed at the point the study began. The failure mode is
not the one we set out to measure (Section~\ref{sec:rq1}); the downstream
effect could not initially be attributed to the tool, and a fourth arm was
needed to attribute it (Section~\ref{sec:rq5}); and seven faults in our own
measuring instruments --- six defects and one non-reproduction --- produced
numbers we had already reasoned from
(Section~\ref{sec:instruments}), one of them found only because two readers of
an earlier draft disagreed about what a channel was measuring. We report each in the body rather than an
appendix, with the superseded measurements preserved in the replication package
beside their corrections, because an instrument defect found and reported by
the authors is evidence about the instrument, and one found by a reader is
evidence about the authors.

\paragraph{Research questions.}
\begin{description}
\item[RQ1] How does an unconstrained narrator of evidence-closed material
actually fail, and does the failure match the name the literature gives it?
\item[RQ2] Does the contract prevent that failure on the validated channels?
\item[RQ3] How does it compare with the structured-output and
validate-and-retry alternatives a practitioner would otherwise reach for?
\item[RQ4] Can a prompt-level defence be certified from observed compliance?
\item[RQ5] Does the tool change what an LLM downstream actually produces, and
if so, which part of it does the work?
\end{description}

\paragraph{Contributions.}
\begin{enumerate}
\item \textbf{The evidence-closed class} (Definition~\ref{def:closed}) with the
two facts the design rests on: faithfulness verification is linear-time
(Proposition~\ref{prop:linear}), and deletion repairs soundness safely while
completeness admits no safe repair (Proposition~\ref{prop:asym}). The second is
a monotonicity argument, and we are explicit that it is not the stronger
safety/liveness result it resembles~\cite{schneider2000enforceable,alpern1985liveness}.
What this setting adds runs \emph{opposite} to the security case, where
insertion is simply a more powerful primitive: over a narrator it is
inadmissible, because an inserted reference fabricates attribution rather than
correcting an action.
\item \textbf{A controlled swap of the validator inside a released
guardrail toolkit, and the narrower claim it forced.} Holding the reask loop,
the budget, the prompt and the model fixed and varying only the validator,
Guardrails~AI's default configuration leaves 35.0\,\% of responses unfaithful
and our deterministic validators, in the same loop, leave 0/200. A third arm
puts the toolkit's \emph{own} generic acceptable-values check on our side of
the line, with the list built from $E$ at call time, and it also reaches
0/200 --- so what does the work is not our validator but binding the
admissible set to the evidence at call time, and the claim is stated that way
(Section~\ref{sec:rq3}).
\item \textbf{A decomposition of the failure, and the finding that its halves
do not co-vary consistently.} Separating \emph{invented} from \emph{misfiled}
entities
is the intrinsic/extrinsic distinction~\cite{maynez2020faithfulness} applied
inside one measured channel; what is new is empirical, not conceptual --- the
two sub-rates are close to unrelated across wordings and invert at the
extremes, so the wording that looks safest on the blended metric is the one
inventing most (Sections~\ref{sec:rq1} and~\ref{sec:rq4}).
\item \textbf{A pre-registered downstream benchmark whose two added arms each
attack our own attribution}: 175 scored runs over four models and three
datasets. Three arms were frozen before execution. The fourth separates the
tool's findings from the extra attempt they arrive with (amendment~A8); the
fifth separates them from the vocabulary of the outcome measure
(amendment~A17), and it is the arm that removed our causal claim on the
checklist and exposed a Goodhart effect in the checklist itself. Each was run
only after its amendment, including the adverse outcome, was written down
(Section~\ref{sec:rq5}).
\item \textbf{A replication package} containing every emitted script, every
model reply, and one record per live response --- 3{,}800 of them --- together
with the frozen protocols, the amendment log, the two independent
implementations of the downstream scorer, and the seven faults --- six defects
and one non-reproduction --- that we found in our own instruments while running
the study.
\end{enumerate}

\section{Background and Related Work}\label{sec:related}

\subsection{Hallucination and faithfulness}

Ji \emph{et al.}~\cite{ji} survey hallucination across generation tasks and
separate intrinsic from extrinsic failures; Huang \emph{et al.}~\cite{huang}
give an LLM-specific taxonomy. Xu~\cite{xu2025openworld} argues hallucination
is unavoidable for LLMs under an open-world assumption while noting that a
closed world admits mitigation. Evidence-closed narration is a concrete,
shipped instance of such a closed world, and the constructive complement to
that argument: the mitigable case is not merely admitted but eliminated on the
channels we verify.

The failure we target is extrinsic in that taxonomy, but with structure the
general problem lacks --- the source is a finite, machine-enumerable
dictionary, so the check is decidable rather than open-world. Luo
\emph{et al.}~\cite{luo2026removal} use the same soundness and incompleteness
vocabulary for a model's own explanations and repair by removal; the object
there is the model's reasoning rather than a deterministic tool's measurements,
and the intervention is on the input rather than the output.

\subsection{Agents, tool use, and what they leave unspecified}

ReAct~\cite{react} interleaves reasoning with tool calls, Toolformer~\cite{toolformer}
teaches a model when and how to call, and tool-integration
standards~\cite{mcp} make third-party tools discoverable over one protocol. All
of this governs how an agent \emph{acts}. None of it constrains what the agent
may afterwards \emph{say} about a tool's output. Provenance surveys
reconstruct evidence-support relations from execution traces after the
fact~\cite{wang2026agenttraces}; Ng \emph{et al.}~\cite{ng2026runtimecontract}
argue independently that agent safety belongs in a \emph{runtime contract} and
back it with an audit of agents claiming work they did not do. We read that
framing as convergent rather than ours, and instantiate one such contract in
production. The contract lives at exactly the unspecified boundary those works
identify.

\subsection{Constrained and structured generation (closest prior art)}

Outlines~\cite{outlines} casts guided decoding as a finite-state machine.
LMQL~\cite{lmql} adds declarative constraints over a typed grammar.
Grammar-constrained decoding~\cite{gcd} guarantees grammatical validity without
fine-tuning, input-dependent grammars included. Guidance~\cite{guidance} pushes
JSON-schema and regex constraints to the token level, and provider APIs
validate tool calls against a declared schema~\cite{structured}.

We do not claim that varying a constraint with the input is new; \cite{gcd}
already does it, and CHyD~\cite{signe2026chyd} goes further, restricting
generation to spans present in the retrieved context so that any quoted span
appears verbatim in the source. CHyD is also the worked example of the
constraint we operate under: it needs logit access, which is exactly what a
commercial endpoint withholds. What remains different is what the domain is
bound to, \emph{when} it is bound, and who enforces it. Ours comes from a
deterministic evidence producer and is bound \emph{at call time} --- not at
curation time, as in EG-VAR's offline-audited lifts from data to formal
claims~\cite{ren2026egvar}, and not at decode time.

The closest work shares our term and much of our structure, and we name it
first. \textbf{EviBound}~\cite{chen2025evibound} --- \emph{Evidence-Bound
Autonomous Research} --- governs an autonomous research agent with two gates:
an approval gate that validates acceptance-criteria schemas before code runs,
and a verification gate that queries the MLflow API afterwards for a run id,
the required artifacts and a \texttt{FINISHED} status, optionally checking the
metric values named in the criteria. Retries are bounded and
confidence-gated. It reports 0\,\% hallucination on eight tasks against a
100\,\% prompt-only baseline, in the ML-pipeline domain, eleven months before
the measurements reported here.

The two-gate shape, the bounded retry, the deterministic post-check against a
machine-queryable producer and the numeric comparison are all held in common,
and a reader should know that before reading our contribution claim. The
difference is the object under verification. EviBound asks whether \emph{the
work was done}: does the run exist, are the artifacts present, does the
recorded metric meet the stated criterion. We ask what may be \emph{said}
about work that was done: which entities a narration may cite, which measured
quantities it may assert, and whether it addressed the finding that matters.
An EviBound-style gate would pass a report that is fully backed by a completed
run and still names a column the dataset does not contain, because no artifact
is missing. That is the gap this contract closes, and it is narrower than the
one our own earlier framing implied.

With that named: to our knowledge no prior work binds the narrator's
admissible \emph{citation} domain to a deterministic evidence producer at call
time and then re-verifies both the numeric content of each claim and the
coverage of the top-ranked candidate in code the provider does not control.
Contemporary systems occupy the remaining components separately. FAX~\cite{kim2026fax} decomposes an answer into atomic claims and
retains, removes, or omits each before the user sees it --- the same gate
position as Tier~B, and behaviourally the same strip-versus-omit split --- but
decomposition and status assignment are performed by an LLM, the verdicts are
categorical rather than numeric, and no coverage requirement is imposed.
EBTE~\cite{zhu2026ebte} verifies typed \emph{action} claims server-side without
trusting model rationales; the object is what an agent proposes to do, checked
before execution, rather than what a tool measured, checked after generation.

We therefore do not claim provider-independent enforcement as a novel
component: it is a requirement this setting imposes, already met by EBTE and by
the validate-and-reask toolkits Guardrails~AI~\cite{guardrailsai} and NeMo
Guardrails~\cite{nemo}, which ship the same outer loop as general-purpose
infrastructure. ProvenanceGuard~\cite{alvarez2026provenanceguard} is that
family's claim-level member, scoring support with NLI over captured tool traces
to catch cross-source misattribution; our single-source setting makes
attribution trivial and lets each verdict be exact rather than model-scored.
HALO~\cite{raduta2026halo} argues the same thesis at the architecture level,
without measurements.

What is left unoccupied, and what Section~\ref{sec:rq3} measures rather than
asserts, is numeric claim-value checking against a deterministic producer
together with completeness against a ranked anchor, over a decidable
faithfulness class, with the strip-versus-flag semantics
Proposition~\ref{prop:asym} shows is forced rather than user-authored. One
terminological caution: the Narration Gap~\cite{huang2026narration} shows a
solver's guarantee is lost in the narration step and proves a monitor/enforcer
equivalence, but its \emph{completeness} names a monitor property --- catching
every flipped conclusion --- not coverage of an anchor within a response, and
its enforcer works by removing the LLM from the answer path, which is
unavailable here because the narration \emph{is} the product.

\subsection{Code assistants, ML tooling, and the data-to-text ancestry}

Foundation models trained on code~\cite{codex} power widely used assistants
that still resolve only a fraction of real-world issues~\cite{swebench}.
ETF~\cite{maharaj2025etf} detects hallucinated entities in code summaries by
extracting them with static analysis and then mapping and verifying them with
an LLM, reaching 73\,\% F1; a detector that is itself a model leaves a
residual, which is precisely what a decidable check removes.

Profiling libraries~\cite{ydata} do not know what a target column is.
Experiment trackers~\cite{mlflow,tensorflow} record metrics without
interpreting them. Automated model search~\cite{autosklearn} picks estimators
without saying why. LeakageDetector~2.0~\cite{truong2025leakagedetector} is the
closest existing tool to the leakage check we guard, and it ships an
LLM-driven guidance path over the detector's output: exactly the ungoverned
narration surface this contract governs.

Nor are our two verified channels new. Entity-centric table-to-text work has
measured hallucinated-entity ratio and source-record coverage for half a
decade~\cite{liu2021entitycentric,dhingra2019parent}. What changes in an
evidence-closed setting is that both become decidable, so they can be
\emph{enforced} rather than scored. mlcompass layers a state-carrying advisory
surface over the same artifacts; what this paper contributes is the reliability
contract on that surface, not the tool surface itself.

\section{Evidence-Closed Narration and Two Facts About It}\label{sec:theory}

\subsection{Why decidability is the load-bearing property}

In an open-world setting, deciding whether a sentence is faithful to a corpus
requires a model of the world. In an evidence-closed setting it does not,
because the world is a dictionary. Concretely, in the leakage investigation
this paper studies, the deterministic layer produces an evidence dictionary
$E$ containing: the suspicious metric and its value; per-feature correlations
against the target $y$ --- of $\rho_P$ and $\rho_S$, whichever has the larger
absolute value, \emph{with its sign preserved}, so a strongly negative
association is reported as negative and not as its magnitude; a ranked
candidate-leak set
$C = \{\, c : \max(|\rho_P(c,y)|,|\rho_S(c,y)|) \geq 0.99 \,\}$; and the
perfect-match rate $P(\hat{y}=y)$.

Reporting Spearman beside Pearson is deliberate rather than decorative.
Monotone target transforms ($\log y$, $\sqrt{y}$, $\alpha y + \beta$) pull
$\rho_P$ down while $\rho_S$ stays at $1.0$, so the log-target leak in our own
synthetic frame sits at $\rho_P = 0.93$ against $\rho_S = 0.999$ and would
slide under a Pearson-only filter. The evidence
dictionary is the product of a pipeline that has to be right about this before
the narrator is asked to say anything at all.

\subsection{Verification is linear-time}

\paragraph{Admissible domains are per field, not per response.} A single
entity universe $A_E$ --- every string the evidence mentions --- is the obvious
formalisation and it is the wrong one. Under it, a response whose
\texttt{column} field reads \texttt{r2} is sound, because \texttt{r2} is in the
evidence: it is the name of the suspicious \emph{metric}. Section~\ref{sec:rq1}
reports that this case, not invention, is what the unconstrained narrator
actually does, and a flat membership test cannot see it. We therefore index the
admissible set by the field a token appears in. Writing $F$ for the schema's
reference-bearing fields,
\[
A_{E,f} \subseteq A_E \quad \text{for each } f \in F,
\qquad
A_E \;=\; \bigcup_{f \in F} A_{E,f},
\]
and in the leakage contract
\[
F = \{\texttt{columns\_referenced},\;
      \texttt{claims[].column},\;
      \texttt{claims[].statistic}\},
\]
with $A_{E,\texttt{column}}$ the frame's columns, $A_{E,\texttt{statistic}}$
the statistic names the evidence carries, and the two disjoint. A token is
\emph{misfiled} exactly when it is in $A_E$ but not in $A_{E,f}$ for the field
$f$ that carries it, and \emph{invented} when it is in neither. The distinction
is definitional here and measurable in Section~\ref{sec:rq1}; it is also what
Tier~A binds, since the enum attached to a field is $A_{E,f}$ and not $A_E$.

\begin{proposition}[Linear-time verification]\label{prop:linear}
Let $E$ define field-indexed admissible sets $\{A_{E,f}\}_{f \in F}$ with
$m = \sum_{f} |A_{E,f}|$, and a claim table $V_E$ keyed on
(column, statistic). Deciding faithfulness of a structured response $r$ ---
field-typed entity membership, value tolerance, and anchor coverage --- takes
$O(|r|)$ expected time after $O(m + |V_E|)$ preprocessing.
\end{proposition}

\begin{proof}
Hash each $A_{E,f}$ and the table $V_E$ once, in $O(m + |V_E|)$. Entity
soundness is $|r|$ membership tests, each against the set indexed by the
field the token occupies; value soundness is one lookup keyed on
(column, statistic) and one comparison per claim; completeness is one
membership test. Each is $O(1)$ expected under hashed lookup with keys of
bounded length.
\end{proof}

The proposition is not deep, and its shallowness is the point: it is the
formal statement of why simple checks suffice here, and therefore of why the
guarantee can be absolute in a setting where decode-time machinery cannot be
attached at all. What is not shallow is the indexing. An earlier version of our
own scorer keyed $V_E$ on the column alone and compared every claim against
that column's correlation whatever statistic it named; Section~\ref{sec:instruments}
reports what that cost.

\subsection{Repair is asymmetric, and one direction is unsafe}

When a check fails, the contract must do something. It strips unsound content
and merely flags a persistent omission. That asymmetry looks like a preference
and is not.

\begin{proposition}[Repair asymmetry]\label{prop:asym}
Call a repair \emph{safe} if it only deletes content. Soundness is
safe-repairable: the projection $\Pi_E(r)$ that deletes out-of-evidence
entities and out-of-tolerance claims lands in the sound set for every $r$ and
is the identity on sound responses. Completeness is not safe-repairable: it is
an existential requirement, so any repair must add a reference the model did
not produce.
\end{proposition}

\begin{proof}
Deletion preserves membership and tolerance constraints and can remove every
violating element, so $\Pi_E(r)$ is sound, and $\Pi_E$ is idempotent.

For completeness, the second claim needs its premise stated, because one
deletion does appear to help and does not. Coverage of $a^{*}$ is required
only of a \emph{committed} response, so deleting the verdict would discharge
the obligation. Two things rule it out, and only the second is structural.
The schema makes \texttt{verdict} a required field, so the projection would
leave the response ill-formed. Substituting \texttt{cannot\_determine} keeps
it well-formed, and ruling that out needs a second premise: that every field
of the payload speaks in the narrator's voice, so a system-chosen abstention
attributes an epistemic stance the model did not take. Both premises are
stipulations of this contract, and we mark them as such rather than as facts
about narration --- our own renderer labels unverified content
(Section~\ref{sec:contract}), and a contract that labelled a forced abstention
the same way would escape the second premise and could discharge coverage by
deletion. We did not build that contract, because a labelled abstention still
occupies the verdict field a reader acts on. Given both premises, every
remaining repair inserts an anchor reference absent from $r$. Hence,
\emph{relative to a schema that requires a verdict and attributes every field
to the narrator}, soundness is enforceable by construction and incompleteness
can only be detected, re-prompted, and flagged.
\end{proof}

\paragraph{What the proposition is, and what it is not.}
Proposition~\ref{prop:asym} is a monotonicity argument on a finite object.
Deletion moves only downward in the lattice of response content; the coverage
requirement is existential and therefore monotone upward; the two never meet.
That is the whole of it, and it needs nothing stronger.

We say this because the natural stronger framing is available and is wrong.
Tier~B is an execution monitor, and Schneider~\cite{schneider2000enforceable}
characterises what a monitor whose only intervention is to halt can enforce:
the safety properties, and --- once computability is imposed --- not all of
those~\cite{hamlen2006computability}. Ligatti, Bauer and
Walker~\cite{ligatti2005edit} refine this into a hierarchy in which insertion
enforces policies suppression cannot. It is tempting to read entity and value
soundness as safety and anchor coverage as liveness, and to inherit the
impossibility. The reading does not hold. Safety and liveness are defined over
\emph{infinite} executions, and a liveness violation is exactly one that is
never finitely refutable~\cite{alpern1985liveness}; a narration response is
finite, and Proposition~\ref{prop:linear} shows anchor coverage is decided by
a single membership test. Schneider's monitor cannot enforce liveness because
it never observes the violation. Ours observes it and re-prompts on it. The
two impossibilities have different causes, so we use the enforcement
literature for its intuition and not as a proof.

What the narration setting does add is a restriction on the \emph{remedy},
running opposite to the security case. There, insertion is simply a more
powerful primitive. Here it is \textbf{inadmissible}: an inserted anchor
reference is content attributed to a speaker who did not produce it, the
precise failure the contract exists to prevent. Grading a monitor by what it
is \emph{permitted} to do rather than what it \emph{can} do is not new ---
Khoury and Hall\'e~\cite{khoury2015partial} organise the action universe into
a lattice of control levels, building on the controllable versus
only-observable split of Basin \emph{et al.}~\cite{basin2013revisited}. What
we add is narrow and specific: the ground for placing anchor insertion outside
the permitted set is that the monitor's output is \emph{speech}, and an
insertion into speech is a fabricated attribution rather than a corrective
action.

\paragraph{This ground is contested, and we name the works that contest it.}
A live line of research performs exactly the insertion we rule out and treats
it as correct. RARR~\cite{gao2023rarr} post-edits model output to repair
unsupported content while preserving the original as far as possible. Closer
still, the Narration Gap's Corollary~3~\cite{huang2026narration} shows that a
sound and complete monitor yields a sound enforcer, built from it --- and
Proposition~\ref{prop:linear} hands us precisely such a monitor for anchor
coverage. We are not contradicting that result. We are declining its
conclusion by dropping a hypothesis it does not need: their enforcer replaces
the narrated conclusion outright, which is available to them because the
narration is not the product. Here it is. An enforcer that substitutes its own
text has not repaired the narrator's answer; it has replaced the narrator.
Whether that trade is worth making is a design question, and a reader who
answers it differently from us gets a different contract rather than a broken
one.

Removal-based repair of a model's own explanations~\cite{luo2026removal}
follows the same instinct without the asymmetry argument.

\section{The Artifact: A Two-Tier Evidence-Bound Contract}\label{sec:contract}

\subsection{Architecture and the trust boundary}

\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{fig1_contract.png}
\caption{The evidence-bound contract. The deterministic evidence producer
emits $E$; Tier~A binds the tool schema's enums to $E$ at call time; Tier~B
re-checks the returned answer in plain code on three channels, retries with
the offending items named, and after the budget strips unsound content and
flags a persistent omission. The dashed boundary encloses the narrator and
nothing else: it is the only untrusted component, and every arrow crossing the
boundary is contract traffic. Three annotations mark where the guarantee
stops. The producer is \emph{trusted and never verified}: the contract starts
below it. The free-text field reaches the user too, marked unverified, so the
guarantee covers channels and not the screen. And the band at the foot states
the scope that is easiest to over-read --- the response is guaranteed
consistent with $E$, and $E$ is not guaranteed to be consistent with the
world.}
\label{fig:contract}
\end{figure}

Figure~\ref{fig:contract} draws the system the way the contract sees it, and a
trust boundary splits it in two. On one side is everything deterministic: the pure-Python evidence producer, the dictionary $E$, the
Tier~B verifier, and the user-facing output, all plain code. On the other is
the \emph{LLM narrator}, which we treat as untrusted regardless of who serves
it. Every arrow crossing the boundary is contract traffic. Outbound, Tier~A
binds the tool-schema enums to $E$ at call time. Inbound, the narrator's
\texttt{submit\_investigation} payload enters only through Tier~B
verification, and on a violation the corrective retry crosses back with the
offending items named.

Inside mlcompass the boundary sits within a larger system: eleven pipeline
tools behind a CLI, a tool-integration server~\cite{mcp}, an autonomous agent,
and editor slash commands, all over a persistent project-context folder. Every
one of those surfaces routes through the same deterministic backend. Because
the evidence layer is deterministic and offline, every command works with the
narrator absent; the narrator only adds explanation, and the contract is what
makes that explanation safe to act on.

\paragraph{Where the guarantee does not reach, and why we say so here.} The
contract governs the narrator \emph{mlcompass itself invokes}. On the
tool-server surface there is no such narrator by design: the tools return the
evidence dictionary and the \emph{calling} model --- the one in the user
editor --- is the interpreter. That model is a narrator over the same evidence
and it is entirely ungoverned. So the honest statement is not that the guarded
path is the only path from evidence to user; it is that \textbf{mlcompass
guarantees the faithfulness of its own narration and cannot guarantee anyone
else}. Exporting an enforceable contract across a tool-server boundary --- so
that a client model consuming the evidence is held to the same check --- is
open, and Section~\ref{sec:conclusion} names it as future work.

\subsection{The three layers}

Two words are doing different work and the distinction is worth one sentence
before they are used together. The system has three functional \emph{layers} ---
evidence production, narration, verification. The runtime contract lives across
the last two and contains two enforcement \emph{tiers}, A and B. Layers say
where code sits; tiers say what enforces.

\paragraph{Layer 1: deterministic evidence producer.} A pure-Python module
reads the predictions table and assembles $E$ as described in
Section~\ref{sec:theory}.

\paragraph{Layer 2: strict-prompted narrator.} The narrator receives $E$ with
a system prompt stating the rules in words: cite only items that appear in
$E$; report every correlation as a structured claim copied exactly from $E$;
address the top-ranked candidate before committing to a verdict; abstain
(\texttt{cannot\_determine}) rather than guess. Section~\ref{sec:rq4}
measures what this layer is worth on its own.

\paragraph{Layer 3: the evidence-bound runtime schema.} Answers arrive through
a \texttt{submit\_investigation} tool.

\emph{Tier~A} restricts the tool's \texttt{columns\_referenced} items and
\texttt{claims[].column} field by JSON-schema \texttt{enum}s built at call
time from $E$.

\emph{Tier~B} re-checks the returned tool input in plain code, trusting no
one:
\begin{enumerate}
\item \textbf{Entity soundness} --- every column cited or claimed must be in
the evidence set.
\item \textbf{Value soundness} --- each claim \{column, statistic, value\}
must match the measured value within $0.005$, so two-decimal rounding passes
and a misquote fails.
\item \textbf{Completeness} --- a verdict other than
\texttt{cannot\_determine} must address the top-ranked candidate; an explicit
abstention is not an omission.
\end{enumerate}
A failed check earns the narrator a corrective retry naming the offending
items (budget~2). Whatever is still unsound afterwards is \emph{stripped}, a
persistent omission is \emph{flagged}, and completeness is re-checked after
stripping, because deleting an unsound claim can orphan the anchor.

\subsection{The invariant, and its scope}

The invariant is easy to state, and its scope has to be stated with it:
\emph{within the validated citation and claim channels}, any response the
contract returns cites only entities present in the deterministic evidence and
quotes only values within the declared tolerance of it
($\tau = 0.005$), by construction, whoever the provider is.

The free-text fields carry no such guarantee. The renderer prints them, marked
as unverified, beneath the validated content, and the product also ships a
second, entirely ungoverned prose interpreter over the same evidence, labelled
the same way. We state this in the artifact description rather than only in
the limitations, because a guarantee whose scope is left to the reader is a
guarantee that will be over-read. Membership, comparison, anchor: the checks
are almost embarrassingly small, and that smallness is what decidability buys.

\paragraph{Consistency with $E$ is not correctness.} The invariant is relative
to the evidence dictionary. It says the narrator cannot cite a column the
detector did not measure or quote a number the detector did not produce; it
says nothing about whether the detector was right. If
\texttt{detect\_leakage} mis-ranks a candidate, or the frame handed to it is
the wrong frame, the contract will faithfully narrate a wrong finding and
every check will pass. The deterministic producer is inside the trust
boundary (Figure~\ref{fig:contract}) and is trusted, not verified. Any
transposition of this design to a higher-stakes setting inherits that
boundary, and Section~\ref{sec:discussion} restates it where we discuss one.

\paragraph{What happens when the contract cannot succeed.} ``By construction''
is only worth the failure semantics behind it, so Table~\ref{tab:failclosed}
states them for every way the path can break. The rule throughout: no
structured claim reaches the user unless it passed Tier~B, and an omission
that survives the budget is surfaced rather than silently tolerated. Two
entries are honest weaknesses rather than design choices. An omission cannot
be repaired by deletion (Proposition~\ref{prop:asym}), so it is flagged and
the response is still shown; and an uncaught exception in the provider call
propagates rather than degrading, so the narration panel is absent and the
deterministic evidence panel --- which is printed unconditionally --- is what
the user sees.

\section{Study Design}\label{sec:design}

\subsection{Empirical methodology, named}

Following the ACM SIGSOFT Empirical Standard for engineering research, we
state the method explicitly rather than leaving it to be inferred. RQ1--RQ4
are answered by a \textbf{controlled experiment} over a fixed evidence
dictionary, in which the only manipulated variable is the enforcement
mechanism (RQ1--RQ3) or the wording of an instruction (RQ4). RQ5 is answered
by a \textbf{benchmark} over pinned public datasets with a pre-registered
protocol, a frozen analysis plan, and an amendment log.

\subsection{Subject system and tasks}

The subject is the shipped leakage-investigation path of mlcompass. The
\emph{synthetic} task is a 1{,}000-row frame of fourteen columns --- the
target, the prediction, and twelve candidate features --- carrying a monotone
transformed leak
($\texttt{log\_target\_v2} = \log(y) + \mathcal{N}(0, 0.01^2)$) and a
high-correlation distractor; ten evidence columns, anchor
\texttt{log\_target\_v2}. In every arm the \emph{shipped}
\texttt{detect\_leakage} produces $E$, so the narrator sees exactly the
evidence shape the product produces in the field.

For RQ5 the subjects are three pinned OpenML datasets --- 1464
(blood-transfusion, 748~rows), 1480 (ILPD, 583~rows) and 44031
(california, 20{,}640~rows) --- chosen for task-type spread and issue
diversity. Each is fetched to a checksummed local copy with its OpenML version
and file id recorded, and re-hashed before every run; a changed input is an
error rather than a surprise.

\subsection{Arms}

\paragraph{Contract and baseline arms (RQ1--RQ3), $N=200$ each.} The first
seven arms below were executed in full on \texttt{deepseek-chat} and again on
\texttt{gpt-5.4-mini}, over the same evidence dictionary, the same prompts and
the same scorer --- 2{,}800 responses in total.
Section~\ref{sec:rq3-second} reports the second provider, where the
result is a null and the null is the point. The eighth,
\texttt{A-GR-CHOICES}, was added after those results forced a concession we
had written but not tested; it ran on 2026-09-18 alongside a re-run of the
other seven, and a third provider --- a local \texttt{qwen2.5:7b} under Ollama,
$N=20$ --- ran the same eight
(Section~\ref{sec:rq3-replication}).
\begin{description}
\item[\texttt{A-L1}] The floor: bare prompt requesting the structured fields,
stating no faithfulness rule, open enum-free schema, no verification.
\item[\texttt{A-CONTRACT}] The shipped enforcement stack (Tier~A + Tier~B)
with the faithfulness \emph{prompt removed}, so the contract is compared to
bare-prompt baselines without confounding prompt with mechanism.
\item[\texttt{A-STRESS}] The shipped contract with the bare prompt \emph{and}
the Tier~A enums removed, so the narrator fabricates at its natural rate and
every Tier~B catch becomes observable.
\item[\texttt{A-GR-STOCK}] \textbf{Guardrails~AI} with structural validation
and reask only: what a validate-and-reask toolkit gives out of the box.
\item[\texttt{A-GR-CHOICES}] \textbf{Guardrails~AI running the toolkit's own
generic acceptable-values validator}, with the list of admissible columns built
from $E$ at call time. Their validator, their loop, our binding; the comparison
is what the validator is given rather than who wrote it. It carries no value
tolerance and no anchor requirement, so it is strictly weaker than Tier~B by
construction.
\item[\texttt{A-GR-OURS}] \textbf{Guardrails~AI running custom validators that
encode the Tier~B checks.} Our validator, their loop; the comparison is loops.
\item[\texttt{A-STRICT-STATIC}] The provider's strict structured-output mode
over a static schema carrying types and required fields and \emph{no} column
enum.
\item[\texttt{A-STATIC-ENUM-STALE}] The same strict mode with a column enum
declared once at author time instead of generated at call time.
\end{description}
Reask budget is 2 in every arm that has one, matching the contract's retry
budget, so no arm is given more attempts than another.

\paragraph{Diagnostic arms (RQ4), $N=200$ each, one provider.} Two further
arms separate the tiers. \texttt{A-TIER-A-ONLY} places the evidence-bound enum
in the schema over a bare prompt with no verification at all, isolating what
the binding is worth before Tier~B runs. \texttt{A-CONTRACT-WORST} runs the
full contract under the paraphrase that trips the check most often
unenforced, so the contract meets the wording most likely to break it.

\paragraph{Paraphrase sweep (RQ4), $N=100$ per variant.} The bare instruction
rewritten six ways --- \emph{terse}, \emph{baseline}, \emph{cautious},
\emph{expert}, \emph{helpful}, \emph{mechanical} --- none containing a
faithfulness rule, over the same evidence and tool schema. All six were
written before any measurement and none was discarded afterwards. Only the
wording moves.

\paragraph{Downstream benchmark (RQ5), $3\times4\times3$ per arm.} Five arms,
each asked to write a training script for a pinned dataset. Three were frozen
before execution; \texttt{control+revise} was added as amendment~A8 and
\texttt{control+revise+rubric} as amendment~A17, each run only after its
amendment --- including the outcome that would go against us --- was written
down:
\begin{description}
\item[\texttt{control}] The task, the CSV path, the target, the column
listing, and the list of installed packages.
\item[\texttt{control+revise}] The control prompt, then a second turn saying
only \emph{review the script you just wrote and fix any problems you find in
it}. No findings, no checklist, no concern named.
\item[\texttt{control+revise+rubric}] The control prompt, then a second turn
carrying a frozen constant that names the six scored concerns as questions ---
\emph{does it leak duplicate rows?}, \emph{does it validate?} --- with an
explicit sentence saying the list is generic and nothing at all about the
script just written. It separates ``was told what is wrong'' from ``was told
what we score''.
\item[\texttt{advise}] The control prompt plus an appended block carrying the
verbatim stdout of \texttt{mlcompass advise} on the same training file.
\item[\texttt{advise+audit}] The \texttt{advise} turn, then one revision round
carrying the verbatim stdout of \texttt{mlcompass audit} on \emph{that arm's
own} first-turn script.
\end{description}
The arm list is ordered so that each neighbouring pair isolates one thing:
\texttt{control}$\rightarrow$\texttt{control+revise} isolates the extra
attempt; \texttt{control}$\rightarrow$\texttt{advise} isolates the advice
block; \texttt{control+revise}$\rightarrow$\texttt{advise+audit} isolates what
the tool adds on top of an extra attempt.

\subsection{Measures}

\paragraph{Faithfulness channels (RQ1--RQ4).} Scored on every response that
reaches the user. \textbf{Entity fabrication}: at least one column, cited or
claimed, outside $E$. \textbf{Value fabrication}: at least one claim whose
column is in $E$ but whose value is off by more than $0.005$.
\textbf{Critical omission}: a committed verdict that never references the
anchor. We report Wilson 95\,\% intervals and raw $k/N$ throughout.

Section~\ref{sec:rq1} introduces a decomposition of the entity channel that we
did not have when the study began, and which changed what we believe the
channel measures:
\begin{description}
\item[invented] a name appearing \emph{nowhere} in $E$ --- the phantom entity
as the literature defines it;
\item[misfiled] a name that \emph{is} in $E$ but is not a column, written into
a field that holds only columns.
\end{description}
Both are contract violations and Tier~B rejects both identically; only the
first is a hallucination. A third outcome is excluded from all three counts:
\textbf{artifacts} --- a claim whose column field is \texttt{null}, which
stringifies to a name nobody owns, and several real column names delivered in
one field. Both are faults, neither is a citation, and counting either as an
invention asserts the narrator produced a name the data does not contain.

The value channel splits on the same principle:
\begin{description}
\item[misquoted] the evidence carries this quantity for this column and the
narrator quoted it wrongly --- the value fabrication the contract is built to
catch;
\item[unverifiable] the evidence carries no such quantity for this column, so
there is nothing to compare against. Not a misquote, and reported separately.
\end{description}
Keying the check on (column, statistic) rather than on the column alone is a
correction made during this study; Section~\ref{sec:instruments} reports what
it was doing before. The blended \textbf{entity} flag retains its original
meaning --- the disjunction of invented and misfiled --- so no comparison in
this paper moves because of the decomposition.

\paragraph{Downstream measures (RQ5).} A deterministic six-item checklist over
the emitted script --- \texttt{no\_seed}, \texttt{leak\_fit\_before\_split},
\texttt{leak\_duplicate\_rows}, \texttt{wrong\_metric\_for\_imbalance},
\texttt{no\_validation}, \texttt{target\_in\_features} --- plus whether the
script runs, and a held-out score obtained by the harness loading the model
the script saved and predicting on data the script never saw.

\subsection{Controls that the design turns on}

\paragraph{Holdout splitting on duplicate groups.} The pinned datasets contain
duplicate rows (125 retained inside train on OpenML~1464). A plain split put
71 of 187 holdout rows verbatim into train, so a script that correctly
de-duplicated scored \emph{below} one that did not. We split on groups of
identical rows: no holdout row appears verbatim in train, while duplicates
remain inside the training file, so the score is honest and the defect stays
reachable. This is recorded as amendment~A4 and is the single change that most
affected the benchmark's validity.

\paragraph{Stating the execution environment.} Every arm's prompt carries the
same generated list of importable packages. Without it, \texttt{runs\_at\_all}
partly measured package availability, and the confound had a direction:
advise output recommends handling class imbalance, which points at exactly the
resampling libraries most likely to be absent, so silence would have penalised
the treatment arm for taking the intervention's advice (amendment~A5).

\paragraph{Transport failures are not data.} A failed API call is excluded
from $N$ and reported per cell, rather than being counted as a clean
non-fabricating response. Section~\ref{sec:instruments} describes the incident
that makes this rule load-bearing.

\subsection{Pre-registration and amendments}

The downstream protocol was frozen before execution, including the arms, the
datasets, the models, the repetition count, the seeds, and --- in
Section~6 of the protocol --- the outcome we would regard as publishable if
the metric did not move. Every deviation is recorded as a numbered amendment
with its reason; seventeen amendments (A1--A17) are in the replication package,
and the ones that changed a conclusion are discussed in
Section~\ref{sec:instruments} rather than buried in an appendix.

Seventeen is enough amendments that the reader is owed the composition rather
than the count, so each carries a classification and the log is summarised in
Section~\ref{sec:threats}: twelve are infrastructure or reporting and cannot
move a result, three are instrument repairs reported as corrections, and two
add an arm. Both added arms exist to attack our own attribution, both were
written with their adverse outcome stated before they ran, and the second one's
adverse outcome is what happened (Section~\ref{sec:rq5-rubric}). What was never
amended is the set of scored rules, the datasets, the models, the repetition
count or the seeds.

\subsection{Models and generation settings}

The seven-arm battery runs on DeepSeek \texttt{deepseek-chat} and on
\texttt{gpt-5.4-mini}, both over OpenAI-compatible endpoints with JSON-schema
tool use. The paraphrase sweep and the two diagnostic arms are
\texttt{deepseek-chat} only. RQ5 runs a four-model panel:
\texttt{deepseek-flash}, \texttt{ministral-8b-latest},
\texttt{qwen2.5:7b} served locally by Ollama, and
\texttt{gpt-5.4-mini}. Temperature is fixed at $1.0$ on every arm and every
provider, sent explicitly in the request body rather than left to a provider
default, and recorded in every run record. Results are reported per model and
never pooled.

\paragraph{Why temperature 1.0.} A practitioner tuning for reliability would
lower it, and a reviewer is right to ask why we did not. Three reasons, and
one admission. It is the default of every endpoint we call, so it is what a
narrator gets unless someone decides otherwise; lowering it would make the
baseline a configuration we chose rather than the one a caller inherits. It is
also the setting the shipped narrator uses, and the contract arms measure that
narrator rather than a tuned variant of it. And it is the conservative choice
\emph{against} our own thesis in the only direction that matters for the
enforcement arms: whatever sampling does to first-attempt propensity, a
contract arm reading 0/200 at the noisiest temperature cannot be an artefact
of a quiet one.

The admission is that this cuts the other way for the \emph{baseline} rates.
\texttt{A-L1}'s 42.0\,\% is a property of this temperature as much as of this
model and this date, and a low-temperature baseline would very likely read
lower. We did not measure the sensitivity, and a reader should treat every
non-zero rate in Sections~\ref{sec:rq1} and~\ref{sec:rq4} as conditioned on
$T=1.0$. That the comparisons survive this is the point of
Section~\ref{sec:rq3-second}: the rate is not stable across models or dates
either, and the contract does not depend on which value it takes.

\section{RQ1: How Does an Unconstrained Narrator Actually Fail?}\label{sec:rq1}

\subsection{The blended rate, and why it is not the answer}

On the bare arm the narrator produced an out-of-evidence entity in
\textbf{42.0\,\%} of 200 responses (84/200, Wilson 95\,\% CI
$[35.4, 48.9]$). Read as published, that is a fabrication rate, and it is the
kind of number this literature reports.

It is not a fabrication rate. Decomposing every flagged response across all
seven arms of the battery --- 1{,}400 live responses --- gives
Table~\ref{tab:decomp}.

One property of that decomposition has to be stated before the table is read.
The channels are scored on the response that \emph{reaches the user}, so in the
four arms where an enum or a verifier intervenes, what is scored is the
repaired response. Flagged entities can therefore only appear in the three
unconstrained arms, and they do: the 162 flagged responses are exactly
$84 + 70 + 8$. The zero in the \emph{invented} column is a property of those
600 user-facing responses plus 800 in which nothing out-of-evidence survived to
be counted. Section~\ref{sec:rq4} measures the unconstrained case directly,
over 600 further responses, and finds invention there.

\textbf{Across the battery's 1{,}400 live responses, not one out-of-evidence
entity reaching the user was invented.} All but one flagged entity is
\texttt{r2} --- the name of the suspicious metric, which $E$ carries as
\texttt{suspicious\_metric.name} and which the model wrote into

\texttt{perfect\_match\_rate}, an evidence field misfiled the same way.

\subsection{What this changes, and what it does not}

It changes what the number may be called. The failure mode this literature
names, and which we had set out to measure, is \emph{phantom-entity
fabrication}: ``a column the data does not contain''. On this evidence that is
not what the 42.0\,\% counts.

The distinction is not new and we do not claim it. In Maynez \emph{et al.}'s
terms~\cite{maynez2020faithfulness}, a name absent from $E$ is an
\emph{extrinsic} hallucination and a real evidence name asserted as a column is
an \emph{intrinsic} one --- content drawn from the source that contradicts it.
Our entity channel had been blending the two, and Section~\ref{sec:related}
compounded the error by calling the target failure extrinsic. What is new here
is not the taxonomy but the measurement: the two behave differently enough
under paraphrase that one cannot be used to estimate the other
(Section~\ref{sec:rq4}). A reviewer with these logs
would say the rate measures a category error, the model naming the metric it
was handed, and on this battery they would be right.

It does not change three things.

First, \textbf{it remains a contract violation.}
\texttt{columns\_referenced} means columns of the data. A consumer acting on
\texttt{r2} --- dropping it, correlating it, listing it as a leak candidate ---
acts on something that does not exist as a column. Rejecting it is correct
behaviour, not over-eager behaviour.

Second, \textbf{it does not affect any arm comparison.} Every arm faced the
same failure; Section~\ref{sec:rq3} separates them from 42.0\,\% to 0/200
regardless of the provenance of the name.

Third, and most importantly, \textbf{invention is not absent in general} ---
only in the responses that reached the user here. Section~\ref{sec:rq4} finds
it, at a much lower rate and, unexpectedly, moving in a different direction
from the blended rate.

A limitation of the instrument belongs here rather than in
Section~\ref{sec:threats}, because it bounds what the word \emph{invented} can
mean. The synthetic frame has fourteen columns; $E$ carries the ten
highest-ranked feature correlations, so \texttt{feature\_3} and
\texttt{feature\_11} are real columns of the data that the evidence does not
contain. A response citing either would be scored as an invention under our
definition --- ``a name appearing nowhere in $E$'' --- though the column
exists. Neither occurred in any of the 3{,}800 responses, so no reported
number is affected, but the measure is \emph{out-of-evidence}, not
\emph{non-existent}, and the two coincide here only by luck.

\subsection{The zeros are not cheap}

Misquotation of a quantity the evidence carries, and critical omission, were
0/200 in all seven arms. So was the unverifiable-claim channel, and that one is
closed by construction rather than by luck: the contract's schema admits a
single statistic name (Section~\ref{sec:rq4}). A narrator that escaped into
abstention would score zero on every channel for free, so we measured whether
it did (Table~\ref{tab:abstain}).

\begin{table}[t]
\caption{The silent channels are silent because the narrator committed, not

\subsection{It is the binding, not the validator and not the loop}

The two rows to read together are \texttt{A-GR-STOCK} and \texttt{A-GR-OURS}.
\textbf{The same toolkit, the same reask loop, the same budget of two, the same
model, the same prompt: 35.0\,\% against 0/200.} The only thing that changed is
what the validator checks.

Guardrails' stock configuration validates structure. Nothing told it which
column names the evidence contained, so nothing in it could check them.

That is a claim about a \emph{default configuration}, not about the toolkit's
capability, and we state it that way. Guardrails ships a hub validator taking
a list of acceptable values, and a competent user could construct that list
from $E$ at call time and attach it to the field. Indeed
\texttt{A-GR-OURS} \emph{is} that user: our validators run inside their loop.
So the comparison is not ours-against-their-ceiling; it is
\textbf{evidence-bound validation against what a practitioner gets out of the
box}, which is the toolkit's out-of-the-box structural
configuration. We have no survey data on how often that configuration is the
one deployed, and do not claim any.

\paragraph{We tested that concession, and it narrows the claim further.}
Writing that a competent user \emph{could} construct the list is cheap. The
\texttt{A-GR-CHOICES} arm is that user: the same Guard, the same open schema,
the same reask budget of two, the same transport and the same scorer, with one
generic acceptable-values check on \texttt{columns\_referenced} whose list is
built from $E$ at call time. It carries none of Tier~B --- no value tolerance,
no anchor requirement, no per-claim checking --- and is therefore strictly
weaker than our validator by construction.

\textbf{It reaches 0/200, with 88 catches.} A generic membership test, given
the right list at the right moment, is enough.

That result is the reason the claim below is narrower than the one an earlier
draft made. \emph{The validator is not what does the work either.} What does
the work is \textbf{binding the admissible set to the deterministic evidence at
call time}, and the paper's central empirical claim is that nothing in a
validate-and-reask toolkit's default configuration does that, while anything
that does --- a generic choice list, our three channels, or a schema enum ---
lands in the same place.

The three Tier~B channels still earn their place, and this arm shows where:
\texttt{A-GR-CHOICES} checks columns and nothing else, so a misquoted value or
an unaddressed anchor passes it. On this task neither occurs, which is why the
two arms tie. Section~\ref{sec:rq4} measures a channel where they would not:
unverifiable statistics run at up to 45 per 100 under paraphrase, and a choice
list on the column field cannot see them.

A further reason to state the claim this way rather than as ours-against-theirs
is what the toolkit does and does not install. A fresh
\texttt{pip install guardrails-ai==0.11.0} registers \emph{no} validators at
all: the registry is empty and the hub namespace exports nothing, so every
validator, the acceptable-values check included, is a separate fetch from a
remote service. ``Out of the box'' is therefore a stronger statement than we
first made --- out of the box there is no faithfulness validator to configure.

\texttt{A-STRESS} reaching 0/200 with the enum removed says the same thing
from the other side. Post-generation verification alone suffices, which is what
makes the guarantee independent of the provider. Tier~B fired on 12 of 200
responses in that arm and passed none of them through.

\subsubsection{The comparison replicates; the rate does not}\label{sec:rq3-replication}
All eight arms of Table~\ref{tab:arms}
were re-run on 2026-09-18, three days after the numbers above, same model name,
same evidence hash, same prompts, same scorer, $N=200$ per arm --- 1{,}600
further live responses. Every
enforcement conclusion holds: \texttt{A-GR-CHOICES}, \texttt{A-GR-OURS},
\texttt{A-CONTRACT}, \texttt{A-STRESS} and \texttt{A-STATIC-ENUM-STALE} are all
0/200 again. The \emph{rates} do not hold. \texttt{A-L1} reads 43.0\,\%
[36.3, 49.9] against 42.0\,\%, which is a replication; \texttt{A-GR-STOCK}
reads \textbf{43.5\,\%} [36.8, 50.4] against 35.0\,\%, which is not.
\texttt{A-STRICT-STATIC} reads 7.0\,\% against 4.0\,\%.

Nothing was changed between the two runs but the date. We report it here rather
than in a footnote because it is the third independent demonstration of this
paper's own thesis --- alongside the second provider in
Section~\ref{sec:rq3-second} and the local model below --- and because a reader
who took 35.0\,\% as a property of Guardrails~AI would be wrong by eight and a
half points within a week.

A third model makes the same point from the other direction. The battery was
also run on a local \texttt{qwen2.5:7b} under Ollama ($N=20$ per arm), where
every arm scores 0/20 except \texttt{A-STRICT-STATIC} at 2/20. That is a third
provider and a third floor at which there is nothing for any mechanism to
prevent.

\texttt{A-GR-OURS} is the instructive middle: Tier~B's checks caught 86
violations across 84 responses inside Guardrails' loop, and the user-facing
rate was still 0/200. The loop is a perfectly adequate delivery vehicle for a
decidable check. It just does not contain one.

\subsection{Provider strict mode is close, and uncertifiable}\label{sec:rq3-degenerate}

\texttt{A-STRICT-STATIC} reaches 4.0\,\%: a static schema with types and
required fields and no column enum leaves the column domain unconstrained, so
any out-of-domain name decodes successfully. That it lands at 4\,\% rather than
42\,\% is evidence that a schema \emph{steers} a model strongly even where it
does not constrain it --- the same effect we report for Tier~A in
Section~\ref{sec:rq4}. Steering is not enforcement, and cannot be certified:
it can regress as silently as a prompt.

\paragraph{Three things are called ``valid'', and the arms measure all three.}
The word does most of the equivocating in this area, so Table~\ref{tab:valid}
separates the senses. A payload can parse, and still put a metric name in a
column field. It can carry the right \emph{type} in every field, and still name
a column the dataset does not have. Only the third level --- the field's
admissible set derived from $E$ at call time --- is the one this paper's
guarantee is about, and it is the only one of the three that no schema can
express, because a schema is written before the evidence exists.

The two failure modes of Section~\ref{sec:rq1} sit one level apart, which is
why a single blended rate hid them. A \emph{misfiled} entity is
type-valid and evidence-invalid: \texttt{r2} is a string in a string field, and
is not a column. An \emph{invented} entity is invalid at the evidence level
too, and at no other. Nothing below the third level can tell them apart,
because nothing below the third level knows what the evidence contained.

\subsection{The second provider fails at nothing, and that is the
result}\label{sec:rq3-second}

The battery was re-run on a second provider and a
different model family --- \texttt{gpt-5.4-mini}, same evidence hash, same
prompts, same scorer, same reask budget, temperature 1.0, zero transport
errors. This ran before \texttt{A-GR-CHOICES} existed, so it covers the seven
arms of Table~\ref{tab:arms} other than that one. All seven score
\textbf{0/200}, including \texttt{A-L1}.

The floor arm does not fail. In 199 of 200 responses the model cites exactly
the ten evidence columns and makes ten structured claims (the remaining
response cites two and claims two); it abstains in 0 of 200 and never writes
\texttt{r2} into a column field. Nothing reaches a user that any arm
needed to prevent, so no comparison between arms exists on this provider.

``Nothing to prevent'' would be one response too strong. Tier~B caught a single
first-attempt violation in the \texttt{A-GR-OURS} arm --- an entity and an
omission in the same response --- and repaired it. The verifier is not idle on
this provider; it is close to it, and the user-facing rate is 0/200 because the
verifier ran, not merely because the model behaved.

We report this as a first-class result rather than a footnote, because it is
the strongest argument in the paper for the position the paper takes.

\begin{itemize}
\item \textbf{It voids every rate in Sections~\ref{sec:rq1} and
\ref{sec:rq4} as a claim about ``the bare narrator''.} Those are properties of
\texttt{deepseek-chat} on 2026-09-15. Read as properties of LLMs, they are
wrong by 42 percentage points against a model measured one day later.
\item \textbf{It does not touch the within-provider comparison.}
\texttt{A-GR-STOCK} at 35.0\,\% against \texttt{A-GR-OURS} at 0/200 holds on
the provider where the failure occurs, which is the only place a preventive
mechanism can be compared at all.
\item \textbf{It is the case for structural enforcement rather than measured
compliance.} An engineer who benchmarked prompt-level reliability on
\texttt{gpt-5.4-mini} would measure 0/200 and conclude the problem does not
exist. The same benchmark on another hosted model, the same week, the same
task, measures 42\,\%. A guarantee that holds by construction is worth having
precisely because the rate it replaces is not a stable property of anything.
\end{itemize}

A sharper framing of the paper's own thesis follows, and we adopt it: the
contract's value is not that it lowers a number. It is that it makes the number
irrelevant.

Two caveats. The absence of failure on one model is not evidence it cannot
occur there --- a paraphrase sweep on this provider is future work, and
Section~\ref{sec:rq4} shows wording moves the rate by an order of magnitude on
the model we did sweep. And a 0/200 floor means this provider contributes
nothing to the comparison, so the comparative claim remains single-provider
even though the study is not.

\texttt{A-STATIC-ENUM-STALE} must not be read as a result. On this task the
author-time column list covers 10 of 10 evidence columns, so the arm is
byte-identical to a live enum \emph{by construction}. The harness detects and
reports this degeneracy at plan time. The arm is informative only on a task the
frozen list predates, and no such task is in this battery; the row is printed
for completeness and carries no comparison. We report this rather than quietly
omitting the row, because a 0/200 cell that looks like a win and is an identity
is exactly the kind of number a reader should be warned about.

Three readings.

\paragraph{Wording moves the blended rate roughly eightfold.} From 9.0\,\% to
72.0\,\%, across six variants written before any measurement with none
discarded afterwards, on identical evidence with no faithfulness rule in any of
them. That prompt wording moves a model's behaviour by this much is
established --- Sclar \emph{et al.}~\cite{sclar2024formatspread} report up to
76 accuracy points of spread from formatting alone. What this section adds is
that the phenomenon transfers to a \emph{faithfulness} rate, and that the
sub-channels inside it decouple. A terse instruction almost never trips the check. A mechanical
field-listing instruction almost always does. No obvious feature of the wording
predicts where a variant will fall.

\paragraph{Invention exists here, at an order of magnitude below the
headline.} Five of six variants produced names absent from $E$ entirely --- the
ten columns $E$ carries are \texttt{log\_target\_v2},
\texttt{near\_target\_proxy}, and \texttt{feature\_4} through
\texttt{feature\_10} together with \texttt{feature\_12} --- not
\texttt{feature\_11}, for the reason given below. There is no column called
\texttt{target}, so a response citing
\texttt{[log\_target\_v2, near\_target\_proxy, target]} invented the third.
Phantom-entity fabrication is therefore real and not an artefact of the
scorer. It occurs at 0--7 per 100, not at the 36--72\,\% the blended rate
reports.

\paragraph{The narrator does not misquote numbers; it invents statistics.}
The value channel splits the same way the entity channel does, and the split
is the difference between quoting a quantity wrongly and naming a quantity
that does not exist. Misquotation is rare --- at most one response per hundred
in any variant. Unverifiable claims are not: \textbf{45 of 100} on
\emph{expert} and 26 on \emph{mechanical}, where the narrator attaches a
statistic the evidence does not carry for that column, such as
\texttt{residual\_r2\_after\_leak\_columns\_excluded} or a per-column
\texttt{abs\_corr\_deficit\_from\_perfect}. There is no number to compare
against, which is precisely what makes the claim unfalsifiable to a reader and
worthless to a downstream consumer.

This channel is empty in every arm of the battery, and the reason is
structural rather than fortunate: the contract's tool schema pins the
\texttt{statistic} field to a single admissible value, so under the contract an
unverifiable claim is \emph{not expressible}. It is the clearest measured
effect of Tier~A anywhere in this study, and it is worth being precise about
what kind of enforcement that is --- the enum is declared once at author time
rather than generated from $E$ at call time, so it constrains the
\emph{vocabulary} of statistics, not their binding to evidence. It closes the
channel completely for this task and would not survive an evidence dictionary
carrying more than one statistic per column.

\paragraph{The two entity sub-channels do not co-vary consistently, and at the
extremes they run opposite.} This was not expected and is the sharper finding, and
Figure~\ref{fig:sweep} is where it is visible:

Reading the two columns of Table~\ref{tab:sweep} against each other:
\emph{terse} has the lowest blended rate (9\,\%) and the highest invention
count (7); \emph{mechanical} has the highest blended rate (72\,\%) and one
invention; \emph{baseline} sits at 36\,\% with none at all.

The mechanism is legible. A field-listing instruction drives the model to
enumerate evidence fields, which produces misfiling, not invention. A terse
instruction says little and the model fills the gap from somewhere other than
$E$.

\subsection{Interpretation}

The manuscript's thesis is that a prompt-level defence cannot be certified from
observed compliance. The decomposition makes that claim harder, not softer:
\textbf{you cannot even certify one failure mode from another within the same
prompt.} The wording that looks safest on the headline metric is the one
inventing most. An engineer choosing a prompt by measuring its fabrication rate
would choose \emph{terse} and would be choosing the variant that most often
invents a column that does not exist.

Abstention was checked here too, for the same reason as in
Section~\ref{sec:rq1}, and is 0/100 in every one of the six variants. The low
cells are low because the model cited cleanly, not because it declined to
answer.

Two further diagnostic arms ($N=200$ each, records in the replication
package) pull the tiers apart. Placing the evidence-bound enum in the schema
over a bare prompt with no verification --- Tier~A alone --- drove the rate to
0/200. Running the full contract under the sweep's worst paraphrase, the one
that trips the check 72 times in 100 unenforced, produced zero first-attempt
violations and therefore zero catches: the steering absorbed the worst wording
before Tier~B had anything to do.
Neither observation is a guarantee: steering can regress as silently as
prompting. Together with \texttt{A-STRESS} they give a consistent picture ---
each tier is independently effective in practice, and Tier~B is the only layer
whose protection is certifiable.

Sixteen of the 25-defect fall is \texttt{leak\_duplicate\_rows} alone and
twenty-three of it is that rule plus \texttt{no\_validation}.
\texttt{wrong\_metric\_for\_imbalance} fires zero times in all 143 runs: its
precondition is a minority class below 20\,\%, which is a property of the data
and true of none of the three pinned subjects, so on this panel the instrument
is five items and materially two. We report the checklist as six items because
that is what it is, and this table because a six-item headline over a two-item
effect is the blend Section~\ref{sec:rq1} objects to.

The distribution also decides which part of the result is defensible.
\texttt{no\_validation} is named by the \texttt{val\_split} rule of
\texttt{mlcompass audit}, so the treatment text and the outcome measure share
vocabulary there (Section~\ref{sec:threats}). \texttt{leak\_duplicate\_rows}
is not: no audit rule mentions duplicate rows, and it is the largest single
contributor. \textbf{That is the part of the downstream effect the instrument
did not hand to the treatment.}

\subsection{The extra attempt is worth nothing, and the findings are worth
less than we claimed}\label{sec:rq5-rubric}

The obvious objection to a treatment arm that revises is that it differs from
the control in \emph{two} ways at once: it is told what is wrong, and it gets a
second attempt. Our first version of this benchmark could not separate them,
and the objection was raised in internal review before it could be raised
externally. The \texttt{control+revise} arm exists to answer it.

A second attempt on its own does nothing: $31 \rightarrow 35$, one model down,
one level and two up, noise around no effect.

\paragraph{A fifth arm, and it does not go our way.} That pair separates the
attempt from the findings and leaves a second confound standing, which
Section~\ref{sec:threats} had conceded and not measured: the findings name the
same six rules the outcome is scored on. \texttt{control+revise+rubric} holds
the rubric and withholds the findings. Its second turn is a frozen constant
listing the six scored concerns, each phrased as a question about the concern
and never as a claim about this script, with an explicit sentence saying the
list is generic. It was pre-registered as amendment~A17, and the amendment
recorded before the run that a result near 8 would mean the fall was largely
the rubric and this section's causal claim would have to be rewritten.

It landed at \textbf{1 flagged defect over 32 scored runs}
(Table~\ref{tab:rubric}), against \texttt{advise+audit}'s 8 over 36. Telling
the model what it will be scored on, with nothing said about its own code,
outperforms handing it the tool's actual findings.

\textbf{So the 31~$\rightarrow$~8 fall is not attributable to the tool's
findings on this metric, and we withdraw that attribution.} The
treatment--outcome vocabulary overlap is not a limitation to note in passing;
it is a confound large enough to account for the whole effect on the checklist.

\paragraph{The rubric arm pays where the checklist cannot see.} Every other arm
executes between 78\,\% and 83\,\% of the time. The rubric arm executes 17 of

conditions to satisfy and nothing about its own code, the model writes
something that satisfies the checklist and does not run.

This is Goodhart's law inside our own instrument, and we can measure it only
because the benchmark records execution separately from the checklist.
Section~\ref{sec:threats} argues that six deterministic rules are not code
quality; this is the first evidence in the study of what optimising against
them costs.

On the joint outcome --- runs \emph{and} carries no flagged defect ---
\texttt{advise+audit} is first at \textbf{64\,\%} [48, 78] against the rubric
arm's 44\,\% [30, 60]. Those intervals overlap substantially. At $N=36$ this
design separates the two arms \emph{weakly}, and we claim no more than that:
the tool's findings buy a better joint outcome than the rubric alone, on
evidence that a larger panel could overturn.

\paragraph{What this arm explains rather than removes.} The claim below is that
self-revision repaired nothing. It is true and this arm tells us why. The within-arm view is sharper. Across the
35 runs that produced a defect count on both sides of the revision turn:

unchanged & 33 \\
worse     & 2 \\
better    & \textbf{0} \\
\bottomrule

\textbf{Self-revision without the tool's findings did not repair a single
defect in 35 runs.} The model was handed its own script and asked to find
problems in it, and found none it could act on.

The rubric arm, on the same datasets with the same models, repaired
\textbf{21 of 25} and regressed none. So the reading this result invites ---
that models cannot repair their own code without external feedback --- is the
wrong one, and our own earlier draft made it. The correct reading is narrower:
\textbf{a model asked to review its own script with nothing named fixes
nothing; a model told what to look for fixes most of it, whether or not anyone
tells it what is actually wrong with the code in front of it.}

A net count cannot carry that sentence, because a run that repairs one rule and
introduces another shows no movement. Both sides of the turn are preserved, so
we rescored them rule by rule under the current scorer. Across all 35 pairs,
\textbf{no rule flagged before the revision was clean after it}: 24
\texttt{leak\_duplicate\_rows}, 8 \texttt{no\_validation} and 1
\texttt{no\_seed} persisted unchanged, and the two runs that got worse did so by
introducing \texttt{no\_validation} where the first attempt had none. Zero
repairs, two regressions, thirty-three unchanged. The claim is about individual
defects and not about their sum.

This is a replication, not a discovery, and reads better as one. Huang
\emph{et al.}~\cite{huang2024selfcorrect} show models cannot reliably correct
their own reasoning without external feedback, sometimes degrading; Olausson
\emph{et al.}~\cite{olausson2024selfrepair} find self-repair in code generation
is bottlenecked by the model's ability to critique its own code, and that
improving the critic is what produces the gains. Our contrast substitutes a
\emph{deterministic} critic for a stronger model, on a task where the critic
can be exactly right, and the effect is what that literature predicts.

\subsection{The held-out score shows no consistent improvement}\label{sec:rq5-score}

Across the nine (model, dataset) cells with both ends scored, the held-out
score moved better in three, worse in three, and within $\pm0.01$ in three. No
direction. The spread inside an arm frequently exceeds the gap between arms:
one arm spans $0.2122$ across three repetitions while its median sits $0.0002$
above control.

We state the conclusion at the strength the data supports.
\textbf{No consistent improvement in held-out score could be shown.} That is not the same as showing there is no
effect, and with only 70 of 108 runs carrying a score --- 21 scripts failed to
run, 17 saved artefacts the scorer could not load, and 8 of 36 cells carry no
score at all --- this design cannot establish a null. Section~6 of the frozen
protocol named ``the process improves, the metric does not'' as a probable and
publishable outcome \emph{before any data existed}, and nothing here refuted
it; but a pre-registered prediction that survives is not a measured null, and
we do not report it as one.

seven faults in those instruments while running the study --- six defects and
one non-reproduction --- most of them after results had already been drawn from
them, and all seven are reported here rather than in an appendix because each
changed something a reader would otherwise take at face value.

\subsection{Defect 1: the checklist penalised correct code, in a biased
direction}

The downstream checklist scores the \emph{absence} of every enumerated way of
excluding the target column from the feature matrix. The enumeration did not
include a list comprehension:

\begin{quote}\ttfamily\small
target\_col = "Class"\\
feature\_cols = [c for c in df.columns if c != target\_col]\\
X = df[feature\_cols]
\end{quote}

This script excludes the target and was scored \texttt{target\_in\_features:
yes}. Fifteen of 108 runs carried the false positive. Two further forms were
found later by the same route: a feature list assembled from named constants
(\texttt{FEATURE\_COLS = NUMERIC\_COLS + CATEGORICAL\_COLS}) and a seed hoisted
to a module constant (\texttt{RANDOM\_STATE = 42}, passed in three places,
scored \texttt{no\_seed}).

The shape of the rule is the defect, not any single missing pattern. An
absence-scored checklist has an open-ended form list, so every form nobody
enumerated becomes a false positive on correct code. \textbf{And the bias has a
direction.} Tidier code hoists lists and seeds to constants; a revised script
is a tidier script; so the checker systematically penalised the coding style
that the treatment arms produce.

Corrected against the same bytes --- no model call, no re-execution, dataset
facts read back from each run's record --- across four rescoring passes:

\begin{center}
\begin{tabular}{@{}llrrr@{}}
\toprule
scoring & found by & \texttt{control} & \texttt{advise} & \texttt{advise+audit} \\
\midrule
original                    & ---   & 40 & 31 & 15 \\
after correction 1 (A7)     & review & 35 & 27 &  9 \\
after correction 2 (A11)    & review & 33 & 26 &  8 \\
after correction 3 (A12)    & ours  & 33 & 24 &  8 \\
after correction 4 (A16)    & audit & \textbf{31} & \textbf{24} & \textbf{8} \\
\bottomrule
\end{tabular}
\end{center}

The direction survives all five scorings. Four of the first corrections also
moved toward our hypothesis, and we said so plainly rather than burying it:
false positives concentrate in careful code and the treatment arms produce more
careful code, which is a checkable mechanism rather than an excuse. An earlier
version of this paper closed the paragraph by writing that ``the next
correction that moves these numbers the other way will be the one indicating
the scorer is finally unbiased''.

Correction~4 is that correction. It moves \texttt{control} from 33 to 31 and
leaves both treatment arms untouched, so it \emph{shrinks} the effect we are
arguing for, from a 25-defect fall to a 23-defect one. We report it in the
position the earlier sentence committed us to. Section~\ref{sec:defect6}
describes what it was.

\subsection{Defect 2: the value scorer never read the \texttt{statistic} field}

Each structured claim is a triple \{column, statistic, value\}. The scorer
compared every claim against the \emph{correlation} of its column, whatever
statistic the claim named. On the contract path that is correct, because
Tier~A pins \texttt{statistic} to a single admissible value and a claim there
cannot be about anything else. On every unconstrained arm, where the narrator
chooses the statistic itself, it is wrong.

The cost was a channel that appeared to fire and did not. Re-scoring the
paraphrase sweep, 69 of roughly 85 value-channel flags were claims of the form
\texttt{\{log\_target\_v2, perfect\_match\_rate, 0.0\}} compared against that
column's correlation of $0.9987$ --- and $0.0$ is the correct perfect-match
rate. The scorer was reporting the narrator wrong for being right.

Keyed on (column, statistic), value fabrication in the sweep is 0, 0, 1, 1, 0
and 0 per 100. The reading it replaced --- that this channel stays quiet ---
was substantially correct. What the correction \emph{uncovered} is
Section~\ref{sec:rq4}'s unverifiable channel, at up to 45 per 100, which is a
larger finding than the one it removed.

This defect was found because two readers of an earlier draft disagreed about
what the channel was measuring. One recomputed the rates and said the paper
was wrong to call the channel quiet; the other opened the flagged records. We
record the provenance because the disagreement, not either reader, is what
located it.

\subsection{Defect 3: the fix for Defect~1 introduced a defect of the same shape}

Defect~1's correction taught the seed rule to see a value hoisted to a
constant, by harvesting \texttt{NAME = <integer>} with a regular expression and
substituting. The pattern matches a line like

\begin{quote}\ttfamily\small
\ \ \ \ random\_state=42
\end{quote}

which is a keyword argument inside a multi-line call, not an assignment. The
substitution then rewrote every \texttt{random\_state} in the script to
\texttt{42}, producing \texttt{42=42} --- and destroying the very
\texttt{random\_state=<digit>} match the seed rule looks for. Two of the three
published \texttt{no\_seed} defects were scripts that seed scikit-learn twice.

An absence-scored rule repaired with a pattern that cannot see syntax is still
absence-scored. The harvest is now done by parsing the script and taking
assignment statements, which closes the class rather than the instance; a
script that does not parse contributes no bindings.

Correcting it moves \texttt{advise} from 26 flagged defects to \textbf{24}
(Tables~\ref{tab:ab} and~\ref{tab:perrule}), with \texttt{control} and
\texttt{advise+audit} unchanged. That is a \emph{fourth} correction in the
direction of our hypothesis, and we note it as such in
Section~\ref{sec:threats} rather than only here.

\subsection{Defect 4: a provider change silently emptied every cell}

The contract harness pins a default model per provider. A pin was updated on a
deprecation notice and never exercised. Every current model at that provider is
a reasoning-mode model, and reasoning mode refuses the forced
\texttt{tool\_choice} the contract requires:

\begin{quote}\ttfamily\small
400 --- Thinking mode does not support this tool\_choice
\end{quote}

so every call failed at transport and every cell reported $0.0\,\%$ with $k/N$
of $0/0$.

The exclusion rule of Section~\ref{sec:design} is what made this visible rather
than catastrophic: transport failures were excluded from $N$ rather than
counted as clean non-fabricating responses, so the tables showed a hole instead
of a false success. That rule had been added after an earlier review found a
failed run scored as a success, and it earned its keep here.

One detail is worth recording for others building such harnesses: the model
that \emph{does} accept the call is absent from the provider's
\texttt{models.list()} endpoint while still being served. Probing the listing
would have confirmed the wrong conclusion. The only reliable check is to send
the call shape the system actually uses.

\subsection{Defect 6: the target-name harvest could not see a parameter
default}\label{sec:defect6}

Defect~1 is scored against a list of \emph{forms} for excluding the target, and
each form is matched against the target's name or against a variable holding
it. The variables were harvested with

\begin{quote}\ttfamily\small
\^{}\textbackslash s*(\textbackslash w+)\textbackslash s*=\textbackslash s*['"]<target>['"]
\end{quote}

which finds \texttt{TARGET = "price"} and does not find

\begin{quote}\ttfamily\small
def train\_and\_save\_model(csv\_path, target\_column="price"):\\
\ \ \ \ X = df.drop(columns=[target\_column])
\end{quote}

because the binding is a function-parameter default, not an assignment. Two
runs on OpenML~44031 are exactly this script, drop the target correctly on
their ninth line, exit~0, and were published carrying
\texttt{target\_in\_features}.

This is Defect~3 again. An absence-scored rule was repaired with a pattern
that cannot see syntax; the repair itself was then found to have the same
fault (amendment~A12); and here a \emph{third} binding form escapes the same
way. The harvest now parses the script and collects names bound to the target
literal by assignment, by parameter default, and by keyword argument at a call
site (amendment~A16). A script that does not parse contributes no names.

Correcting it moves \texttt{control} from 33 flagged defects to \textbf{31},
with every treatment arm unchanged, and removes \texttt{target\_in\_features}
from the panel entirely. It is the first correction in this study to move a
result \emph{against} the hypothesis we are arguing for.

\subsection{How we found it: a differential audit of the final scorer}

Section~\ref{sec:threats} concedes that after five instrument defects a reader
has no reason to trust the sixth version of the scorer more than the fifth. The
concession is not an answer, so we built one.

\texttt{benchmark/independent\_defect\_scorer.py} decides the same six rules by
a different method: \texttt{ast} over the parsed script rather than regular
expressions over its text. On two rules it is deliberately inverted.
\texttt{check\_defects} scores \texttt{target\_in\_features} and
\texttt{no\_validation} by the absence of every enumerated correct form --- the
shape this section has now twice identified as the reason a defect existed ---
so the second scorer fires on positive evidence of the defect instead. That
makes it strictly more conservative on those two rules by construction, which
is the point: where the two disagree is where the first scorer's enumeration
has run out.

Both scorers were run over all 143 preserved scripts, 858 rule-instances.
Table~\ref{tab:audit} is the result \emph{as the audit found it}, against the
scorer before Defect~6 was corrected. Five rules agree on every script. The
sixth disagrees twice, both times with the regex scorer flagging and the
\texttt{ast} scorer clean, and both times the regex scorer is wrong --- those
two runs are Defect~6. With the correction applied the same command returns
858/858 and \texttt{target\_in\_features} fires nowhere, which is a statement
about the repair and not a second piece of evidence: the audit is what located
the defect, so agreement afterwards is expected rather than informative.

\paragraph{What this is, and what it is not.} It is not an independent
replication. Both scorers are ours, written days apart, by people who have read

blind spots, and an agreement of 856/858 between them is weaker evidence than
the same number between strangers. What it does establish is narrower and still

The independence the paper actually needs is human. The replication package
contains \texttt{benchmark/blind\_review/}: a stratified sample of the emitted
scripts with arm, model and dataset stripped and the order randomised, a rating
form for the six rules, and the script that computes checklist precision and
recall against the ratings together with Cohen's~$\kappa$ between raters. We
have not run it. We report the apparatus rather than a result, because
two authors rating their own artefact is not blind, and reporting it as though
it were would be the same kind of mistake this section exists to document.

\subsection{Defect 7: the pre-registration was not enforced, and the tooling
caused the violation}

The downstream protocol rests on freezing a plan before execution. For one run
that discipline was decorative: the runner checked only that a plan file
\emph{existed}, then ran whatever the command line said. A plan froze twelve
cells of one arm at three repetitions --- 36 runs --- and the execution
performed 48 runs across all four arms at one repetition, wrote them under the
plan's own identifier, and exited successfully.

The cause was not carelessness at the keyboard. On freezing a plan the tool
printed:

\begin{quote}\ttfamily\small
Run it with:\\
\ \ python run\_ab.py --experiment-id <id> --panel-id <p> ...
\end{quote}

carrying neither the arm selection nor the repetition count. \textbf{Following
the tool's own instruction guaranteed the mismatch.} A pre-registration whose
tooling hands the author the command that breaks it is a paragraph, not a
method.

The plan's cell table is now parsed back into the arms, datasets, models,
repetitions and seeds it commits to, and the runner aborts --- naming every
divergence, before anything executes or is written --- if the run about to
start is not the run the plan froze. The check runs before the dry-run listing
returns, because a violation discoverable only by spending money is not a
check. The 48 rows were relabelled rather than deleted, with a note stating
what happened, and the arm was rerun against the enforced plan.

\subsection{Non-reproduction: a point estimate is a property of a date}

A pilot battery run three months earlier, on the same task and the same
provider family with the same scorer, measured the bare-arm entity rate at
11.5\,\%, CI $[7.8, 16.7]$. The battery reported here measures 42.0\,\%,
CI $[35.4, 48.9]$ --- far outside that interval. The pilot measured the
paraphrase sweep span as 1\,\% to 100\,\%; this study measures 9\,\% to
72\,\%.

We cannot reconcile them, and we are not going to pretend otherwise. Both pilot
figures were obtained against a \emph{rolling model alias}, and their
per-response records were not retained, so there is nothing left to recompute.
What we can say is what the discrepancy implies for anyone reading rates of
this kind, our own included.

First, \textbf{a fabrication rate is a property of a model version at a date,
not of a model.} Reporting a point estimate and a confidence interval against a
rolling alias produces a number that cannot be reproduced even by its own
authors, and the interval invites a precision the design does not support. We
treat this as a threat to validity in its own right
(Section~\ref{sec:threats}), and it is the reason every cell in this paper
pins a model string, a date, and a harness commit, and retains one record per
response.

Second, \textbf{the qualitative claims are the ones that survived the
instability.} Rewording still moves the rate by roughly an order of magnitude;
the contract still returns 0/200; the stock-validator baseline still leaves a
third of responses unfaithful. Results built on qualitative invariants outlived
a fourfold change in the underlying rate, and results built on point estimates
did not. We recommend the former, and have written this paper accordingly.

All 3{,}800 per-response records behind the present study are in the
replication package.

\section{Discussion}\label{sec:discussion}

\subsection{Prompts are advisory; schemas with verification are enforcement}

The sweep turns a slogan into a number. One model, one evidence dictionary, and
a rate anywhere between 9\,\% and 72\,\% depending on harmless wording choices.
The strict prompt's zeros are real, and they still leave a 1.9\,\% Wilson upper
bound with nothing structural holding them in place across the next model
update or the next paraphrase. The contract supplies what no prompt can: a
worst-case guarantee at any propensity, under any wording, on the channels it
validates.

Section~\ref{sec:rq3} is what upgrades this from a slogan to a comparison. Had
\texttt{A-GR-OURS} landed at 20\,\% we would have learned that the loop matters
and our validator is one of several adequate ones. It landed at 0/200 with the
same loop that leaves 35\,\% under stock validators, which locates the
contribution precisely: not a better reask loop, but a decidable check that a
general-purpose loop cannot express because nothing tells it what the evidence
contained.

\subsection{Detection enables correction}

The stress arm carries a second lesson. The verifier does more than block: it
names what went wrong, and machine-generated violation reports are a strong
mitigation in their own right. Contrast the \emph{cautious} paraphrase --- which
amounts to telling the model to be careful --- at 68\,\%. Vague guidance is
weak; precise deterministic feedback is strong. The division of labour follows:
let the verifier, not the prompt author, do the correcting.

RQ5 is the same lesson at a larger scale, and one of its two confounds turned
out to carry the effect. Asking a model to review its own script with nothing
named repaired zero defects in 35 runs. Handing it a deterministic tool's
findings took the checklist from 31 flagged defects to 8 --- but handing it a
generic list of the six scored concerns, and nothing at all about the script,
took it to 1 (Section~\ref{sec:rq5-rubric}). On the checklist the tool's
findings are therefore not what did the work, and we say so where the number
appears.

The lesson that survives is the one about specificity, and it is unchanged in
direction and narrower in scope: what a model cannot do is find problems in its
own code when nothing is named. What it can do is act on \emph{any} specific,
checkable statement --- ours, or a rubric. Where the two differ is what the
checklist cannot see: the rubric arm satisfies the six rules with code that
runs 47\,\% of the time, against 83\,\% for the arm handed real findings. On
the outcome that composes both --- runs and carries no flagged defect ---
the tool's findings lead, 64\,\% against 44\,\%, on intervals that overlap.

\subsection{Negative results are boundaries, not failures}

No misquotation and no omission fired anywhere in the battery, and we did not
read that as a victory. The honest explanation is that the numbers sit
verbatim in the context window, copying them is easy, and the anchor is the
most salient item in $E$. Longer contexts, derived statistics, or busier
evidence could activate either.

The sweep sharpens this rather than confirming it. Unconstrained, the narrator
does not misquote the numbers it was given --- it attaches statistics the
evidence never carried, on 45 of 100 responses under one wording. A channel we
had described as quiet was quiet only for the failure we were looking for. The contract closes both pre-emptively
at the price of a set lookup and a float comparison
(Proposition~\ref{prop:linear}). Paying that price before a channel is observed
to fail, rather than after, is the right default for evidence-closed narrators.

The held-out score in RQ5 is the other negative result, and the more important
one for practitioners: \emph{the process improves and the metric does not
follow}. A tool that measurably reduces defects in generated training code did
not measurably improve the models those scripts produce. Both halves belong in
the report.

\subsection{Where the contract transposes}

Three invariants make it portable: a deterministic evidence producer, a finite
enumerable set of observed entities and values, and a runtime enum bound to
that set with independent verification. Any narration task with all three
supports the same guarantee. A clinical-decision narrator could be bound to the
patient's actually-measured abnormal results, with cited values verified against
the measurements; an expert-system narrator could be bound to the identifiers
of the rules that fired. In the clinical case the transposed guarantee would be
that the narration is consistent with the recorded measurements --- not that the
recommendation is clinically valid, and not that the measurements are right. The
distinction is the one drawn in Section~\ref{sec:contract}, and it matters
more
as the stakes rise. We have not evaluated either domain, and they mark where our
claims stop.

One engineering note from shipping: when a capability is exposed through
several interfaces --- a CLI and a tool server here --- parity must be enforced
through shared code paths and tested as an invariant. We hit and fixed exactly
such a divergence.

\section{Threats to Validity}\label{sec:threats}

\subsection{Construct validity}

\paragraph{The entity channel measures two things.} This is the threat
Section~\ref{sec:rq1} exists to address. Until we decomposed it, a rate
reported as \emph{fabrication} was dominated by misfiling. We now report both
and keep the blended flag only for continuity with the arm comparisons. Any
reader comparing our rates to another paper's should check which of the two
that paper counts; we suspect the distinction is not made elsewhere.

\paragraph{The downstream checklist is an absence-scored proxy, and we can
now put a number on that.} Six deterministic rules are not ``code quality''.
They are six things that are cheap to check and expensive to get wrong, and
Section~\ref{sec:instruments} shows how the absence-scoring shape produces
false positives with a direction. Two independent raters blind to arm would be
a stronger instrument; the apparatus is in the replication package and we did
not have the raters.

Until this revision that paragraph was an argument. The
\texttt{control+revise+rubric} arm makes it a measurement. Handed the six
scored concerns and nothing about its own code, the model reaches 1 flagged
defect over 32 scored runs --- the best checklist score in the study --- while
its scripts execute \textbf{47\,\%} [32, 63] of the time against 78--83\,\% in
every other arm (Section~\ref{sec:rq5-rubric}). That is Goodhart's law measured
inside our own instrument: the checklist can be satisfied by code that does not
run, and it was, without anyone asking for it. Any reading of a checklist total
in this paper --- including our own --- has to carry the execution rate beside
it, which is why Table~\ref{tab:rubric} reports the joint outcome and why the
surviving \texttt{advise+audit} claim is stated on that outcome and not on the
count.

\paragraph{The treatment text and the outcome measure share vocabulary, and
the overlap accounts for the effect.} This was the threat we considered most
serious in RQ5, it is structural rather than incidental, and it is now measured
rather than conceded. The \texttt{advise+audit} arm pastes \texttt{mlcompass
audit} output into the prompt, and across the 54 preserved audit files the
rules that actually fire are \texttt{seed}, \texttt{val\_split},
\texttt{unused\_holdout} and \texttt{metric\_choice} --- which map onto three
of the six scored items.

An earlier version of this paragraph offered a defence: the largest single
contributor, \texttt{leak\_duplicate\_rows} (24~$\rightarrow$~8), is named by
no audit rule, so the overlap was ``weakened but not removed''. That defence
was too generous to us. The arm that tests it directly ---
\texttt{control+revise+rubric}, carrying a generic list of the six scored
concerns and nothing about the script, pre-registered as amendment~A17 with the
adverse outcome written down before the run --- reaches 1 flagged defect over
32 scored runs against \texttt{advise+audit}'s 8 over 36. On the checklist,
being told what will be scored beats being told what is actually wrong.
Section~\ref{sec:rq5-rubric} withdraws the causal attribution that this
paragraph used to protect.

What survives is narrower and is stated where it is claimed: on the joint
outcome a practitioner receives --- the script runs \emph{and} carries no
flagged defect --- \texttt{advise+audit} leads at 64\,\% [48, 78] against the
rubric arm's 44\,\% [30, 60], with intervals that overlap substantially. At
$N=36$ this design separates the two arms weakly. A reader who concludes that
RQ5 does not establish a checklist-level benefit for the tool's findings is
reading our own result correctly.

\paragraph{Free text is unmeasured.} The guarantee covers the validated
citation and claim channels. Enforcement pressure could push fabrication into
the unverified prose field, and we did not measure such displacement.
Miscalibrated confidence on correctly-cited, correctly-valued evidence is also
unscored.

\subsection{Internal validity}

\paragraph{Provider non-determinism, measured rather than supposed.}
Temperature is fixed at $1.0$ and sent explicitly, but the endpoints are closed
and may change beneath a stable model name.
Section~\ref{sec:instruments} documents two of our own figures that a later run
did not reproduce for what we believe is exactly this reason, and
Section~\ref{sec:rq3-replication} re-runs the whole battery three days later on
the same model name and watches \texttt{A-GR-STOCK} move 8.5 points. That
re-run is the one comparison in this paper that isolates the date: same
provider, same model name, same prompts, same scorer, same evidence hash. The
second-provider result of Section~\ref{sec:rq3-second} does \emph{not} isolate
it --- provider, model family and date all differ there --- and we draw the
weaker conclusion it supports, that reliability is not portable across
configurations, rather than the stronger one about drift that it cannot carry.

\paragraph{Repetitions share a split.} The three repetitions of each downstream
cell use one split per dataset, so they measure generation variability and not
split variability. A design varying both would be stronger and is future work.

\paragraph{The checklist arms are not matched on what reaches a runnable
script.} The rubric arm's 47\,\% execution rate means its checklist total rests
on a different, smaller population than the other four arms' --- 17 scripts
against 28--30. We report the count, the execution rate and the joint outcome
separately (Table~\ref{tab:rubric}) rather than a single figure, because no
single figure over unequal denominators is honest here. The comparison we
believe is sound is the joint one; the comparison we believe is misleading, and
which the earlier draft's framing invited, is defect counts alone.

\paragraph{The stress arm's propensity is not the bare arm's.} It reuses the
shipped contract's user message, which mentions a contract, so its first-attempt
propensity differs from \texttt{A-L1}'s. We report its catches as
demonstrations that the verifier fires, not as estimates of a bare rate.

\subsection{External validity}

\paragraph{One task family for the contract.} RQ1--RQ4 use one synthetic
leakage task with one leak pattern. Other evidence shapes and other leak
patterns are unmeasured.

\paragraph{Provider coverage is uneven, and two of the three providers are
nulls.} The battery ran on three providers --- \texttt{deepseek-chat},
\texttt{gpt-5.4-mini} and a local \texttt{qwen2.5:7b} --- and only the first
fails at all. The other two return 0/200 (and 0/20) on every arm including the
floor, so they confirm that the rates do not transfer and contribute nothing to
the comparison between mechanisms (Section~\ref{sec:rq3-second}). The
comparative claim is therefore single-provider even though the study is not,
and we state it that way wherever it appears. The paraphrase sweep and the diagnostic arms
are single-provider. RQ5 uses four models --- three hosted, one local ---
which is where this paper's generalisation evidence lives. Rates should
not be transferred between providers; our own sweep shows they do not transfer
across paraphrases of a single prompt on a single provider.

\paragraph{Datasets are small and tabular.} Three OpenML datasets, 583 to
20{,}640 rows. Nothing here speaks to deep-learning pipelines, to which the
audit rules largely do not apply.

\paragraph{The verifier assumes the evidence is correctly typed.} The
field-indexed domains $A_{E,f}$ are derived from the evidence dictionary's own
structure: columns come from the correlation table, statistic names from the
keys beside them. If a future evidence producer put a metric name where a
column belongs, the admissible set would inherit the error and the verifier
would certify it. The contract checks the narrator against $E$; nothing in it
checks $E$ against itself.

\paragraph{The evidence domain here is small, and we did not test a large one.}
$E$ carries ten columns. Proposition~\ref{prop:linear} bounds the verifier's
cost and says nothing about the schema's: Tier~A serialises $A_{E,f}$ into the
tool definition on every call, so a frame with a thousand candidate columns
sends a thousand-element enum, against provider enum limits, request size
limits and whatever a model's attention does with a list that long. We have no
measurement of where that degrades. A practitioner with a wide frame should
treat the enum as untested above the scale reported here.

\paragraph{The guarantee is relative to the evidence, not to the world.} Stated
in Section~\ref{sec:contract} and repeated here because it is the threat most
easily lost: a narration that passes every check is consistent with what
\texttt{detect\_leakage} measured. If the detector is wrong, the contract
transmits the error faithfully. Nothing in this paper measures the detector's
accuracy against ground-truth leakage.

\subsection{Conclusion validity}

\paragraph{Seventy of 108 runs carry a held-out score.} Eight of 36 cells carry
none. We therefore report ``no consistent improvement could be shown'' and
decline to report a null. No decision rule for ``beats'' was pre-registered,
and with medians separated by $0.0002$ that, rather than the amount of data, is
the binding constraint on any stronger claim.

\paragraph{Corrections ran one way four times, then stopped.} The first four
scorer corrections each moved the downstream numbers toward our hypothesis, the
fourth being the fix to the fix (Section~\ref{sec:instruments}, Defect~3). The
mechanism is stated and checkable there --- false positives concentrate in
careful code, and the treatment arms produce more careful code --- but four in a
row is a pattern a reader should weigh independently of any mechanism we offer
for it. An earlier version of this section said that the correction moving these
numbers the other way had not arrived, and that until it did we could not
distinguish a biased instrument being repaired from an instrument being repaired
in a biased direction.

Two have now arrived. Defect~6 removes two \texttt{control} flags and touches
no treatment arm, shrinking the effect from a 25-defect fall to a 23-defect
one. Amendment~A17's rubric arm then removed the causal attribution for what
remained. Neither is a calibration and we do not present them as one: five
corrections that favour a hypothesis and two that do not is still a lopsided
record. What changed is that the record is no longer unanimous, and that both
corrections which broke it came from procedures built to look for exactly this
--- a second scorer implementation on a different technique
(Section~\ref{sec:defect6}) and an arm whose adverse outcome was written down
before it ran (Section~\ref{sec:rq5-rubric}) --- rather than from us noticing
something. The apparatus for the human-rated check that would settle the
scorer question is in the replication package and has not been run.

\paragraph{Seventeen amendments is a lot of amendments.} A protocol frozen
before execution and then amended seventeen times invites the question of how
much of it stayed frozen, and the answer belongs here rather than in the
package. Twelve amendments are infrastructure or reporting and cannot move a
result in either direction: added provenance fields, log-directory handling,
key loading, the differential-audit harness, the blind-review apparatus. Three
are instrument repairs whose direction is reported as a correction in
Section~\ref{sec:instruments} rather than absorbed. Two add an arm ---
\texttt{control+revise} (A8) and \texttt{control+revise+rubric} (A17) --- and
both were added to attack our own attribution rather than to support it; each
was written with its adverse outcome stated before the arm ran, and A17's
adverse outcome is what happened. What was never amended is the set of scored
rules, the datasets, the models, the repetition count or the seeds. The
amendment log in the package carries this classification per entry, with a
column for whether the amendment could move a result in the direction of our
hypothesis.

\section{Conclusion}\label{sec:conclusion}

Evidence-closed narration names the class of tasks whose citable entities and
verifiable quantities are finite and machine-enumerable at call time. For this
class, faithfulness checking is linear-time
(Proposition~\ref{prop:linear}); soundness can be enforced by safe deletion
while completeness can only be detected (Proposition~\ref{prop:asym}, a
monotonicity argument whose remedy is restricted by what enforcement over
speech is permitted to invent); and fabrication on the verified channels is
therefore preventable rather than merely mitigable.

We measured a two-tier contract built on those facts, in the shipped narration
path of an open-source tool. Against the nearest real alternative, the finding is that
the outer loop was never the contribution: Guardrails~AI's own validators leave
35.0\,\% of responses unfaithful and the same loop running our deterministic
validators leaves 0/200. Against six rule-free rewordings of one instruction,
the failure rate moves from 9\,\% to 72\,\% --- and the invention rate does
not follow it, so the wording that looks safest on the headline metric is the
one inventing most. Downstream, across four models and three datasets, the
result went against us: flagged defects fall from 31 to 8 when the tool's
findings are supplied, but to 1 when a generic list of the six scored rules is
supplied instead, so on the checklist the findings are not what did the work
and we withdraw that attribution. What survives is that a second attempt with
nothing named repairs nothing in 35 runs, that \emph{any} specific statement of
what to look for repairs most of it, and that the arm optimising against the
rubric alone produces code that runs 47\,\% of the time against 83\,\% ---
which is the clearest evidence in the study that a six-rule checklist is a
proxy and not the thing itself.

We are explicit about what is claimed: not a new decoding algorithm, but a
decidable-class framing, a contract carrying one complexity observation and one
transposed repair asymmetry, and measurements of a shipped system against the
alternatives a practitioner would otherwise use. We are equally explicit about what
this study revised in our own understanding of the system it measures: the
failure mode is not the one we set out to find, a fabrication rate we had
measured once did not reproduce, and the downstream effect required a fourth
arm before it could be attributed to the tool at all.

The programme ahead is concrete: a public narrator-fabrication benchmark across
providers, tasks and leak patterns; verified claims over derived and relational
statistics; contract composition along multi-step agent chains, each step's
enum derived from the verified output of the step before, for which
assume-guarantee composition across agent boundaries~\cite{zheng2026continuity}
is the nearest existing machinery; a paired comparison against a
template-generated, LLM-free narration of the same evidence, which is the
experiment most likely to tell us what the language model is contributing that
a deterministic renderer would not; and an enforceable contract that survives
export across a tool-server boundary, so that a client model consuming a
tool's own evidence is held to the same check as that tool's internal
narrator.
