🔧 Feature engineering
  • Latitude, Longitude → Add spatial features such as geohash/grid cell, 
distance to coast, and latitude-longitude interaction terms or 
polynomial/spline terms.
     The target is a California housing-related regression problem, and 
location variables often carry strong nonlinear spatial structure beyond raw 
coordinates.
  • MedInc → Try log-transforming or winsorizing extreme values; optionally add
binned income bands.
     ‘MedInc’ has a wide range and visible outliers, which can make linear fits
unstable and can help tree models focus on meaningful thresholds.
  • AveRooms, AveBedrms → Create derived ratios like rooms_per_bedroom = 
AveRooms / AveBedrms and bedrooms_per_room = AveBedrms / AveRooms.
     These columns are structurally related and can capture housing composition
better than the raw averages alone.
  • Population, AveOccup → Add population density-style or crowding features, 
e.g. Population / AveOccup if meaningful under the dataset’s definitions, and 
consider log1p transforms.
     Both columns show strong skew/outliers, and occupancy-related effects are 
often nonlinear.
  • HouseAge → Add nonlinear basis features such as age bins or spline terms.
     HouseAge spans 1 to 52 and may affect price in a thresholded or saturating
way rather than linearly.
  • All numeric predictors → Standardize features for linear models and 
consider robust scaling for outlier-heavy variables.
     The feature scales differ substantially across columns, especially 
compared with 'Population' and 'AveOccup'.

⚠ Pitfalls
  • Capped/censored target values at the upper bound of 'price'
     → Treat the maximum-pileup as a censoring/measurement issue to 
investigate; consider censored regression approaches or at least flag/inspect 
those rows, and avoid interpreting residuals near the cap as ordinary noise.
  • Heavy right-skew and outliers in several predictors
     → Use robust preprocessing such as log transforms, winsorization, or 
robust scaling; inspect influential points before fitting linear models.
  • Potentially misleading evaluation if using random splits only
     → Use cross-validation and, if possible, spatially aware validation by 
geographic blocks to reduce leakage from nearby houses sharing similar location
effects.
  • Ratio features can explode on small denominators
     → When engineering ratios from ‘AveRooms’ and ‘AveBedrms’, add small 
epsilons or filter implausible cases and inspect extreme values.
  • No missing values means quality issues may be hidden rather than absent
     → Still run sanity checks for duplicates, implausible values, and unit 
consistency, especially for the target cap and extreme occupancy values.
