🔧 Feature engineering
  • V3 → log1p transform and/or robust (median/IQR) scaling of V3
     V3 is strongly right-skewed (mean 1378.7 vs median 1000, max 12500, 45 IQR
outliers); a log or rank transform stabilizes variance for the linear baseline 
and reduces the influence of extreme donors.
  • V2 → derive donations-per-month = V2 / max(V4,1) and V3-per-donation = V3 /
max(V2,1)
     V2 (frequency, mean 5.5) and V4 (months since first donation, mean 34.3) 
describe the same donation history from two angles; their ratio is a normalized
donation-rate feature that a linear model cannot form on its own.
  • V1 → derive recency_ratio = V1 / max(V4,1) and recency_rank vs V1 quantiles
     V1 (months since last donation, mean 9.5, max 74) should be interpreted 
relative to the donor's total observed window V4; the raw value conflates a 
long-tenured lapsed donor with a recent first-timer.
  • V2 → bin V1/V2/V4 into quantile buckets (e.g. qcut into 4-5 bins) as extra 
categorical features for the tree models
     All four predictors are small-range integers with skewed counts; binning 
lets trees split on ordinal donation-behavior tiers and can expose 
non-monotonic thresholds between low- and high-frequency donors.
  • V4 → add polynomial/interaction terms V1*V2, V1*V4, V2*V3 for the linear 
baseline
     With only four raw features the logistic model has little capacity; 
explicit interactions between recency (V1) and frequency/history (V2, V4) are 
the cheapest way to capture the conjoint effects trees find automatically.

⚠ Pitfalls
  • 215 exact duplicate rows (28.7% of the data) reported in warnings
     → Confirm duplicates are genuine repeat observations; if they are 
artifacts, de-duplicate before splitting, and if they represent repeated donors
use GroupKFold / grouped splitting on the duplicate key so identical rows never
span train and test. A naive random split would leak copies and inflate 
held-out scores without any metric looking wrong.
  • Class imbalance: Class 1 is 76.2% vs Class 2 at 23.8%
     → Report precision/recall, F1, and ROC-AUC or PR-AUC instead of raw 
accuracy; use class_weight='balanced' or scale_pos_weight, and tune the 
decision threshold on out-of-fold predictions rather than defaulting to 0.5.
  • Very small dataset (748 rows, 4 features) makes any single train/test split
high-variance
     → Use stratified k-fold cross-validation repeated with several seeds, and 
keep the models simple (regularized linear, shallow trees, low learning rate + 
few estimators) to avoid overfitting the tiny feature space.
  • Heavy-tailed predictors with flagged outliers (V2: 45 IQR outliers; V3: 45 
IQR outliers, max 12500 vs median 1000)
     → Prefer tree models or robust transforms over raw-scale linear models; if
trimming or winsorizing, decide the rule using training folds only so outlier 
handling does not leak test information.
  • Column names V1-V4 are opaque, and the Class encoding is 1/2 rather than 
0/1
     → Map Class to a 0/1 binary label explicitly before training and verify 
which class is the positive (donor) outcome; keep a human-readable rename 
(Recency, Frequency, Monetary, Time) so feature importances and coefficients 
stay interpretable.
