⚠ Pitfalls
  • Exact duplicate rows (215 duplicates, 28.7% of the data).
     → Verify whether duplicates are genuine repeated records; if not, remove 
duplicates before splitting, or use a group-aware split so identical rows never
appear in both train and test.
  • Potentially inflated evaluation from random train/test splits because 
duplicates may leak across splits.
     → Deduplicate first or perform grouped/blocked splitting; otherwise 
held-out performance can look better than it truly is.
  • Class imbalance in Class (about 76% vs 24%).
     → Use stratified splitting, monitor balanced metrics such as 
F1/ROC-AUC/PR-AUC, and consider class weights or threshold tuning.
  • Small dataset size with only 748 rows.
     → Prefer simpler models first, use cross-validation, and keep feature 
engineering conservative to avoid overfitting.
  • Outliers in V1, V2, and V3.
     → Inspect whether extreme values are valid domain cases; if they are, use 
robust scaling, winsorization, or tree-based models that handle outliers 
better.
